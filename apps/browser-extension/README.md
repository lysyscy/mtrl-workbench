# 工作台 i8 会话桥（Edge / Chrome MV3 扩展）

> 原组件归属：`TAIL-476`。0.1.0 已完成本机 Edge 通知书代表验证并随工作台上线。0.1.1 按用户 2026-11-05 裁定取消账号菜单限制；本次源码修改与正式服务、已安装扩展的加载分开报告。

## 这个扩展解决什么

工作台的原生 i8 取数走「后端 HTTP 客户端 + 按账号保存的 Cookie 缓存」，缓存缺失或失效时会**重新登录**（必要时强踢在线会话）。

本扩展让工作台可以改用**你已经登录的那个浏览器 i8 会话**：请求由**你浏览器里的 i8 标签**发出，后端只负责构造、校验、解析与落库。

效果：日常点工作台原有的抓取按钮即可，**不需要任何模型/Agent 在每条请求中间转接**，也不会因为取数把你自己顶下线。

## 它严格不做的事

| 不做 | 为什么 |
| --- | --- |
| 不读 / 不导出 / 不存 Cookie、localStorage、令牌 | 不申请 `cookies` 权限；会话材料全程留在浏览器里 |
| 不开远程调试端口、不用 `debugger`、不用 `webRequest` | 那些不是可发布的日常产品 API |
| 不申请 `tabs` / `<all_urls>` | 只用 `activeTab`：权限由你**点扩展图标**临时授予当前标签，导航/关闭即撤销 |
| 不接受页面传来的任意 URL / 方法 / 头 | 只执行后端票里的那一条，且必须与选中标签同源、必须命中**只读取数白名单**；方法限 GET/POST；头限 `accept`/`content-type`/`x-requested-with`/`accept-language` |
| 不自己重试、不跟随跳转 | `redirect: 'manual'`；真机上跳转返回的是不透明响应（读不到状态与 Location），所以一律停下并说明原因，不会跟到登录页 |
| 不登录、不顶号、不改页面 DOM | 只是在标签里执行 `fetch` |

请求使用用户选中标签里的当前 i8 会话；不再读取或比对菜单中的账号、组织。请求目标仍须与标签实际站点一致。

## 安装与更新

`apps/browser-extension/` 是唯一维护和加载目录。更新沿用同一个目录，不再生成独立安装包。

1. 打开 `edge://extensions`（Chrome 是 `chrome://extensions`），打开「开发人员模式」。
2. 点「加载解压缩的扩展」，选择本仓的 `apps/browser-extension/`。用扩展详情中的来源路径核对加载目录。
3. 保留 `manifest.json` 中的 `"key"`，工作台用固定扩展 ID `jfkgliolimmpceandogfimjkadplidem` 连接。
4. 扩展源码更新后，在扩展页点「重新加载」，再按[使用流程](#使用流程日常)选中 i8 标签并确认工作台会话桥能连接。

### 工作台地址范围（无需改 manifest）

`manifest.json` 的 `externally_connectable.matches` 与扩展内发送方检查共同限定以下入口：

- 生产服务：`http://127.0.0.1:8000/`、`http://localhost:8000/`（`ops/nssm_install.ps1` 里的单 worker 服务）
- 本仓预览：`http://127.0.0.1:8065/`、`http://localhost:8065/`（`docs/guides/frontend-preview.md` 的预览端口）
- 局域网正式入口（0.1.2，用户2026-11-06确认）：`http://192.168.5.3:8000/`。其他电脑须在打开工作台和i8的同一浏览器配置中安装新版扩展；连接标识复用工作台的局域网HTTP兼容随机ID实现。

新增工作台地址或端口属于权限变更，须单独确认，由维护人更新源码中的发送方检查和 `manifest.json`。本扩展刻意**不申请 `<all_urls>`**。

### 卸载

`edge://extensions` → 移除本扩展。工作台侧连接状态随页面关闭自然消失；后端不保留任何会话材料。

## 连接选中的标签

**无需展开或保持账号菜单。** 用户在已登录的 i8 标签点击扩展图标后，工作台只核对该标签的实际站点。
实际账号、组织由该标签当前会话决定；工作台里的绑定账号与取数范围是本地配置，不代表扩展已核验浏览器登录身份。
本次取消菜单 DOM 适配和逐条账号、组织核验，不另读隐藏值或会话凭据代替。

同一个浏览器里可以同时开多个工作台页面：连接与身份基准是**按页面（连接）分开记**的，一个页面重连或断开
不会顶掉另一个页面已经连好的那条；只有你**换选另一个 i8 标签**时，旧的连接才全部失效、需要重新点连接。

具体到"谁能用这条连接"，扩展按**发送消息的那个工作台标签页 + 文档**认归属：

- 只有建立连接的那个页面能取数；另一个工作台页面即使知道同一个连接标识，也**不能**取数、**不能**顶掉
  已有连接、**不能**把它撤绑 —— 一律明确拒绝并说明原因；
- 工作台刷新后仍换新的文档连接标识；曾主动连接的账号会自动重新绑定扩展当前手选的 i8 标签，无需再点连接。只保存连接意图，不保存会话凭据，也不复用旧请求；
- 每条请求还必须带**这个连接当前的代号**：缺代号、为 0、或属于上一次连接（断线重连后）的旧代号，
  一律**一个字节都不发**，连用户的 i8 标签都不去碰；
- 连接站点必须与工作台配置以及扩展刚读取的站点一致；请求执行时仍核对实际标签站点。

## 使用流程（日常）

1. 在浏览器里正常登录 i8，停在业务页，无需展开账号菜单。
2. 点扩展图标**选中这个标签**（换标签/新开标签要重新点一次）。
3. 首次打开工作台 →「i8 接入」页 → 取数方式选「浏览器已有会话」→ 点「连接浏览器会话」。之后刷新工作台会自动恢复连接。
4. 之后各日常抓取入口（付款通知书、库存/结存、机械台账、自动关联、项目同步等）点原来的按钮即可。
5. 工作台在连接或抓取时发现扩展暂时失联、i8 标签暂停或绑定需要更新，会自动尝试重连。短暂断网和工作台服务重启也会触发恢复。恢复期间显示未就绪，失败或超时的抓取由用户重新发起。i8 标签关闭、权限或登录失效时需按提示处理。

主动点「断开／停止连接」或切回工作台直连会停止自动恢复。有效轮询和回帖会续上工作台侧活跃时间；空闲超过120秒只用于清理真正失联的通道。i8自身登录期限仍由i8决定。

⚠️ 选过「浏览器已有会话」之后，断开/刷新/失败都**停在**该方式；要改回直连必须你自己在「i8 接入」页切换。

## 已知限制（未验证项）

- 采购合同列表和详情由工作台从生效的 i8 服务地址派生，并通过固定的只读白名单。
- 如果 Edge 长期冻结后台标签，可在「系统和性能」中将 i8 站点加入从不休眠名单。扩展只检查标签状态，不切换标签或更改浏览器性能设置。
- 每条请求的超时预算**由工作台按该请求自己的读超时给出**（例如合同列表 200s、详情 60s、其余 30s）；超时按"超时"停，**不谎称**会话失效。
- 代号、站点、发送页面归属的浏览器检查由隔离 Chromium 样机覆盖（`tests/browser_smoke.py`，加载临时副本、只连假站点）；样机用 `tabs` 权限程序化选中标签，不能代替真实 `activeTab` 用户点击授权验证。
- 二进制报表（xlsx 导出）经 base64 传输，由后端做长度完整性核对；长度对不上即停（不重试，也不设拍脑袋的字节上限）。
- `externally_connectable` 与 `scripting.executeScript` 已在本机Edge实际安装后通过通知书日常入口验证；其它Edge版本和部署不自动视为通过。
- 0.1.1 不再依赖账号菜单 DOM；实际登录失效由取数响应判定，不以“已连接”代表 i8 认证成功。
- 历史验收中，用户在真实 Edge 选中 i8 标签后，原工作台按钮抓取了 2026-11 通知书 17 条，测试副本逐条读回一致。[真实验收记录](https://github.com/lysyscy/mtrl-workbench/blob/e79b50fe9bd049ede5fbabdd1152fbddecfed9bb/.scratch/browser-session-loading-20261103/evidence/TAIL-476-daily-live.md)
