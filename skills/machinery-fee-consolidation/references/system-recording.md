# 系统明细录入

仅在 `SYSTEM_RECORD=1` 且用户要求录入本批时使用。输入是月份总目录及申报月份，Agent负责识别项目、有效页、分类和版本，再直接调用材料工作台的业务保存逻辑写数据库并回读。用户无需上传文件、打开录入预览或另点确认汇总。只读检查仍不写库。

## 生成

1. 按SKILL.md盘点目录并运行提取。用下述工具的state命令只读取得当前项目、同月明细和版本，供关联与去重；配置沿明确指定的材料工作台项目，不复制凭据。无法访问时先完成提取，不凭名称猜仓库。
2. 对照 `state.projects` 确定原报项目到仓库全名的映射。按设备、车牌、出租单位、日期和原来源关联同月系统明细；同条业务复用 `state.details[].rows[].id`。新增业务分配本批稳定id；修订、移动行、改文件名时仍复用原id。源序号、行号或相同金额均不能证明同条业务。
3. 用内部review记录已核选择。`rows`覆盖全部提取记录，提取问题逐项处置；同项目／月／类别提供本次完整原报行。上次原报行未对应时先找回关联，确需删行须取得本批明确授权并列removed_rows及理由。此工具不生成整类清空批次。

```json
{
  "period": "2026-10",
  "projects": {"原报项目名": "系统仓库全名"},
  "rows": [
    {"record": 0, "id": "首次分配或复用的稳定id", "reason": "来源已核实，关联同条设备", "values": {"plate": "已核实车牌"}},
    {"record": 1, "exclude": true, "reason": "租赁分公司内租，另列人工补充"}
  ],
  "issue_resolutions": [{"issue": 0, "reason": "已核实原备注为车牌，填入plate，原备注留来源"}],
  "removed_rows": [{"warehouse": "系统仓库全名", "category": "zero", "id": "确需删除的系统原行id", "reason": "原报修订取消此项，已逐行确认"}]
}
```

`record`和`issue`是提取结果数组的0起始索引。`values`只写已核实的字段修订，不把缺失项填0。原报字段、原值、税率和来源坐标保留；跨模板包月的数量、日价、天数仍按字段映射处理，不能塞进月数、月单价或入场日期。允许在明确核实后用 `category` 修正分类。

```text
python -X utf8 scripts/record_system.py --project-root 材料工作台绝对根目录 state --output 本批工作目录/state.json
python -X utf8 scripts/record_system.py --project-root 材料工作台绝对根目录 write --extraction 提取结果.json --review review.json --receipt 本批工作目录/录入回执.json --operator 当前操作者
```

运行时使用材料工作台现有backend虚拟环境；其他宿主需能运行同一项目及其数据库配置。工具核原报SHA、逐行处置、项目归属、稳定id和删行理由；业务层对本次全部范围持事务锁并核版本，失败整批回滚，相同请求不重复记账。关联同条业务后，原报修订与系统人工补充按三方比较合并；有实质冲突就停止，Agent向用户说明原报值、现有值及影响，取得逐项选择后在review的conflict_resolutions中记录，不默认全覆盖。

## 直接写入与回读

用户要求“录入这批”即办理已明确来源、项目和月份的本批录入；不额外停在统一预览或确认步骤。项目、分类、原报权威版本或金额有疑义时，只询问具体问题。内部提取、review、state和回执放本批工作目录，原报保持只读，不把内部中间文件作为用户必须操作的交付。

保存有金额的明细即更新对应月金额；空金额行不参与，明确0照算。字段未齐可留待补，缺税率不猜净额。过程资料手填覆盖后，仅补备注、车牌不改金额；明细金额或税率变化更新对应金额。删除最后一条金额明细时相应月额清空。不修改i6、历史累计或i8。

工具完成事务后，另行重读明细行数、id、字段、合计和过程资料对应金额，核重试未重复追加；只按真实回读报告成功、待补和冲突。未来新批次仍从原报与系统当前状态开始。
