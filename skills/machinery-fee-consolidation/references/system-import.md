# 系统明细录入

仅在 `SYSTEM_IMPORT=1` 时使用。输入是月份总目录及申报月份，Agent负责逐本识别项目、有效页、分类和版本；脚本负责把已核实的提取记录转为现有机械费工作台JSON，不代替业务判断。

## 生成

1. 按SKILL.md盘点目录并运行提取，保留每页选择理由和每个待核问题。用工作台的正常登录会话只读取得 `/api/m06/workbench?ym=YYYY-MM`，保存为本批 `state.json`。使用已有身份或正常登录；登录信息不进入技能包、录入文件或核对记录。无法访问时先完成提取，不凭名称猜仓库。
2. 对照 `state.projects` 确定原报项目到仓库全名的映射。按设备、车牌、出租单位、日期和原来源关联同月系统明细；同条业务复用 `state.details[].rows[].id`。新增业务分配本批稳定id；修订、移动行、改文件名时仍复用原id。源序号、行号或相同金额均不能证明同条业务。
3. 写 `review.json`。`rows`必须覆盖全部提取记录，每条提供采用或排除理由；提取器的每个问题须在 `issue_resolutions` 记录处置。同项目／月／类别提供本次完整明细，不只提供改动行；上次原报行未对应时，先找回关联，确需删行才列 `removed_rows` 和依据。整类清空走系统明细页人工确认，本生成器不生成空批次。

```json
{
  "period": "2026-10",
  "projects": {"原报项目名": "系统仓库全名"},
  "rows": [
    {"record": 0, "id": "首次分配或复用的稳定id", "reason": "来源已核实，关联同条设备", "values": {"plate": "已核实车牌"}},
    {"record": 1, "exclude": true, "reason": "租赁分公司内租，另列人工补充"}
  ],
  "issue_resolutions": [{"issue": 0, "reason": "已核实原备注为车牌，填入plate，原备注留来源"}],
  "removed_rows": [{"warehouse": "系统仓库全名", "category": "zero", "id": "确需删除的系统原行id", "reason": "原报修订取消此项，已逐行确认"}]
}
```

`record`和`issue`是提取结果数组的0起始索引。`values`只写已核实的字段修订，不把缺失项填0。原报字段、原值、税率和来源坐标保留；跨模板包月的数量、日价、天数仍按字段映射处理，不能塞进月数、月单价或入场日期。允许在明确核实后用 `category` 修正分类。

```text
python -X utf8 scripts/build_system_import.py --extraction 提取结果.json --review review.json --state state.json --output 原报目录之外/机械费录入.json
```

生成器仅用标准库，提取器仍需openpyxl/xlrd。它检查原报SHA未变、每条记录和问题均被处置、项目属于当前档案、id不重复、上次原报行有对应或删行依据（系统额外手填行由三方合并保留）。生成相同内容得到相同request_id；系统确认仍以最新版本保护与三方合并为准。

## 预览与确认

交付可选入“机械费 → 录入预览”的JSON，另给项目／月份／类别、行数、含税／净额合计、未补字段、分类或税率调整摘要。可以通过正常会话调用 `/api/m06/workbench/import-preview` 形成同一预览，每次新预览给新的request_id，确认重试复用该preview_id；预览会保存预览记录，不写正式明细和月值。停在此处等待用户确认本次具体内容。

用户确认后，上传文件并在界面确认写入，或用该预览id调用 `import-confirm`。冲突必须逐项选择 `incoming/current`，不默选全部覆盖；传 `confirm_amounts:false` 只保存明细。按用户进一步确认，在明细页分别确认含税和净额采用；已有手填值保持到明确替换，缺税率等待核格不强行确认。不修改i6、历史累计或i8，也不生成历史导入文件。

确认后回读核对明细行数、id、字段、合计及来源，检查重试没有重复追加；系统有后续修订时重新预览。未来新批次仍从原报目录与当前系统状态开始，不把旧生成文件当新来源。
