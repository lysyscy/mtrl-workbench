# 机械费报表整理

按用户给的月份总目录逐本整理项目报表，生成系统明细录入文件，用户确认后才写入；原四页Excel汇总能力保留为可选输出。用户只需给目录与申报月份，不必逐项目放技能。i8抓取由系统按项目操作，本技能不改i8或i6历史数据。

## 输出开关（手改0或1）

```text
SYSTEM_IMPORT=1
EXCEL_EXPORT=0
```

- `SYSTEM_IMPORT=1`：生成工作台可读取的JSON，并展示录入预览，停在用户确认之前；不是Excel文件。
- `EXCEL_EXPORT=1`：额外生成独立四页Excel，沿用用户指定完成汇总的格式与公式。设0则不要求Excel底稿，也不执行Excel写入与格式验证；原报读取和金额核对照常进行。
- 两项可同时为1；只能填0/1。两项为0时只检查来源和问题，不生成交付文件。用户当次明确要求优先于默认开关。

## 业务规则

- 源文件保持原样。只读请求只检查；获准输出时保存到独立位置，保留源文件和历史报表。
- Excel输出启用时，最终工作簿与用户指定的完成汇总保持同样的四页名称、顺序、表头、列位、项目分组、字体、边框、行高、列宽、合并、打印和冻结设置。不要另造两页布局、加“项目/来源/计算税率”等列或为了规范而加标题。来源、原报附加字段、差异和待核项放在工作簿之外的核对记录中。
- 同月修订时，未变化的外租合计和表1/4无需重写；新月归集时按实际申报明细更新外租汇总、月份与相应公式范围，保护历史记录及内租输入。上月文件只供复制样式，不能将上月明细或补充数据当作本月数据。保留补充字段的规则仅适用于已关联的同月、同条业务。
- 报表按月收取。以本次报表的申报月份确定批次，保留原租赁日期、入场日期，不按日期所在的自然月过滤明细。包月设备可能早已入场，入场日期旧不代表费用过期。
- 旧月份表头可能是模板残留。结合实际明细、申报情况和用户说明识别有效页；月份或项目冲突未解决时列出具体页，继续处理其他明确的页。
- 设备名称、规格、单位等本期有值字段以当月项目表为准，不自动沿用旧写法。目标分组、排序和序号采用用户完成汇总的安排，不能把源序号当业务主键。关联到同条明细后，原报缺失的目标已有补充字段保留并说明来源；不要将其称为当月原报数据，也不要按空值清空。
- 分别处理日期值与显示格式。真实日期及已核实的Excel日期序列值按模板显示；General格式的短数值如 `8.21`、文本如 `9.16` 保留原报写法，不统一套日期格式、不推断1900年或凭空补年份。比较时回到源值、类型和格式，不能把自己错误转换后的值当原报。
- 一般按页面格式分零租、包月，同时检查标题和实际内容。源页名只提示范围：同一页可能已经搬入多种设备明细。租赁分公司属于内租，另列人工补充事项，不放进包月外租明细。项目不必在外租表里申报内租。
- 普票的不含税金额等于含税金额，包括写有百分比的普票。专票按含税金额除以 `(1+税率)` 计算。票种或税率缺失、有歧义时标待核；不能把缺失信息当作普票或零税率。
- 沿用已提供模板的精度规则；没有其他约定时保留计算精度，显示两位小数，报告这一处理。按用户确认的规则调整后再复算。
- 保留原报合价，核查数量、单价与合价关系。合价可能含运费、按天折算或人工结算；差异列出，不用数量乘单价强行覆盖。
- 提取有效明细，排除标题、项目分组行、合计/小计、签字栏和空白模板。序号空白、重号、断号及数字写成文本不构成删除依据。保留重复发生的实际业务，不按相同金额或设备去重。

## 工作步骤

1. **只读盘点。** 分开识别月份汇总、项目回传、内部租赁、过程汇总和历史资料，排除 `~$` 锁文件。逐页查看标题、合并表头、原字段、公式和已保存的结果；不要直接运行会改写源文件的重算脚本。
2. **确认本批来源。** 对目录、文件名、填报单位、明细项目及月份的冲突逐项处理。每个入选页记录来源文件、页名、项目、分类及入选理由。同一报表多份修改版需确认本次权威版本；不能按修改时间或所在目录自动决定。
3. **逐行提取。** 可使用下述脚本读取已确认的页。它保留原字段、公式、值和坐标，不决定冲突页、内租业务或跨版本去重。脚本问题列表为空或每个问题已处置，才能宣称本批完整。
4. **生成已启用的输出。** 系统录入读取[系统明细录入](references/system-import.md)，将提取记录与当前系统项目、同月明细关联，生成JSON并送入录入预览，等待本次确认。Excel输出读取[字段映射与工具边界](references/field-mapping.md)，复制用户指定四页底稿到独立位置，按原列位、分组和公式写入；表1/4内租仍由用户填写。两种输出共用同批已核实明细，不从一个结果反推另一份来源。
5. **验证并交付。** 逐行核对原报与输出字段、记录数、金额及不含税结果，检查日期值/类型/格式、车牌与备注，聚合一致不能替代字段核对。JSON验证来源、稳定id、冲突和预览合计；未确认前不写正式明细/月值。Excel另证明格式、内租及未授权区域保留；同月修订总额不变时表1/4保持原样，有公式按用户指定Excel技能在副本重算验证，工具不支持的公式保护缓存并明确未做原生重算。说明待核项，不把未解决的来源冲突称为完成。

## 提取辅助脚本

提取器需openpyxl读取`.xlsx`、xlrd读取旧版`.xls`；系统JSON生成器只用Python标准库。本机使用材料工作台`backend`项目的虚拟环境（依赖由该目录pyproject.toml/uv.lock管理）；其他宿主使用已具备这两项库的隔离Python环境。下列命令的`python`替换为该环境解释器，脚本路径相对技能目录；不要往全局Python安装项目依赖。

准备一个本批计划 JSON，给已确认的文件和页指定项目、月份、分类以及入选理由。输出路径使用源目录外的新路径：

```json
{
  "period": "2026-09",
  "sheets": [
    {
      "path": "绝对路径/项目当月报表.xlsx",
      "sheet": "零租设备月报表",
      "project": "已确认项目",
      "kind": "零租",
      "reason": "本次申报页，项目与月份已核实"
    }
  ]
}
```

```text
python -X utf8 scripts/extract_reports.py --plan 本批计划.json --output 新位置/提取结果.json
```

`records` 是待整理明细，`issues` 是未覆盖或需判断的行，`sources` 记录读取前后 SHA-256。脚本扫描表头位置和重复表头，不对名称、数量或单位作业务归一化。`tax` 中的计算为复核值；启用Excel输出时仍用公式并完成重算验证。

`0 issues` 仅表示脚本检查没有待核行，不替代申报项目/月度一致性检查、班组等缺报字段检查、计费依据核对和输出回读。

无名称但有金额的行会列为待核。逐行确认它是合计或旧记录后，可在该页计划中用 `"exclude_rows": {"31": "已确认的原表合计行"}` 排除；理由随来源记录保存，不把首批行号当成通用删除规则。

需要核对首批样本覆盖和真实限制时，阅读 [验证记录](references/validation.md)。它记录已做的检查，不承诺未验证格式自动适用。

## 保真修订辅助脚本

对已完成四页文件做明确单元格修订时，可用 `scripts/apply_template_edits.py`。计划列出底稿哈希、来源哈希和表2/3要改的单元格、值、类型、理由。类型为 `text`、`number` 或仅更新已独立复核结果的 `formula_cache`；已有公式保持原表达。该工具保留ZIP包内未改部分及改单元格以外的XML。

```text
python -X utf8 scripts/apply_template_edits.py --plan 已核对单元格计划.json --output 新位置/机械费汇总.xlsx
```

该脚本只处理已存在的单元格，不插行、不自动匹配目标行、不决定业务映射，也不重算Excel。新月记录数变化时需先按原表复制行样式、重建分组和相应公式引用，再对全簿进行格式和公式验证；不能把单元格修订能力宣称为新月完整重建。
