## 共同输入与职责

项目输入、票协议、个人源绑定和提交推送授权以 `ops/agents/issue-tracker.md` §四为准；当前技能正文从 Skills Manager 中央库准确定位。个人包的源、隔离、验证、发布与安装核验入口是 improve-workflow 的包操作约定。

实施前核实际全局规则、仓内入口和自有技能消费链，保留此次审计的可定位原句与版本证据：普通实施的 Matt 全流程与个人收尾重复；TDD 的测试接缝确认与技术自主权交叉；只读检查遇新会话同步；实际间接依赖未全部纳入核验；两个 skill-creator 定位歧义；重启授权与入口读取范围不一致。Ponytail 最短差异及模式共享限制作为适配与未修边界，不修改原版。

只有输入不足或变化时补读。源与部署出现独有修改时先保护并判明来源；中央安装目录不是自有技能维护源。共同规格定义目标，票面定义独有验收，票 Comments 持有执行证据和状态，不另建长期待办账。

## 能力缺口与两个个人技能的分工

全局仅保留触发原则：遇到陌生领域、明显能力缺口、重复失败，或准备编写大量工具性代码时，先检查已有能力及成熟方案，再决定是否自行实现。全局不写工具目录、搜索安装步骤或强制某个 CLI/MCP 组合；仓内只接入必要指针和本项目权限。

| 主人 | 触发与责任 | 对应票 |
|---|---|---|
| implement-solo-spec | 当次实施遇到缺口时执行按需工具发现、选择、小场景验证与使用；统筹本轮五票的依赖、写入负责人、整合、累计审查和票收尾 | TAIL-330 |
| improve-workflow | 用户要求复盘优化、个人技能维护或适配时，从真实证据判断原因与可迁移性，比较和采纳长期能力；负责个人包的冻结版本、隔离修改、验证、发布和同步 | TAIL-331；包生命周期用于本轮个人源改动 |

普通任务查一次工具不启动整轮复盘或修改个人方法；复盘发现一个候选不自动授权产品改造、账户连接或付费。两个技能按各自主人引用共同方法，不复制同义流程；improve-workflow 当前已有“候选归属与外部能力”，implement-solo-spec 已有浏览器工具选择，应先核其可达性与遗漏，再补缺口。

具体执行从现有工具、库、已安装技能和连接开始；足够则复用。能力仍不足时，按缺口查官方或可信的 CLI、库、技能、MCP/插件及平台能力，find-skills 仅承担技能发现，不能把技能搜索无结果视为没有现成工具。核实际能力、来源版本、输入产物、权限副作用和兼容性，比较自行实现与引入的总成本；信息足以决定时停止搜索，先以隔离小场景证明收益再在授权内采用。

不追求最新版本、最高热度或组件数量，不强制每个普通任务联网搜索，不默认叠加 CLI、skill 和 MCP。可靠的既有 Python/Playwright 等测试体系继续复用；本轮不迁移产品测试、不安装示例工具。技能安装与分发交 Skills Manager；其他工具及连接按其实际入口和已有授权处理。演练可用候选夹具，不产生真实安装、连接或付费副作用。

本轮由同一主 Agent 协调两种职责：implement-solo-spec 承担 effort 调度，improve-workflow 承担个人包生命周期。共享发布操作只有一个负责人，包内必要核验保留；审查和收尾复用覆盖相同版本与范围的有效证据，不启动两个相互嵌套的总调度或重复最终审查。本轮运行沿用开工时保存的技能版本，新版安装核实后下一轮采用。
