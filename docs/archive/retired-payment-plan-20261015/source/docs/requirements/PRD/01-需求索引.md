## 一、命名规范（`ACC-<域>-<序>`）

验收用例 ID = **`ACC-<域>-<序>`** —— **独立命名空间**。

- **为什么不绑 `MOD-*`**：`MOD-*` 是「PRD 分章用」的编号；跨模块需求会在多个模块下产生同名用例，且模块一调整，用例 ID 全部悬空。
- **为什么不复用 `DEV-*`**：`DEV-*` 是**口径**编号、不是**用例**编号；一条口径常要拆多条用例，且部分需求没有任何 `DEV-*`。
- **追溯由 `99-追溯表.md` 承载**：`ACC ↔ REQ ↔ MOD ↔ DEV`，ID 里**不内嵌**其他编号。
- ℹ️ `ACC-*` 已**纳入 `delivery/demo/_ids.js` 的覆盖前缀**（2026-09-14 裁定）⇒ 悬空会被报红。

## 三、索引自检（集合式，不写计数）

- **口径指针齐备**：每行都有（`REQ-R15`…`R19` 指向 Non-goals 主人节 + `NG-*`）。
- **用例 ID 齐备**：每行都有，且每行都标了来源（可移植的组 / 需新建 / 不建用例）。
- **可移植**（来源为既有断言组）：`REQ-R2` `R3` `R6` `R7` `R8` `R9` `R10` `R11` `R12` `R14` `R20` `R21` `R22`
- **需新建**：`REQ-R1`
- **部分可移植 + 需新建**：`REQ-R13`（页面划分半边需新建，**判据现成** = `NAV` 分组 + `MOD` 归属）

- ⭐ `REQ-R1` 的真空**可补、判据现成**：主人节 §7.1 已写明「导出内容须与当前筛选一致」⇒ 标「需新建」= **没人写断言**，**不是**无从断言。
