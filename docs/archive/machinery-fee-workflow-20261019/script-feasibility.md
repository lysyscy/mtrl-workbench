# 项目机械原报的脚本可行性调查（2026-10-17）

结论：常规Excel明细提取、金额校验和已有模板映射适合程序主导；当前脚本尚不能无人确认完成来源选择、跨版本合并及完整月度工作簿生成。实样支持“常规程序处理＋系统内异常确认”的方向，不能据本次诊断宣称完整业务自动化准确率达到某百分比，也不必将外部Agent对话作为固定入口。陌生模板或图片的AI辅助可选，业务归属与金额冲突仍需有明确依据。

## 范围与方法

1—9月全部256份非锁定Excel清单逐本检查，252份打开检查表页，4份材料出库xls实际为xlsx，当前读取器拒绝，未确认其内部有无机械页。137份位于编号项目目录、51份月根汇总、68份公司收发结存子目录；所有原文件前后SHA一致。

历史根为D:/工作/材料/材机报表/往年数据，2050份Excel，2047份完成表头盘点，3份HTML内容伪xls被当前读取器拒绝；检查全部可读工作表，限每页前60行/120列，共5369页。2050份按文件SHA去重为1616份，历史重复副本不能冒充独立样本。

本次实际调用现有extract逻辑：项目、月份与零租/包月分类仅用诊断占位，不表示已审核；未生成合并表，也未以最终汇总为逐行金标准验收。图片只视觉检查一张，ZIP只目录盘点，未解压验证内页；RAR/ET等未完整解析。源文件、技能和产品代码均未修改，未重算、未调用i8。

## 已发现的脚本适配和缺陷

- 现有norm(value or '')将数字0变成空串；主代理已复现tax_check(100,0,'专票税率')被标缺失。仅证明诊断误分类，不据此确认零税率业务成立。1—9月“税率缺失”62条实际39条空白、23条数字0。
- 1—9月84项有金额无设备名，74项为SUM；另含SUBTOTAL和静态合计，需增加合计识别及与明细独立核算，不能一律当丢明细或直接忽略。
- 税率数字3、含油/不含油或斜杠等不能自动补成已确认票种；本期56条歧义中33条为数字3。原报缺失不是任何识别工具能推断成确定事实。
- 历史“车号／车辆牌照号／台班数量／设备数量／税率／使用人”等已有表头别名未进入当前结构化字段，需映射与语义确认；raw_cells保留并不代表输出字段已完整。
- 历史28页仅30余行但格式膨胀到一万多列，当前尺寸保护拒绝；需要安全限定实际表格读取范围，不能简单移除保护。
- 4份本期伪xls及3份历史HTML伪xls可考虑按文件内容识别后适配；当前未实现。

## 仍不能静默自动裁决的真实情况

1. 9月慧能目录的一本国风报表：工程公司汇总页A3写慧能，B6/B7与设备明细A3写国风；国风目录另有一本，两个文件各页值仅零租O列26格不同，其余全同。脚本可检测冲突、近重复和增量，不能仅凭目录决定项目与权威版本。
2. 9月宜化目录一本工作簿分别有宜化、宁夏石嘴山两页，两页A3写不同项目；必须逐页归属，不能一本固定一个项目。
3. 一月乌兰察布目录同时有不同台账，标题/月字段和租赁日期并不一致；申报月、租赁日期和模板残留需分别处理。
4. 1月慧能一本同时有零租设备报表和Sheet1，各可提取58条。未裁定页的用途前，全部机械表头都读会重复归集。
5. 9月签字照片与电子表并存，不能作为两批费用相加；图片若为唯一来源，另需识别及核验。
6. 对拆行、合行、重复业务及人工纠错，尚未实测三方合并。没有稳定业务标识时，不能用相同行号代替对应关系。

## 对方案的约束

推荐系统按钮驱动扫描、读取、核对及明确确认；固定模板走程序，来源/页选择/项目冲突在系统内展示并确认，确认过的模板映射可以复用但不能忽略新冲突。先改进已证实的读取器问题，再用经人工核定的完整月份逐行比对、回放修订，才能给完整自动化覆盖率和维护成本。

保持Excel汇总编辑自由与任意月份可修订的用户要求。现有单元格修订脚本不具备新月增删行和公式范围重建，不能因提取测试通过就宣称按钮合并已可用。只有在异常量真实过多时，再评估系统内AI辅助；是否调用Agent或模型与是否必须外部聊天是不同选择。

包月吊车外租设备月报一页内纵向拼接多段标题、表头、项目行、设备与签字栏。H5为27500，紧邻H6再次为27500，E6写“明细”；同类主行/附加说明行组合反复出现。设备名称和单位同时存在，现提取器将两者都当作有效费用行。原extract实际提取31条、合计450866.68；工程公司汇总表第17行本月包月J17为226933.34。其18项issues并未将成对明细的重复计入明确标为重复风险，用户不应从“识别表头/提取完成”推断结果可靠。

按版面暂辨的主要设备行金额可与J17对应，但本轮未将其定为已验收的业务真值或改写原表。复现证据：.artifacts/machinery-fee-workflow/august-huineng-case-20261017/reproduction.json。

该例修正前轮调查的信心边界：前轮全量机械扫描有价值，但未逐行理解段落与主从关系，遗漏了金额重复计入的真实风险；不能据“多数模板相同、字段可读”推荐固定提取器独立承担整批归集。

用户明确偏好由Agent整体理解不可信、可变结构的来源，而不由用户逐项维护格式适配和异常映射。后续方案据此转向Agent主导逐本/逐页/逐段判断、选择来源与生成有依据的处理计划，脚本执行准确提取、金额计算、保真写入及独立核验。系统按钮可作为任务入口，Agent执行环境及模型接入尚未选型；不能写成现有系统已经能直接执行skill。真正缺失事实或无法判断的冲突仍提交用户，不凭模型猜测补齐。
