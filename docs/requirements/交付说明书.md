# 交付说明书

> **本文件 = 仓内产品资料的说明与导航**。读者 = **用户、分析者和接手开发者**。
> ⚠️ **本文件不是索引的主人、也不含任何业务口径与取值** —— **资料清单与阅读导航的唯一主人 = 《材料科业务全流程说明书》§0.2 / §二**；业务口径回《说明书》，技术口径回《技术栈选型分析》。
> 项目代码与产品资料都在本 Git 仓库中；不再单独生成或传递交付包。**不写进度**（状态 / 完成度一律不在本文件）。

---

## 一、产品资料在哪里

完整产品资料 = **本文件所在的这个目录**（仓库里名为 delivery 的那一层），随项目代码一并克隆、更新和恢复。目录内的 7 项及其用途由《材料科业务全流程说明书》§0.2 统一列出。

| 你想知道 | 去哪（**只给指针，本文件不复述**） |
|---|---|
| 项目是什么 / 业务怎么走 / 有哪些口径 | 《材料科业务全流程说明书》**§〇 接手须知 → §一 速览**（**项目定位与业务口径的唯一主人**） |
| 产品资料包含哪几项、每项干什么、怎么排阅读顺序 | 同上 **§0.2（清单）＋ §二（导航）** |
| 交付契约（需求 / 规格 / 验收 / 任务分解）从哪进 | `PRD/00-总览.md` |
| 技术口径（技术栈 / 部署形态 / 非功能） | 《技术栈选型分析》 |
| i8 对接的具体实现参考 | `PRD素材包-20260911/`（⚠️ 旁证，见 §五 第 2 条） |

## 三、怎么开始读（三类读者 · **只给指针**）

| 你是 | 先读 | 拿到什么 |
|---|---|---|
| **业务核对**（科室本人） | 《说明书》§〇 → §一 | 口径全貌 |
| **接手开发**（新机器 / Codex） | ① 《说明书》§〇 → §一 → §二 ② `PRD/00-总览.md` ③ `demo/设计规则-提炼自付款通知书页.md` ＋ `delivery/demo/材料报表自动化工作台-交互原型.html` ＋ **`demo/原型导读.md`**（索引） ④ 《技术栈选型分析》 | 业务 ＋ 需求规格 ＋ 交互规格 ＋ 技术口径 |
| **验收方** | `PRD/验收/README.md`（**怎么跑**）＋ `PRD/验收/验收基线.json`（**验什么**）＋ `PRD/验收/用例索引.md`（用例号定义处） | 一套可执行的验收口径 |

> 需要**建档设计细节** → 《全自动建档-实施计划》。
> 需要**验收取值来源** → 《说明书》§0.6.2 第 3 步 ＋ `PRD素材包-20260911/验收标准/`。

## 四、权威位（**每类事实只有一个主人**）

| 层 | 主人 |
|---|---|
| **业务口径** | 《材料科业务全流程说明书》（冲突裁决规则见其 **§0.1**） |
| **交互规格** | `demo/` 原型本身（**原型即交互规格**；`demo/原型导读.md` 只做索引） |
| **交付契约** | `PRD/`（**只引用、不复制** —— 它不是"第二本说明书"） |
| **技术口径** | 《技术栈选型分析》 |

> ⚠️ **实现细节**（列宽 / 按钮位置 / 存储结构）归 `demo/设计规则` 与《技术栈选型分析》，**不得升格为口径**。

## 五、接手前必知的三条警戒

1. ⛔ **不得自行补齐未写的口径** —— 遇 `OPEN-*` / `NG-*` 或空白处，应**标「待确认」并回问**，不要臆造（禁令主人 = 《说明书》§0.6.3）。
2. ⚠️ **旁证不得反推** —— `PRD素材包-20260911/` 的定位是「**i8 对接的实现参考 ＋ 验收取值基线**」，且**含已作废口径**（登记表 = 该包 `清单.md` §二 2.3）⇒ **照抄会做错值**；业务口径只认《说明书》、技术口径只认《技术栈选型分析》。
3. ⚠️ **「没报红」不等于「对了」** —— `demo/` 下的四个自检脚本（`_smoke` / `_doccheck` / `_links` / `_ids`）各有**明确的覆盖边界**（原型 HTML/CSS 层、素材包正文、`§x.y` 节号、工作区内部目录等**不在扫描范围**）。跑法见《说明书》**§0.7.3**，覆盖边界见 `demo/` 各脚本的文件头说明。
