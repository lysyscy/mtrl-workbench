# 集采合同、发票与付款

集采台账按合同承载结算与付款，通知书通过合同关联进入付款链。贸易公司与实际供应商的合同、发票和结算口径分别存在，不混作同一收款事实。i8 收款单位“资产处集中采购”不等于实际供应商；本地供应商自动预填须用户确认，人工值优先。

## 合同与关联

抓取仅刷新 i8 原事实白名单，合同纳入/不纳入标记、实际供应商、人工备注及约定不能被重抓静默覆盖。供应商/合同匹配限本项目，多命中不猜。集采通知书未关联合同不能付款；修改/撤销按真实付款子表与通知书关联同步，不能只改显示金额。

合同结算、发票和付款各自保存，欠款按合同结算减付款。贸易公司三方业务分别登记供应商侧/贸易侧材料与发票，不用一侧缺失推另一侧零。合同、发票、付款子表的内部 ID 用于写入；网页动态序号只代表当前排序与纳入项位置，不纳入不占号；合同编号是业务字段，不能拿动态序号替代。

## 账期与方式

账期、合同付款方式、其他条款独立。合同付款方式四值为现汇、承兑、供应链、其他（备注）；空表示未约定。账期接受非负天数及容差，如90±10天，最大天数为100自然日；只是提醒，不计算到期可付金额，不拦截原业务，也不改历史实际付款方式。

付款窗口按通知书分别展示项目、材料名、本条付款金额、相关发票日期、账期和提醒截止，同合同多通知书不能合并丢失依据。付款日期变化重新取上下文，排序/刷新不覆盖金额与方式草稿，最终按当前日期复核提醒。合同默认仅在无已确认拟方式时采用，历史实际流水保持。

原 Excel 核对发现合同方式冲突或未约定，标原表方式及既有说明列，该行暂不回写，正常行继续。人工修正或明确有意例外后重新预览，提交核当前合同关联/方式、通知书状态/金额/原值和指纹，变化整批拒绝。不把默认现汇冒充 i8 原值或已确认计划。共享字段与兼容行为见 [jc-payment-contract](../reference/jc-payment-contract.md)。

## 展示与导出

合同排序/筛选与显示偏好不改变业务编号和归属。普通 Excel 跟随台账现有列，打印版遵守独立模板，不因新增账期/方式擅改打印列。通知书付款反查按合同 ID 定位，不能按供应商名或动态序号跳转。历史集采 Excel 导入不提供现行入口；既有批次/撤销模型及数据仍保留。


## 子表金额与日期保护

有贸易公司时结算取贸易发票合计，无贸易公司取供应商发票合计；欠款合同级实时计算，不拆月。不按遗忘的加价比例猜结算。两侧发票同款、日期必填（新草稿默认北京时间当日）、金额严格正数且无业务上限；主表金额只读派生，不另存主表手填数。手工历史汇总每项目一行，历史未结金额录在供应商发票子表，日期为核对截至日，不能当开票日改写；金额已扣除截至日以前的付款，不重复录这些付款。普通备注维护保留历史标记与截至日。

合同付款子表保手工/通知书引用来源。引用只存关联，合同付款取通知书统计付款金额；统计0且无有效流水时引用不显示但关系保留，统计等流水合计则按笔显示，否则显示统计累计及差异（含统计0但已有实付）。引用行跳转通知书，不提供通用删除/解绑，正式换关联在通知书页处理；手工行仍可按原能力删除。

仅已有专项审核的合同日期集合受保护，i8重抓不覆盖其审核日期，其余沿原同步策略（含空值），不能把这项保护扩大到全部源字段。新合同默认纳入，两态标记手工保护；项目内纳入合同按日期、同日录入先后派生序号，无日期后置，筛选不改变号、不纳入不占号，内部ID不作为网页列。

账期提醒仅在合同仍欠款、通知书未实际付清且有约定和对应发票时，贸易公司取贸易侧、其他取供应商侧。付款日不晚于发票日＋最大账期（含当天）提醒，次日不提醒；不两侧重复计算。多发票逐条保日期依据，无法解析日期不猜，空提醒不证明日期真实或合同可付。纯读取返回字段和404兼容仍按共享接口契约。
