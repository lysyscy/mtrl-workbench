# PRD · 验收

> **当前读取方式（2026-10-08）**：按任务读说明书对应节与MOD能力行；验收JSON保持判据含义。demo原型及导读用于历史追溯，已不作为现行界面字节或交互布局的基准；当前界面由运行实现及相关判据确认，程序现状不自动替代业务目标。

> ⚠️ **第 2 层（可执行验收套件）的代码不放这里** —— 它**与代码同仓**（决策 2026-09-14）。

## 一、为什么代码不在这里

验收套件是**能跑的代码**，必须**跟代码一起执行**（随工程依赖与实现执行；当前本机不引入CI）。放进文档目录会变成"**躺着不跑的代码**"。

## 二、本目录的文件

| 文件 | 作用 |
|---|---|
| `验收基线.json` | 每个 `ACC-*` 的**判据 + 口径指针**（**不复述取值** —— 取值一律到主人处取；报表域的取值类基线另见 `PRD素材包-20260911/验收标准/`） |
| `用例索引.md` | `ACC-*` 的**定义处**（首列）+ 编号 ↔ 需求索引（**不写判据**；**「覆盖点」的主人 = 本目录 `验收基线.json` 的 `cover`**，索引侧刻意不留该列） |
| `README.md` | 本文件 —— **怎么跑（机制契约，§三）** ＋ 本目录文件说明 |

## 三、怎么跑（**机制契约** —— 具体命令随实现方的工程结构而定）

> **三层**：① **人读基线**（本目录两个文件）② **可执行套件**（**与代码同仓**）③ **汇总报表**（按用例出四态）。
> ⚠️ 本节只给**机制契约** —— 实现方照它建套件，PRD 侧照它验「转绿」。**PRD 侧不放可执行代码**（见 §一）。

| 环节 | 契约 |
|---|---|
| **绑定** | 每个测试**成对**声明「用例号 + 判据点号」⇒ 一条判据点 ↔ 一个测试。**不许只挂用例号** —— 否则报不出「哪条判据点还没验」 |
| **四态** | **绿**（跑过且通过）· **红**（跑过且失败）· **待建**（判据点已定、断言尚未建，登记在基线的待建区）· **未绑定**（既没跑过、也没登记为待建） |
| ⚠️ **未绑定 ≠ 通过** | 「未绑定」必须**单独成态并显示** —— 否则出现「**没验过 = 通过**」（本项目最贵的一类假绿） |
| **用例何时算绿** | 该用例的**全部判据点都绿**才算绿；未达标时报「绿 X/Y」分数（判据点随实现推进逐个转绿） |
| **谁跑 · 何时跑** | 验收按实际影响覆盖对应判据；局部通过不代表全量完成，提交动作不自动扩大检查。当前仍在用的业务保护按真实后果验证 |
| **失败怎么报** | 报表**按 `ACC-*` 分组**列出红 / 待建 / 未绑定；**有红即非零退出**（供流水线判停） |
| **待建项怎么交接** | 基线 **`_pending_assertions`**（唯一登记处）分三档：**A 待实现方建断言** / **B 不可机器断言**（走真实浏览器走查 / 人工复核）/ **C 口径侧登记**（逐条带 `status`：**判据待建** / **待回问业务方** / **承认不可断言** / **已落判据** —— 与 `PRD/99-追溯表.md` §四 **同一集合**）。实现方按 A 建断言 |

## 四、两条纪律

1. **一条口径 = 一条验收点**；用例**断言出口、不断言数值**（锚点见 `PRD/99-追溯表.md`）。
2. **移植既有断言时**：把「**存在但未导出**」的出口提升为「**已导出**」（`_smoke` 里有一类出口只存在、不在 `__X` 导出清单内 ⇒ 只能行为式断言，测不到口径函数本身）。
