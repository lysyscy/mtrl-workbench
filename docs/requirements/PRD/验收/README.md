# PRD · 验收

> **当前读取方式（2026-10-08）**：按任务读说明书对应节与MOD能力行；验收JSON保持判据含义。demo原型及导读用于历史追溯，已不作为现行界面字节或交互布局的基准；当前界面由运行实现及相关判据确认，程序现状不自动替代业务目标。

> ⚠️ **第 2 层（可执行验收套件）的代码不放这里** —— 它**与代码同仓**（决策 2026-09-14）。

## 一、为什么代码不在这里

验收套件是**能跑的代码**，必须**跟代码一起执行**（随工程依赖与实现执行；当前本机不引入CI）。放进文档目录会变成"**躺着不跑的代码**"。

## 二、本目录的文件

| 文件 | 作用 |
|---|---|
| `验收基线.json` | 每个 `ACC-*` 的**判据 + 口径指针**（**不复述取值** —— 取值一律到主人处取；报表域的取值类基线另见 `PRD素材包-20260911/验收标准/`） |
| `用例索引.md` | `ACC-*` 的**定义处**（首列）+ 编号 ↔ 需求索引（**不写判据**；**「覆盖点」的主人 = 本目录 `验收基线.json` 的 `cover`**，索引侧刻意不留该列） |
| `README.md` | 本文件 —— **怎么跑（机制契约，§三）** ＋ 本目录文件说明 |

## 三、验证与历史报告

本目录持有业务判据和口径指针；实现侧按实际行为、风险和已有保障选择测试。测试不再强制绑定ACC编号，不按测试数、覆盖率或四态总数验收；原判据的业务意义保留。

运行结果报告实际选集、原始退出码、失败节点和未验边界。mock交互、API/隔离数据库、真实系统和人工业务验收分别陈述；局部通过不代表全量完成。

历史四态JSON及报表仅用于固定版本追溯：绿/红/待建/未绑定只表示该判据视图。未绑定、未执行或缺失不算通过；报告同时检查原始pytest退出状态，判据全绿不能掩盖未绑定失败。默认pytest不再生成或刷新该报告，当前命令回工程验证指南§十一。

基线的待建区和原追溯记录保留原版本含义，不要求为新测试补登记，也不自动推导当前完成程度。

## 四、两条纪律

1. **一条口径 = 一条验收点**；用例**断言出口、不断言数值**（锚点见 `PRD/99-追溯表.md`）。
2. **移植既有断言时**：把「**存在但未导出**」的出口提升为「**已导出**」（`_smoke` 里有一类出口只存在、不在 `__X` 导出清单内 ⇒ 只能行为式断言，测不到口径函数本身）。
