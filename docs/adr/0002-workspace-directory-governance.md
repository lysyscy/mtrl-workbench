# 工作区目录治理

目录的维护和回收由同一个负责人或生产者决定。已登记的开发运行、前端发布、运行预览和备份分别沿各自的清理入口处理。已保留的业务资料、在用状态、Hold、永久项和有效回退资源按原规则保护。[ADR-0001](0001-development-artifact-ownership.md)

[目录清单](../../tools/audit/directory_manifest.json)是机器读取的唯一目录登记，包含归属、Git 策略、维护入口和退出条件。本 ADR 记录治理边界。仓库 README、开发工具入口和产物指南链接到这两处。

提交钩子用 `directory_audit.py --staged` 检查 Git 暂存文件的顶层目录。新增顶层目录时，把清单与新路径一起暂存。尚未接入清单的工作树通过共享钩子使用主检出的清单。日常巡检从仓根运行 `tools/audit/directory_audit.py`，默认与 `--dry-run` 均为只读。清单以 `check_children` 标明需要逐个登记子目录的边界。运行 ID、版本和其他由生产者管理的子目录沿其原有登记核验。

完整审计报告未登记目录、过期保留记录、发布孤儿及无主残留。专用目录的报告附维护入口。文件数或大小超过软阈值时显示 `WARN`。`RESIDUE` 提示可选清理项。这两类提示不影响退出码。`--apply` 只复核清单允许的空退役目录和无源字节码缓存。路径、链接、Git 索引或保留状态无法核实时，保留现场。
