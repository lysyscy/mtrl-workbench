# 产物生命周期与工具接入

本项目的产物分类、实际入口和退出规则。2026-11-06按[已批准方案](../adr/0001-development-artifact-ownership.md)切换开发输出；业务资料、项目例外与固定旧运行保持原保护。


### 1. 先确定材料身份

| 类型 | 保留规则 |
| --- | --- |
| 原始业务输入、正式业务数据、正式交付 | 永久保留，不受通用清理器的年龄或容量规则删除 |
| 可复用源码、必要规则与测试反例、影响正式结果的关键人工裁定和来源依据 | 归唯一维护源或正式记录；不随单次运行过期 |
| 完整提取结果、候选版本、详细核对快照、调试日志、截图、轨迹和已终结的故障证据 | 仅保留近期确有用途的最小集合，按下文限期管理 |
| 重复副本、无价值试验、已无用途的一次性脚本和临时环境 | 无活动消费者、恢复用途和独有未保存状态后释放 |
| 第三方工具缓存 | 由工具原生机制回收；不直接删除工具内部缓存结构 |
| 活动预览、在用构建、待验收输出、有效备份及持久运行状态 | 由实际消费者与其专门生命周期决定退出，不套用通用文件年龄 |

“永久保留”不要求永久保留每次运行的物理副本。源码和规则可由仍可达的 Git 历史追溯；正式业务依据归其实际主人。另行授权的业务处置或功能退役仍可按自身规则处理。未跟踪或被忽略的文件不因仓库已推送而获得可恢复性。

正式系统已完整记录的结果不另造永久回执；未记录的关键裁定或独有来源依据先移交正式主人。短期材料转为长期样本或依据时，明确用途与主人，不能无限续期整棵现场。原件不为归档而反复复制。

### 2. 只有明确登记的产物进入自动清理

由技能或工具按一轮运行或具有同一退出条件的一组材料自动登记，不要求用户逐文件维护。一个运行允许多组材料分别结束用途。

通用清理器只遍历已接入、边界明确的运行区。目录名、扩展名、文件年龄和 `.gitignore` 都不是删除授权。未知散件、普通目录及历史现场先保留并列候选；旧规则记录不能自动升级为可删除登记。

### 3. 用途结束后起算

相关成果已保存或交付、必要核对完成、永久依据归位且没有活动消费者继续需要该组材料时，记录用途结束时刻。只有任务原本要求人工验收时才等待验收，不新增普遍的人工确认步骤。

结项时释放可重建且没有下次用途的中间产物；只为具名后续操作、未决验收或有效回退保留最小材料，并写明退出条件。持续使用的数据、规则与当前发布状态归正式入口，只供历史回顾的结论由 Hindsight 承接。未决失败、未知后果和独有未保存状态继续保护。

文件创建、访问、复制或修改时间不代替该事件，查看文件不续期。重开任务登记保护状态，新运行的新材料有独立起点，不刷新整批旧材料的期限。

### 4. 保留期限

- 无下次用途的中间件优先用系统临时 API 随任务退出；已登记的 work 在 close 后立即具备清理资格。
- 仅为具名用途登记 evidence。写明下一动作及退出条件，按需选截止日或 30／60 天；明确跨月才用 60 天。成功日志、截图和已终结的故障证据不自动保留。
- 未决验收与有效回退仍按下节保护。已有登记、固定运行和未迁移生产者保留原期限；不接管旧资料或改变业务、服务和原件边界。
- 期限按起算时刻计算，不能在起算当日就扣掉一天；用统一时间标准计算，向用户显示本地时间。

上述期限不追溯覆盖已在运行的旧任务、项目特例或现有材料登记。改变已采用规则按 setup 的受控更新流程执行。

### 5. 未决事项局部保护

金额差异、未知写入结果、待验收或恢复用途仍在时，只对直接相关材料登记暂缓删除，记录原因与解除条件；其余已完成材料继续退出。依赖不能可靠拆分时先保留最小可确认完整单元并报告。

首次登记保护后 30 天进入复查。复查到期只提示需要行动，不能触发删除或由清理器自行判断问题解决。实际处理者核实后可继续保护、缩小范围或补足永久依据；清理器不自动填入“已复查”。未处理时保护继续生效，同一逾期状态不每天重复提醒。

解除保护前确认永久信息已归位。从未起算的材料此时开始保留期；已起算材料取“原到期日”与“解除后 7 天”中较晚者。该缓冲只作用于相关材料，不整体重置运行期限。

### 6. 退出、定时清理和提醒分别执行

生产者在用途结束时释放可重建且无需保留的中间件，只有有具名用途的最小证据才进入限期保留。原有自动生产者仍按已采用的收尾规则运行；业务后果、消费者或归属不明时继续保护。

经授权安装的本机周期任务每天检查一次；错过执行时在下一次具备运行条件时补跑。到期代表具备候选资格，不保证到期瞬间或机器关闭时完成删除。

正常清理保持安静，记录精简结果；失败、无法核实及复查到期首次出现或发生实质变化时提醒，重复不变问题去重。提醒渠道必须在接入时确定并实际验证，不能把仅写日志称为已通知用户。

### 7. 删除前重新核对

候选计划与执行共享同一套资格判断，执行时再次核查实际绝对路径、链接/重解析点、运行归属、保留类型、到期时间、保护状态和活动使用。

生产者与删除使用同一运行的互斥机制。不能确认无活动使用时保留并报告；不只凭可能复用的 PID 判断。结项后的新增文件或内容变化须对照结项清单发现，保留相应组并报告，不能随整目录被删除，也不自动续期。

永久项、源码、业务原件、正式数据、有效备份、凭据、他人修改及独有未保存状态排除。路径越界、记录损坏、锁不可确认或状态矛盾时停止该组处置，不扩大删除范围。

### 8. 符合条件的到期材料直接删除

完成保留期并通过当次检查的可丢弃材料直接删除，不额外增加回收站、隔离期或整包备份。已删除的短期证据不承诺可恢复；仍有恢复用途的材料应在删除前处于保护状态。

部分删除和失败如实记录，重试只处理剩余匹配文件。普通开发入口保留原测试/构建/发布退出码，清理未完成另写回执并提示；显式清理命令异常仍非零。无法安全建立新输出时在执行前停止该写入。记录不含凭据或业务原文，必要证据有限保留。

### 9. 数据库和原生资源独立管理

通用文件清理器不删除业务数据库中的来源、版本、基线、幂等回执或其他辅助记录。其退出必须由业务机制证明不再参与计算、重试、修订保护或追溯，并按单独授权实施。

构建版本、备份、依赖环境及第三方缓存优先沿原有管理器和专门退出规则；不将它们作为普通目录按年龄回收。

基础规则采用源为lysyscy/My-Skills `2e0e153c0b434da03a2b1363b45945599a76b0c9`。2026-11-09固定运行时更新至 `8fa4fd17db298809bf4fbe1effe42aa769d50d31`，加入下述 Impeccable 适配器。setup负责部署、升级`tools/_vendor/setup_solo_workflow`，来源和字节清单在其deployment.json；共用修改回唯一维护源，项目不独立分叉。开发命令直接使用随仓固定版本，运行时不加载个人技能目录。

新接入或获准迁移的生产者按本页具名留证；现有 workspace_paths 自动入口继续原合同，直至随消费者一起完成迁移。

新运行默认`.artifacts/runs/<run-id>`，run.json自动保存归属、结果和保留信息；日志、报告、截图按需创建。普通测试、构建和发布入口经workspace_paths自动登记与收尾，不要求另做三步手续。后端pytest中间件使用系统TEMP，报告直接写项目；跨进程候选和预览构建仍放受保护的run/work。读写消费者登记PID及OS创建身份，父进程退出不越过活跃子消费者。

工具入口仍为`tools/artifact_lifecycle.py`：`check`只读；`sweep`执行到期清理。独立任务可显式`register --group <标识> --owner <任务> --reason <用途> --kind work`登记无后续用途的工作材料，或用`--kind evidence`登记具名用途的证据，reason写明下一动作与退出条件，使用返回目录；外部合作消费者用`lease --group <标识> -- <命令>`。用途结束用`close --group <标识>`结项：work立即具备清理资格；evidence显式选择`--days 30`、`--days 60`或`--deadline <带时区的未来时间>`。未决用hold/review/release，保原原因、解除条件及缓冲规则。普通开发失败通过development_run声明；只有全部消费者能参与登记的生产者才声明abandonment_safe，不能把任意外部进程退出视为已核实。

旧AgentArtifacts/mtrl-workbench登记区及`.artifacts/active`、archive继续按原消费者与期限退出，不自动搬家或续期。续办旧全局登记运行时显式设置MTRL_LIFECYCLE_ROOT到原已登记根；新项目根的项目/工作树身份必须匹配。系统TEMP不承诺跨重启保存，不放唯一输入或待保留源码。业务原件、备份、正式与回退资源沿各自机制管理。

## Impeccable过程产物

生成设计稿、原型或评审快照前，用固定版本适配器声明本次独占的 Impeccable 原生路径。外部命令与独立预览经 `exec` 登记占用，原生工具继续在原位置读取。已有文件、链接和其他活动任务占用会拒绝接管。PRODUCT.md、DESIGN.md、设计侧车、共享配置和 live 恢复状态继续由原主人维护。

从仓根用项目 Python 执行 `tools/_vendor/setup_solo_workflow/impeccable_artifacts.py --project .`，后接相应子命令：

```text
start --group <任务标识> --owner <负责人> --path .impeccable/mocks/<任务标识>
exec --group <任务标识> -- <原生命令>
finish --group <任务标识> --confirmed --days 30
```

各独立消费者持有登记直到实际退出。用途结束、评审已关闭且消费者均已退出后，负责人用 `finish` 将产物按散列移入受管证据目录并封存。正在验看、用途不明或恢复所需的材料保留保护。收尾中断时重试仅处理仍匹配的余项。通过 `exec --read` 读取已封存证据不延长期限。旧资料沿原负责人及授权处理，调度仅检查已登记的运行。

## smyw过程产物

本项目新建的 smyw 规格、预览和反馈使用已登记的任务工作目录，不写上游示例的项目根 `.smyw`。上游技能及其更新保持原渠道；从仓根使用当前宿主实际加载的 smyw 技能目录：

```text
backend/.venv/Scripts/python.exe -B tools/_vendor/setup_solo_workflow/smyw_artifacts.py --project . start --group <任务标识> --owner <负责人> --skill <smyw技能目录>
backend/.venv/Scripts/python.exe -B tools/_vendor/setup_solo_workflow/smyw_artifacts.py --project . build --group <任务标识> --skill <smyw技能目录>
backend/.venv/Scripts/python.exe -B tools/_vendor/setup_solo_workflow/smyw_artifacts.py --project . apply --group <任务标识> --skill <smyw技能目录> --feedback feedback-v<N>.md
```

`start` 返回工作目录及规格路径；规格、预览、版本和原样反馈均留在该目录。`build`、`apply` 在消费期内调用当前上游脚本；`apply --dry-run` 保留反馈预检。每次操作前以合成数据验证当前上游的目录构建与反馈回写，接口不兼容或检查中发生更新时停止并保护草稿；不要同时更新技能。其他独立生成或预览进程通过 `exec --group <任务标识> -- <命令>` 持有消费，外部浏览器不能自动识别，仍在查看或等待反馈时保持 active。

用户和所有消费者结束、决定及必要反馈已归位后，负责人执行 `finish --group <任务标识> --confirmed`。该标志确认用途结束，不新增例行用户确认；运行以 `work` 结项并立即具备清理资格，实际删除仍由已接入清理入口执行。需保留的最小证据按具名后续用途另行登记；旧 `.smyw` 不自动接管或清理。
