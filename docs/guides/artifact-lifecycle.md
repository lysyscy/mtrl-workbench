# 产物生命周期与工具接入

2026-10-30 用户确认的通用方法。setup 接入或维护时使用；日常任务读取已部署规则，不回读本参考。项目例外与固定旧任务保持各自基线。


### 1. 先确定材料身份

| 类型 | 保留规则 |
| --- | --- |
| 原始业务输入、正式业务数据、正式交付 | 永久保留，不受通用清理器的年龄或容量规则删除 |
| 可复用源码、必要规则与测试反例、影响正式结果的关键人工裁定和来源依据 | 归唯一维护源或正式记录；不随单次运行过期 |
| 完整提取结果、候选版本、详细核对快照、调试日志、截图、轨迹和已终结的故障证据 | 仅保留近期确有用途的最小集合，按下文限期管理 |
| 重复副本、无价值试验、已无用途的一次性脚本和临时环境 | 无活动消费者、恢复用途和独有未保存状态后释放 |
| 第三方工具缓存 | 由工具原生机制回收；不直接删除工具内部缓存结构 |
| 活动预览、在用构建、待验收输出、有效备份及持久运行状态 | 由实际消费者与其专门生命周期决定退出，不套用通用文件年龄 |

“永久保留”不要求永久保留每次运行的物理副本。源码和规则可由仍可达的 Git 历史追溯；正式业务依据归其实际主人。另行授权的业务处置或功能退役仍可按自身规则处理。未跟踪或被忽略的文件不因仓库已推送而获得可恢复性。

正式系统已完整记录的结果不另造永久回执；未记录的关键裁定或独有来源依据先移交正式主人。短期材料转为长期样本或依据时，明确用途与主人，不能无限续期整棵现场。原件不为归档而反复复制。

### 2. 只有明确登记的产物进入自动清理

由技能或工具按一轮运行或具有同一退出条件的一组材料自动登记，不要求用户逐文件维护。一个运行允许多组材料分别结束用途。

通用清理器只遍历已接入、边界明确的运行区。目录名、扩展名、文件年龄和 `.gitignore` 都不是删除授权。未知散件、普通目录及历史现场先保留并列候选；旧规则记录不能自动升级为可删除登记。

### 3. 用途结束后起算

相关成果已保存或交付、必要核对完成、永久依据归位且没有活动消费者继续需要该组材料时，记录用途结束时刻。只有任务原本要求人工验收时才等待验收，不新增普遍的人工确认步骤。

录入回读核对完成可结束核对快照的活动用途；开发检查完成且结论已保存可结束相应截图日志的活动用途。失败或取消须先明确结果、没有未知写入后果并已决定不继续调查，才可将最小失败证据转入限期保留。

文件创建、访问、复制或修改时间不代替该事件，查看文件不续期。重开任务登记保护状态，新运行的新材料有独立起点，不刷新整批旧材料的期限。

### 4. 保留期限

- 普通核对证据、开发日志截图及已终结的故障证据：用途结束后满 30 天。
- 明确用于下个月比较或下一业务周期核对的材料：用途结束后满 60 天，记录具体用途；业务任务不自动全部采用 60 天。
- 特殊需要使用具名截止日与理由，按相应任务批准的约定执行。
- 期限按起算时刻计算，不能在起算当日就扣掉一天；用统一时间标准计算，向用户显示本地时间。

上述期限不追溯覆盖已在运行的旧任务、项目特例或现有材料登记。改变已采用规则按 setup 的受控更新流程执行。

### 5. 未决事项局部保护

金额差异、未知写入结果、待验收或恢复用途仍在时，只对直接相关材料登记暂缓删除，记录原因与解除条件；其余已完成材料继续退出。依赖不能可靠拆分时先保留最小可确认完整单元并报告。

首次登记保护后 30 天进入复查。复查到期只提示需要行动，不能触发删除或由清理器自行判断问题解决。实际处理者核实后可继续保护、缩小范围或补足永久依据；清理器不自动填入“已复查”。未处理时保护继续生效，同一逾期状态不每天重复提醒。

解除保护前确认永久信息已归位。从未起算的材料此时开始保留期；已起算材料取“原到期日”与“解除后 7 天”中较晚者。该缓冲只作用于相关材料，不整体重置运行期限。

### 6. 退出、定时清理和提醒分别执行

生产者在用途结束时释放无保留必要的短命资源；已完成用途的必要证据进入限期保留。进程崩溃、没有活动锁或命令已退出，都不能单独证明业务结项。

经授权安装的本机周期任务每天检查一次；错过执行时在下一次具备运行条件时补跑。到期代表具备候选资格，不保证到期瞬间或机器关闭时完成删除。

正常清理保持安静，记录精简结果；失败、无法核实及复查到期首次出现或发生实质变化时提醒，重复不变问题去重。提醒渠道必须在接入时确定并实际验证，不能把仅写日志称为已通知用户。

### 7. 删除前重新核对

候选计划与执行共享同一套资格判断，执行时再次核查实际绝对路径、链接/重解析点、运行归属、保留类型、到期时间、保护状态和活动使用。

生产者与删除使用同一运行的互斥机制。不能确认无活动使用时保留并报告；不只凭可能复用的 PID 判断。结项后的新增文件或内容变化须对照结项清单发现，保留相应组并报告，不能随整目录被删除，也不自动续期。

永久项、源码、业务原件、正式数据、有效备份、凭据、他人修改及独有未保存状态排除。路径越界、记录损坏、锁不可确认或状态矛盾时停止该组处置，不扩大删除范围。

### 8. 符合条件的到期材料直接删除

完成保留期并通过当次检查的可丢弃材料直接删除，不额外增加回收站、隔离期或整包备份。已删除的短期证据不承诺可恢复；仍有恢复用途的材料应在删除前处于保护状态。

部分删除和失败如实记录；重试先核实际剩余文件与未完成动作，不重复宣称全部完成。清理结果只保必要身份、动作、数量和错误，不含业务原文，并沿普通限期规则退出；当前执行所需状态保持保护。

### 9. 数据库和原生资源独立管理

通用文件清理器不删除业务数据库中的来源、版本、基线、幂等回执或其他辅助记录。其退出必须由业务机制证明不再参与计算、重试、修订保护或追溯，并按单独授权实施。

构建版本、备份、依赖环境及第三方缓存优先沿原有管理器和专门退出规则；不将它们作为普通目录按年龄回收。
