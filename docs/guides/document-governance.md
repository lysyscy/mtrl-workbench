# 文档维护与专项处置

现行目录和命名由README.md持有；个人标准来源与项目例外见docs/agents/workflow.md，工作资料生命周期见docs/guides/work-records.md。本页解释哪些资料应同步及何时需要专项处置，不复制业务正文。

## 一、信息层与权威

宿主MEMORY与RULE只保存每轮必要边界和条件指针；现行产品、架构、指南、参考和Agent协议在docs各自固定职责位置。docs/status.md只作当前活动导航；任务状态、范围与验收在原票。历史原文退出默认加载，输出仍由真实工具配置保存。

## 二、同批同步

| 改动 | 同批核对 |
|---|---|
| 业务、字段或验收含义 | 需求唯一主人、对应MOD和判据；真实语义变化沿当前授权 |
| 目录或正文落点 | 入口、实际引用、路径/glob、扫描根、排除、生成源、预算、基线、回执和选测 |
| 运行方法或资源 | 对应指南、实际程序/配置与恢复来源；迁文档不自动授权重启或迁运行资源 |
| 活动任务资料 | 固定范围、原裁定、必要完整评论、任务引用和真实消费者 |
| 历史归档 | 原文字节、原路径、固定SHA及来源索引；原文旧引用按当时上下文解释 |

目录在场、Markdown链接可达或一次检查通过，都不能单独证明机器仍消费新输入。更新路径后用真实消费者和相关缺失反例核对。

## 三、归档与删除

分别判断现行迁移、历史归档、无独有信息的删除候选、活动/恢复/未知材料。先保护当前Git、索引、未提交原件与忽略资料，再执行已获批准的清单。删除必须能说明结论在哪里、还有谁使用以及如何恢复；零引用、旧日期和scratch名称只提供调查线索。

现行权威实际统一，结束资料保留来源后归档；新发现的独有信息、活动用途或归属缺口原地保留。当前任务已授权的处置不重复请求同意；新增业务裁定、实质范围或授权缺口才交用户。

旧D件按原协议原文原地保持，只补替代关系；新重要决定使用docs/adr。旧_doc_downgrade工具仍只服务已登记旧分区及仓外索引，不用于docs/archive的新批量处理。

## 四、索引与自动化

README、需求入口与状态导航引用各自主人；来源索引记录历史位置与恢复版本。检查、预算和硬数字回实际工具及docs/reference/thresholds.md，不抄第二份数表。引用查询与整体盘点是明确调查动作，可能覆盖历史；普通任务阅读和默认内容扫描先限定现行与活动资料。

## 五、引用与来源

跨文档写实际仓内路径和必要章节。历史段的旧地址注明来源语境或从来源索引追溯，不把薄入口当成永久目录统一。移动同批修活引用；保留的原文不伪改成今天的结果。需要追溯时从docs/archive/index.md、原票或固定Git版本取原上下文。

## 六、验证与保存

验证内容守恒、独有事实与活动范围、历史原文字节、真实机器输入、缺失反例以及恢复依据。纯文档不默认运行无关业务全套；失败、未执行和未知边界据实记录。提交推送按workflow授权，推送后核远端SHA，恢复只还原本批路径并保护随后出现的新内容。
