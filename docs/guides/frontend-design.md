## 视觉基础

React 主题角色的唯一色值来源为 `backend/app/mod03_notice/page.py`；`theme_react.py` 解析同一组角色，同时供 `GET /api/m15/theme?surface=react` 的预览卡与 `theme.css?surface=react` 的整页消费，Ant Design、AG Grid 和业务 CSS 不另建配色表。441采用用户已认可的八套：中性浅色（存储名“默认”）、原版松绿、暖色纸面、深侧栏、深色、高对比、玫瑰柔粉、丁香浅紫。松绿保原整套配色，其余按批准样板区分页面、侧栏、表面、边框和交互层次；成功/警告/危险/信息及类别色不随主色换义。退出的旧主题在React读取/渲染时回默认，不批量改库；保留主题按原名对应。旧壳十套定义保持，账号偏好字段仍为共享字段，不宣称新旧偏好分离。

共享尺寸基准：MiSans 正文 13.5px，标题 18px，表头至少 12px；字重 400/500/600，数字 tabular-nums。常用控件高 32px，行内紧凑按钮 28px；整页表格基准行高 36px、表头 34px，单元格纵向各留 2px，网格内输入/选择与紧凑按钮采用 28px；工具条仍为 32px。长文本、来源反馈与确认操作按需增高，过程矩阵手填/明细确认分别保 56/76px，完整信息和控件可用优先；弹窗按任务保各自尺寸。字号档位按现有比例缩放文字、控件和表格几何；密度不靠隐藏列或裁剪金额维持。

输入、普通按钮与选择约6px小圆角，卡片/弹窗约8px、内层分组约6px，类别/状态标签约4px；简单矩阵与专业表格保合适直边。普通边界采用0.5px轻线，编辑、焦点、错误和高对比保清楚边界；页面与按钮去多余阴影，浮层保定位所需阴影。分组间距以8/16/24px表达层级，同组控件等高。按钮悬停只反馈颜色/边界，约130ms；减少动态效果时关闭反馈动画。

普通有效文字及占位文字至少 4.5:1，大字号至少 3:1；软底状态使用相应深色文字，浅灰只承担装饰。破坏性按钮及“撤销付款”使用危险红色，查看/更改关联等行内操作有完整按钮外观；付款禁用保柔和主色识别、清晰不可点及原因，不靠整片灰色抹掉语义。侧栏整行 hover/active 使用主题角色，无链接下划线；选中、焦点、错误、禁用不互相覆盖。

风格迁移保已确认的信息位置、业务交互、路由、数据流和表格列；审美认可不等于实验布局或业务验收通过。集采工具顺序、批量区、筛选内分类、内联新增与收发登记、金额旁子表按当前旧壳实际运行入口核对（含加载后绑定），不能只对照模板；账期和付款方式直接在行内编辑，不设独立维护入口。集采三个子表顶部摘要仅保供应商、材料名和本侧合同金额，付款子表将合同金额改为结算金额；下方明细与必要操作保留。正常桌面用组件库分页消除横向和嵌套滚动，合计仍取完整数据；极窄或最大字号以内容和操作可达为底线，不裁内容或缩字硬塞。入口验收从在用根地址和侧栏点击开始，核对同一构建的路由、数据和静态资源。共用基础落地后按页组收敛，未经页面核验不宣称全站完成。

## 阅读与操作

新增按钮、说明或确认步骤前，核当前用户任务和既有入口；没有未满足的用途时不增加重复操作。刷新、清空、重置不是组件接入的默认产品配置，也不能补偿本应自动完成的正常同步。已有业务用途或可访问性需求支持的入口保留。

搜索、勾选与打印/导出范围沿当前有效业务口径，不因前端实现方便增加“先清空搜索才能继续”等前置限制；业务含义冲突时查证并更新原业务主人，不在界面中自行裁定。

默认紧凑业务工作台，留白服务分组和操作，舒适字号不以缩字换空间。页头、筛选、操作条按任务分组；标签/控件对齐，主操作清楚，辅助安静可发现。浮层展开/收起都应协调，长表、弹窗可内滚且不遮主要动作；检查相关视口/放大态，不给关闭的面板永久留大空白。

中文、英文、数字和控件使用本地官方 MiSans，400正文、500表头、600标题/汇总；使用官方 unicode 分片，未覆盖码位按需由完整字库兜底。来源、散列、覆盖与许可归 `backend/app/web/fonts/misans-web/manifest.json`，更新入口为 `tools/dev/sync_misans_web.py`；旧壳、Excel 和打印字体契约各自保持。数字右对齐并采用等宽数字特性，金额列有稳定宽度，长文本可换行；不能借排版改精度、单位、列序或完整金额。冻结对象列、表头、合计与横滚配合，列宽按列量，不在每行重复测量。输入控件可淡边界/淡底，但悬停、焦点、修改、禁用、错误仍可辨。

合理桌面宽度内优先同时显示全部列。AG Grid采用原生内容拟宽与flex：数字、短字段紧凑，长文本承接余宽；机械汇总等已确认金额扩展的表保其角色。原生表格采用浏览器table-layout:auto与width:100%，不再维护自写余宽分配器。AG拟宽只看到已渲染行，完整金额/合计及不可裁断标识仍按当前全量结果保护下限，不能只靠首屏样本；不在滚动时拟宽。编辑期间冻结当前实际宽度，离开编辑后恢复；保用户手调列宽。仅可用下限放不下时横滚兜底，不缩字、隐藏必要列或裁金额。实现依据：[AG Grid 列宽](https://www.ag-grid.com/react-data-grid/column-sizing/)、[W3C 自动表格布局](https://www.w3.org/TR/CSS22/tables.html#auto-table-layout)与[MDN field-sizing](https://developer.mozilla.org/en-US/docs/Web/CSS/field-sizing)。普通编码、日期和操作人等窄列按需换行，保完整内容；付款通知书的单据日期、单据编码，以及库存的单据编号、单据日期、业务类型始终完整单行，不裁断或省略，空间不足保横滚；多行单元格使用正文行距，避免继承单行表格的整行高度。编辑中不全表重测宽，缩窗延后的适配在编辑结束后补做；以实际 CSS 视口和容器 scrollWidth 核完整列、冻结列与按钮。

用户2026-10-28确认AG Grid列宽偏好：默认自动适配，只在列头拖拽结束时保存实际手调列，按账号与表格存于当前浏览器；跨项目、月份/年份复用，不按窗口大小另建配置。手调列保持宽度，其余列继续由原生内容拟宽/flex适配，必要时横滚；字号档位按基准宽度缩放并受当前完整金额/标识下限约束。各表提供“恢复自动列宽”，只清本表列宽偏好，保排序、筛选和勾选。选择框等功能固定列保持固定；付款通知书日期/编码在完整单行下限之上允许拖宽。浏览器存储失败给出本次有效或清除失败反馈，不冒报已永久保存。原生HTML矩阵与特殊明细继续由浏览器自动布局，不另写拖拽或余宽分配器。

MOD05 欠款页上方集采、辅材、机械三块展开全部非零项目，取消局部滚动，由页面滚动承接，零欠款项目仍隐藏。下方逐月双侧台账各按内容定高：短表合计紧接末行，长表内部滚动且合计常驻本表底部。切项目加载时保留上一表区空间、隐藏旧项目数据及编辑入口，完成后按新数据收高；加载/错误不冒充空表。付款流水仍由主表占用剩余可用高度、保留空结果表区及固定合计；小窗口/大字号以页面滚动保证可用。

表格宽高随任务和内容密度安排：列多的工作表充分使用可用表区，短字段紧凑、长文本承担必要弹性，保护完整金额、选择和动作。列少的表限制列宽并收敛或合理组织表格/卡片容器，避免机械均分拉满或内容挤在一角而外框占满页面。行数与横向密度分别判断；内容自适应的短表不强行撑高，已有全高主工作区保留任务布局，不为填空白添加信息或控件。首次数据到达及相关容器变化后实际观察，编辑与用户手调列宽期间保持稳定。先核共享能力的调用、配置、容器与时机，再决定实现改动。

占用工作区剩余高度、正文内部滚动的主工作表，合计固定在本表数据视口下边缘，少量数据时也不漂在正文中间，横向滚动时与对应金额列一致；双侧表各归自己的容器。内容自适应短表的底部随内容结束，不为沉底制造整屏空白；合计不固定到整个浏览器窗口遮挡其他表格、弹窗、分页或滚动条。位置不改变业务合计范围和数值，优先使用现有组件能力。

表格操作保留中文输入和鼠标编辑所需的输入位置；虚拟滚动不缩小选择/合计/导出范围。连续编辑保存和读回不覆盖下一格草稿、焦点或滚动。账号/项目/月/记录明确归属，迟到响应不能串范围。自动预填、上次值带入、已保存与已确认采用分别可辨，不能用空白和零混淆。

收发结存、年度提取和月度会大表按真实结果自然增高，合计紧接末行，长页由整页滚动承接；大表编辑期间保持列宽。切页只给标题约130ms短反馈，库存计数局部反馈，不对大表整体位移或逐行入场，也不等待动画才开放操作。

时间选择按调用者能力提供月、同年跨月、年、季度、周或全部；普通日期录入保持日期控件。侧栏固定在视口内，与正文独立滚动，导航文字和底色沿对应主题角色变量保持对比。

业务弹窗居中，按任务和内容定宽并设视口高度上限；短名单、单段备注收窄，长表正文内滚，标题和主要动作可见。展开/收起都检查，不能把场景尺寸设为全站固定值。提供右上关闭、点外、Esc 与右下取消；无变化直接关闭，输入/选择变化须确认放弃，处理中保持既有保护并归还焦点。

行内动作使用紧凑按钮，金额/编码导航保链接语义，均有完整点击区和悬停反馈。表格正文支持浏览器原生拖选复制，AG共用默认启用文字选择及DOM顺序；鼠标点只读文字不画冗余整格大框；内嵌输入保留清楚的编辑焦点。分类与付款方式保完整文字、箭头和当前值，不能因控件窄而猜类别。双侧台账合计各归对应表，流水合计在金额列下对齐，金额完整保留。

撤销/重做按钮先显示当前动作名称和影响数量，确认时重核同一历史条目，取消不写入；原生输入框内的编辑撤销保留。项目档案的可编辑字段直接在行内维护，类型只展示，排序拖动显示整行及相邻位移。通知书、流水和集采搜索在非空时提供清除入口，流水实时搜索；集采统一搜索替代供应商专用搜索和合同金额下拉。

应用内切页保筛选、勾选、排序、滚动和未保存输入；后台重读保既有画面/草稿。这些临时状态只在当前账号内存保存，F5/重启重置，换号清理；不能把身份核验网络失败当作退出而丢上下文。列宽偏好按本页持久化规则，永久导出偏好按[付款与欠款](../requirements/payments.md)的业务规则。

新前端复用自己的共用构件；旧壳 projPanel、原生 select 裁剪例外、卡头 .sp 与 shell/view.js 适配沿[旧前端参考](../reference/legacy-frontend.md)，不把旧选择器移植成 React 规则。

## 状态、颜色与反馈

加载、空、错误、部分成功和完成如实区分；不把未加载画零或空表。结果贴对应行/格，整批可给总评，正常跳过与需处理异常分别用词/标记/计数。数值带对象、单位、时间口径，可由明确表头承担；未知仍未知。

React控件复用现有AntD日期、选择、输入和语义标签；金额/中文输入/离格草稿编辑器沿现有实现，不为控件替换改变字符串与保存语义。普通短暂成功可用App消息；过程资料按用户2026-10-27决定不显示保存成功提示，也不替换为浮动通知；子表、抓取、付款及机械写入的失败、部分结果、待核实和需后续处理清单留在对象旁，便于持续核对。

提示成功绿只用于已经完成的回执，警示黄只用于须注意的风险/禁止项，预告、空态指路和普通说明用普通提示。颜色只表达语义：主操作用主题强调色，破坏性动作危险色，恢复不与删除同款；警告、失败、成功、普通跳过可区分。金额正负本身不是异常，不凭正负自动刷红绿。合计靠位置、字重、底色，不和异常抢颜色；通用壳选颜色，业务域给含义/文字。主题变量统一，页面不复制硬编码配色；界面字号档位按用户保存/隔离并立即生效。

React 状态标签使用 `status-tag`，类别与付款方式使用 `EnumTag`；两类各消费自己的语义角色，避免类别默认色覆盖状态。少量枚举状态和有限类别用带完整文字的彩色标签；可编辑状态控件保交互及相同语义色。完成绿、待处理/部分完成黄、错误/禁止红、撤销中性灰；类别用稳定类别色，不把类别当成功或危险。重要含义同时有文字、形状或位置依据。

不可执行动作提前禁用并说明原因与可解决路径，后端仍兜底。结果说明发生了什么和下一步，处理中不说完成。默认值要符合真实业务，重要后果在决定位置可见；改动后的默认、展开、收起及受影响空/错状态要实际观察。截图生成、能点击或静态断言不能单独证明视觉/业务完成。

## 熟手文案

优先用分组、层级、间距、对齐、颜色和形状表达关系；每个元素有明确主要用途。删重复说明前核是否仍有消歧、必要操作提示或可访问性名称，仍有歧义保最短必要标签，不能为去文字而让用户猜后果。

保留系统特有行为、数值来源、不可逆后果和下一步；删业务常识复述、机制辩解、内部规则编号及已由控件表达的说明。旧页首口径抽屉不恢复，必要后果放对象附近。用“写入/写不进去”“抓取”“信息化编号”等熟悉用词；“入库”留给材料业务，解析可用。普通操作面避免后端字段、URL、异常类名和状态码。

人话错误出口为 core/errors.py 的 human_reason/log_exc，旧壳为 api.js 的 errHuman。技术原文留运行日志、执行记录或专门技术明细，打印机地址等用户核现场所需信息保留。悬停可按排障用途保必要编号，不能只因技术词清掉线索。相同且会一起变化的完整标签可抽共用；说明块提取常量时核测试/实际 DOM，不能让检查失明。

## 领域专属显示

项目候选显示/归档/排序回 [项目](../requirements/projects.md)；活动大表独立排序。集采动态序号与合同编号分开，纳入/不纳入不占同一套序号。机械公司汇总/明细/核对保持四页职责，长表金额跳转的临时项目范围切页/换月/预览/取消筛选即清，缺值/差异提示不改完整项目合计。业务规则各归需求分册。

交付只核受影响构件与相关状态；默认/展开/收起、勾选前后及同类双侧区域成对检查，共用件核受影响调用者。真实默认、变化与必要缩放可读、可操作、无错位遮挡才结束。检查入口见 [开发指南](development-and-verification.md)，无需为每次小修新增永久文档或全站截图。

弃稿确认全站复用集采台账的通用标题“放弃未保存的修改？”、说明“本次输入和选择尚未保存。”及“继续编辑 / 放弃并关闭”按钮，不按业务另写版本；轻量确认采用同一420px字号缩放宽度与内容自适应高度，不继承业务工作窗的固定大高度。自动推荐、读取后的默认带入不算用户修改；未操作或仅前后切换步骤时直接关闭，实际输入/选择变化才提示。
