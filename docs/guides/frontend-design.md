## 浏览器支持（用户2026-11-12确认）

表格宽高随任务和内容密度安排：列多的工作表充分使用可用表区，短字段紧凑、长文本承担必要弹性，保护完整金额、选择和动作。列少的表限制列宽并收敛或合理组织表格/卡片容器，避免机械均分拉满或内容挤在一角而外框占满页面。行数与横向密度分别判断；内容自适应的短表不强行撑高，已有全高主工作区保留任务布局，不为填空白添加信息或控件。首次数据到达及相关容器变化后实际观察，编辑与用户手调列宽期间保持稳定。先核共享能力的调用、配置、容器与时机，再决定实现改动。

### 动效与连续操作

2026-11-06用户授权重新选择动效方案，Q2为改善目标，Q1/Q6/Q7为约束，替代此前仅保标题短反馈的限制。页面、浮层和展开分别表达任务位置、前后层次和内容关系；操作与业务回执由原逻辑立即处理，动画不承担成功判定或写入锁。

- 页面保活节点由Motion驱动短距离纵向接续，方向沿导航顺序；导航选中背景在原入口之间移动。工作区标签用横向接续和移动下划线。旧内容退出时立即`inert`并退出可访问树，保持原节点、尺寸、滚动、筛选、选择和草稿，隐藏后暂停原有查询/布局准备。
- 业务弹窗由Ant Design继续持有遮罩、关闭与焦点机制，`BusinessModal`持有共同的轻缩放/纵向进入与更快退出。条件挂载调用使用`DialogPresence`；退出中的旧窗不可点击，每次重新打开独立建实例，保调用者原有key语义。弃稿、在途写入、未知回执和读回判断沿原业务主人。
- 普通控件反馈约130ms，组件状态约240ms，浮层进入约320ms、退出约180ms；原生details展开约280ms。保活视图和位置指示采用共用有阻尼弹簧，静止后结束，不做循环装饰。弹簧与presence归`workspace-motion.tsx`，浮层曲线和原生展开归`ui-theme.css`，AntD令牌归`ui-provider.tsx`。
- 尺寸展开优先用浏览器`::details-content`与`interpolate-size`，旧浏览器保原生即时开合；不测量或排队每一行，不让长列表等待逐行动画。网格内控件的颜色/禁用反馈即时更新，页面和portal浮层承担运动，避免保活切页时数百控件逐个过渡并触发重复尺寸准备；表格内保存和数据重读保持安静，局部反馈继续消费真实状态。
- 减少动态效果由稳定Provider、CSS与共用动效上下文协调，关闭空间运动；运行中切换设置不重建账号树、弹窗或草稿。原生输入、焦点归还、鼠标继续操作始终保持。

选型采用Motion 14.10.0（MIT）与既有AntD 6.6.7 / rc-motion 1.3.3，精确版本和间接依赖以组件锁文件为准。原生CSS候选已用于实际页面、弹窗和展开对照；Motion的收益是可中断弹簧、共享位置指示及卸载前退出的成熟实现。没有引入自制动画引擎或改变路由、查询和保存体系。View Transitions的快照和串行中断方式不适合当前高频保活工作区，未接入路由。退出Motion时，先恢复保活节点的即时显隐与条件卸载，移除位置指示组件和对应依赖；原业务状态、AntD弹窗与原生展开可独立保留。

实现与判断参考：[Motion布局与中断](https://motion.dev/docs/react-layout-animations)、[Presence退出](https://motion.dev/docs/react-animate-presence)、[减少动态效果](https://motion.dev/docs/react-accessibility)、[Ant Design动效](https://ant.design/docs/spec/motion/)、[IBM Carbon动效实践](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview)、[原生details内容过渡](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/::details-content)。验收以同条件生产构建录屏、必要的浏览器性能记录和连续操作为准，静态画面及类型检查不单独证明自然或流畅。

## 状态、颜色与反馈

加载、空、错误、部分成功和完成如实区分；不把未加载画零或空表。结果贴对应行/格，整批可给总评，正常跳过与需处理异常分别用词/标记/计数。数值带对象、单位、时间口径，可由明确表头承担；未知仍未知。

React控件复用现有AntD日期、选择、输入和语义标签；金额/中文输入/离格草稿编辑器沿现有实现，不为控件替换改变字符串与保存语义。普通格内编辑从输入、回车或离格保存到后台读回的全过程保持静默：本格保留当前输入，不短暂回旧值；无关内容不位移、不闪隐，不重新拟列宽，用户期间主动滚动的位置不被恢复逻辑覆盖。只更新必要的业务值及关联合计，不为普通数值变化重做整表排版；真正的范围、字号、容器变化及必要业务提示按各自既有规则处理。聚焦、普通草稿、保存中与后台重读不插入说明或状态条；原有取消修改入口置于既有工具行的固定位置。已确认写入但读回未结束时保留输入显示，读回成功或明确核对后再退出相应草稿，下一格输入不被覆盖。批量操作、导出等独立动作的短成功消息在底部居中、避开合计及滚动条，自动消失且不占布局；通知书剔除回执为“已剔除 N 条”，不常驻展示显示/有效/剔除/撤单统计说明，不显示标记保留、默认隐藏、不销毁数据或规则来源等操作常识（含悬停说明）；过程资料按用户2026-10-27决定不显示保存成功提示，也不替换为浮动通知；子表、抓取、付款及机械写入的失败、部分结果、待核实和需后续处理清单留在对象旁，便于持续核对。

过程资料金额回车或离格保存，非编辑时用千分位和两位小数，编辑保原始数字文本、输入法和输入位置。正常保存保持安静；明确失败保留原输入，原因/重试与取消贴对应格，其他合法格可继续保存。未知结果说明项目、月份、字段及本次输入，重读后明确核对状态，核对前暂停后续保存；切页和切项目仍保草稿，不增加离页阻塞。已有机械明细时的来源切换确认沿机械费需求。

提示成功绿只用于已经完成的回执，警示黄只用于须注意的风险/禁止项，预告、空态指路和普通说明用普通提示。颜色只表达语义：主操作用主题强调色，破坏性动作危险色，恢复不与删除同款；警告、失败、成功、普通跳过可区分。金额正负本身不是异常，不凭正负自动刷红绿。合计靠位置、字重、底色，不和异常抢颜色；通用壳选颜色，业务域给含义/文字。主题变量统一，页面不复制硬编码配色；界面字号档位按用户保存/隔离并立即生效。

React 状态标签使用 `status-tag`，类别与付款方式使用 `EnumTag`；两类各消费自己的语义角色，避免类别默认色覆盖状态。少量枚举状态和有限类别用带完整文字的彩色标签；可编辑状态控件保交互及相同语义色。完成绿、待处理/部分完成黄、错误/禁止红、撤销中性灰；类别用稳定类别色，不把类别当成功或危险。重要含义同时有文字、形状或位置依据。

不可执行动作提前禁用并说明原因与可解决路径，后端仍兜底。结果说明发生了什么和下一步，处理中不说完成。默认值要符合真实业务，重要后果在决定位置可见；改动后的默认、展开、收起及受影响空/错状态要实际观察。截图生成、能点击或静态断言不能单独证明视觉/业务完成。
