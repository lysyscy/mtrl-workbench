# React 工作区与表格架构

## 账号工作区与页面

React 账号工作区由 `apps/frontend/src/main.tsx` 的 `pages` 注册表统一派生页面标题、分组导航、路由和已访问页面的保活容器。切页只暂停所属页面，账号树与 QueryClient 的重建边界保持独立。每个账号组件树持有独立 QueryClient；初次身份读取失败只提供重试，已知身份暂时核验失败时保留树、筛选和草稿，隐藏数据并以 inert 暂停操作及查询，同账号核实后恢复并重读，确定换号或会话失效才清缓存重建。

业务页统一通过 React.lazy 按页加载。每页的 PageErrorBoundary 隔离资源加载及渲染错误，保留导航和其他保活页面；显式重新加载页面前消费 useHistoryProtection，在途操作、未知结果或未保存草稿仍阻止刷新。

欠款页与流水页共享同一账号 QueryClient，但分别保活。台账编辑/保存仍由 LedgerPage 持有，跨页导出与历史操作继续消费账号工作区的台账 guard；不能因拆导航而卸载草稿或绕过在途/未知结果保护。通知书定位流水不依赖欠款项目或欠款查询就绪。

## 表格与更新边界

PageSurface的首次发布由页面显式`data-page-loading`和`data-page-chrome`所指字体决定，各表负责自身布局和局部重试。QueryCache只唤醒准备检查；身份核验、已有内容保活和保存锁继续由各自主人持有。PageActivity向新增业务网格传递当前页可见性，保活隐藏页暂停尺寸准备；路由使用BrowserRouter公开useTransitions=false，及时切换路由身份，首次数据/字体等待仍由现有PageSurface负责。

React业务数据表统一用AG Grid Community承载输入、合计、分组表头及虚拟窗口；标准屏幕视图展开报表合并标签，沿用原服务端快照值，不从重复标签重算金额。Excel/PDF继续由原模板生成，不依赖企业版。受管声明补丁只处理已采用网格版本与 TS7 严格可选属性的兼容；精确版本、补丁与升级核对回组件依赖及锁文件。

库存、通知书、付款流水、欠款双侧主表、机械公司汇总、收发结存、焊材/气体年度提取及月度会大表经`grid-presentation.tsx`装配表格呈现生命周期：页面提供业务列、数据及范围，内部统一列定义保留、尺寸所有权、测量列派生、挂载、首显与局部重试；`grid-layout.ts`仍持有深尺寸准备：文本短内容走字体测宽，长文本与富控件在最终宽度下有界实测；富控件通过所属React树的portal复用真实渲染器和上下文，不直接复制控件样式。统一应用正文/固定合计行高及表头后发布首显，保留虚拟滚动。工作区实际AG数据行以paint containment限定重绘范围，避免滚动时行内容使大区域反复绘制；离屏grid-layout-measure保持自然溢出，浮层沿原portal挂载。

相同不可变输入及实际几何复用已应用布局；自然高度表的自身输出高度不作为尺寸失效输入，普通固定高度表仍响应高宽变化。表头按几何缓存；实际富控件字体在测量前等待，无关页面字体完成事件不使本表失效。同范围重读保留画面、当前编辑器及用户列宽，范围改变回顶部，切项目隐藏旧范围。

输入期间延后替换渲染器定义；通知书稳定排序回调，避免无关渲染触发重排和整行重建。正文与合计数据直接交给AG Grid按稳定行ID增量更新，不等待异步尺寸测量才发布；普通保存的滚动保留交给原生网格，不再记录或恢复自制阅读锚点，用户在保存期间主动滚动也不被覆盖。字体取消的准备与已应用布局分开记录。

通知书与欠款的PageSurface只等待现有工具区字体，不串联全局查询、表尺寸和额外双rAF；通知书表区及欠款双侧各自等待实际字体和尺寸应用，保留首次表框，局部失败提供重试。计数与侧标题字体随所属表准备；数据依赖动作沿原禁用语义。机械及材料报表沿同一工具区/表区边界发布；分组列保原结构，固定合计按pinned取值，富控件适配只支持当前实际使用的数据取值与渲染器。

自然高度报表在当前已知行DOM、公开渲染队列及实际需要的横向滚动条占位完成后发布；机械同范围重读保留现有汇总输入。BusinessGrid复用同一PreparedGrid准备链承载新增复杂编辑工作区和过程矩阵，调用方直接提供原生ColDef，不新建表格DSL。重复小表及同快照只读报表由ReadGrid使用AG原生行/表头自适应及同一字体、主题与列宽入口，内嵌输入仍由业务组件持有，避免每张小表都启动深测量。

合同候选使用react-virtuoso虚拟化原卡片，完整候选与选择仍归原主人。过程差异与特殊费用也复用共享准备，差异按网格挂载建立首次状态，费用展开状态参与富控件测量且行ID采用安全编码；费用工具区与表区按既有PageSurface模式独立首次发布。过程工具字体与自身数据并行，外框保持满内容区并等本表真实拟宽，其他保活页查询不阻塞；过程矩阵沿同一字体与布局准备发布，原生分组表头、固定核算月、底部合计与内部滚动保持；编辑会话保当前列宽。

AG Grid的列宽采用首次fitCellContents与原生列状态；普通输入、离格、保存读回不重新拟宽。列定义使用initialWidth/initialFlex，已显示布局的尺寸建议保留到范围、字号、实际容器尺寸或显式复位变化；不因普通数据更新或滚动重算，不恢复退役的table-widths分配器和整表userWidths开关。列定义由React单独发布，手调列在交给AG之前即解除自动min/max，不能先按自动边界夹紧、再靠异步事件恢复手调宽度；grid-width-state只通过公开ColumnState应用有实际差异的宽度，并消费完成的uiColumnResized事件持久化手调列，grid-widths接账号上下文、字号、真实布局变化和恢复入口；自动列不写偏好。

按账号/表格使用localStorage，项目/月/年不进入偏好键；恢复时先用原生resetColumnState释放宽度所有权，再应用不含width/flex的原列状态以保排序、显隐、固定和列序，筛选与业务勾选仍由原主人持有。已删除焦点进入/离开时清空和恢复flex的冻结通道。首次布局仍以完整结果保护非首屏金额和标识，普通数值变更复用已有行高与列宽；富控件真正发生多行正文或错误变化时才重新测量，手调偏好保持。

同一账号/表的多实例共享内存列宽通道并按完成的原生列宽事件同步，最后一个实例退出后释放；项目排序采用AG原生非受管行拖拽，持久化仍按完整项目顺序和状态分区转换，不用可见行索引。当前完整覆盖、成本缺口及受控操作未验边界回TAIL-449证据。注册表页面使用普通 React.memo，台账独用项目 prop，历史上下文依真实依赖稳定，router/context/query 更新继续参与。

库存枚举只在筛选弹层打开时按依赖计算，条件预编译，空筛选复用原数组与合计；机械下载继续消费全页 ledgerExportGuard。。

减少动效通过 CSS 和始终存在的公共 MotionProvider 处理，避免动态插入 Provider 重建账号树、丢弹窗或草稿。首页复用通知书同一查询与失效链；i8 页展示本机配置、现有结果及执行记录，读取结果不代表调用外部接口。

账号重新核验后各字段不变时保留身份对象引用，避免所有保活页因同值新对象重绘；不可见窗口的聚焦事件不触发检查，同一在途检查合并重复聚焦。没有时间宽限或跳过已触发核验的访问保护，同账号仍按原语义恢复并重读。相同“全部项目”查询统一缓存键，默认在建项目与档案维护扩展形状保持各自口径。

AG Grid只注册当前采用的公共module与其依赖，含行样式、合并格、提示及所需命令能力；现有浏览器入口同时捕获缺module运行错误。布局观测区分当前准备与复用，复用不沿用旧的测量耗时；AG原生列宽事件与尺寸准备分别核验，不把旧data属性或networkidle静默窗口算作本次工作。
