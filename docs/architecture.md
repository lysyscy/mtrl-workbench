# 当前架构与工程不变量

FastAPI 承载业务，PostgreSQL 保存事实，NSSM 托管现行单 worker 服务。旧前端在 backend/app/web；React 在独立工作树的 `apps/frontend` 开发；候选 `FRONTEND_APP_DIR` 可将同源 `/app` 指向完整React发布目录，空值保旧壳；`FRONTEND_PREVIEW_DIR` 只启用隔离 `/preview`。构建与操作见[预览指南](guides/frontend-preview.md)。正式 `/app` 已于2026-10-28启用React，旧壳保留作同一升级后端/当前库的界面回退；现场版本与用户验收边界回[状态](status.md)。抓取走 HTTP，PDF/打印渲染在服务身份下运行。

React 已获准采用构建步骤；原无构建/不另用 React 的旧阶段限制已被本次授权取代。业务判定、金额与写入仍归后端，正式切换和旧版退役分别守原授权。

React 账号工作区由 `apps/frontend/src/main.tsx` 的 `pages` 注册表统一派生页面标题、分组导航、路由和已访问页面的保活容器。切页只暂停所属页面，账号树与 QueryClient 的重建边界保持独立。每个账号组件树持有独立 QueryClient；初次身份读取失败只提供重试，已知身份暂时核验失败时保留树、筛选和草稿，隐藏数据并以 inert 暂停操作及查询，同账号核实后恢复并重读，确定换号或会话失效才清缓存重建。

欠款页与流水页共享同一账号 QueryClient，但分别保活。台账编辑/保存仍由 LedgerPage 持有，跨页导出与历史操作继续消费账号工作区的台账 guard；不能因拆导航而卸载草稿或绕过在途/未知结果保护。通知书定位流水不依赖欠款项目或欠款查询就绪。

## 分层与装配

core 保存金额、时间、配置、身份和共用机制，不 import 业务包；需要业务数据时由 core_bindings 注入 loader，取数实现归数据主人。mod 包间调用 service，不跨包直查 repository/表；既有允许边界以 test_layering 与实现头说明为准。page 的按钮/表单 HTML 不进入 API 导出，PAGE_ONLY_KEYS 负责剔除。

操作人使用 core/identity.py 的 current_operator。金额规范回 [需求](requirements.md)，唯一计算出口 core/money.py，数据库使用 numeric(18,2)，不引入整数分列或 float。月份展示可用 substr，月份过滤用日期闭区间以利用索引。新增 ORM 模型同步 models_registry；模型漏声明默认值/约束先修模型，不用迁移误删真实结构。

## 写入、幂等与恢复

付款在同一事务先按通知书ID稳定次序取得FOR NO KEY UPDATE行锁并刷新Session缓存，再读余额/关联/状态、整批校验和写流水重算；锁序与用户选择/回执顺序分开，不额外锁旧流水以免反转撤销锁序。低频编辑按版本拒绝冲突。重复 request_id 不重复付款。占位档案取号在事务内，唯一约束与受控重试兜底。导入替换限同源自动行，保手动行及人工覆盖；业务批次/撤销模型与数据保留，即使旧导入入口退出。

长任务先取得必要数据、释放写事务，再渲染/投递；外部请求不持有长写事务。同表抓取串行，人工触发留执行记录。i8 界面操作的强踢策略、调用边界与恢复语义归 [i8 契约](reference/i8-contract.md#界面主动操作与登录策略)；内部必要空响应复核也按该契约，不能扩大成外部动作重试器。

跨页写入后统一失效并重新读真实数据，不维护一张人工“写→读页”依赖副本；本项目读取量允许全标脏，避免读侧变化漏同步。保存成功而读回失败须区别于写入失败，保护后续草稿和编辑焦点。账号、项目、月份和记录身份进入读取/草稿范围，迟到响应不能覆盖新上下文。

React公共网络/金额工具归`apps/frontend/src/api.ts`，域API保逐端点回执校验；合同与付款流水读取以Valibot schema推导类型并校验；合同在contracts-api分共同/列表/详情，列表专有归属/关联字段与详情发票结构分开，保原对象额外字段及退回日期null归一；流水在flow-api保两态及nullable归属，金额继续由core cents校验，不把缺失事实补成0；notices-api保工具兼容再导出。身份确定变化时切断上一账号请求生命周期，合并请求自身signal，旧401不得清掉新身份。窗口返回的背景核实保本地点击/输入响应，身份请求自身外的新网络意图等待核实；同账号继续一次，变化取消旧意图，失败明确阻断并保App重试入口，不把未发出的写入标为结果未知。台账POST出口归ledger-api，页面保队列、版本、草稿和焦点。明确成功、明确拒绝、结果未知和已写成后重读失败分别处理；未知须可靠读回，不因放弃草稿自动解除。全站只用HistoryControls办理撤销/重做，各域以useHistoryGuard登记草稿/进行中/待读保护。项目写后刷新及未知结果可靠读回同步失效当前账号QueryClient中的history查询，保持项目自身读回与历史读取错误各自语义，不全量重取其他页面。台账草稿键包括账号、项目、查询范围、行记录及原所属月份；同账号未知写入跨项目保持锁定，可靠台账和历史读回后才解除，离页暂停查询和后续写入。

过程资料、月度会大表与历史结余的单格提交共用`cell-save.ts`的快照/串行/结果分类/未知锁机制，`use-cell-save.ts`接React生命周期与history guard。各域保留草稿身份、来源预检、确认写入后如何续接后续草稿及可靠读回；明确拒绝、未知结果、已写成后重读失败分开，放弃草稿不解除未知锁。台账的版本令牌和原月份续接、费用新增记录恢复及机械批次确认保持专有实现。

React过程资料机械逐格保存使用/api/m06/mech-cell，旧壳/api/m06/mech保既有手填协议；新入口的原金额与签名取同次机械有效值读取。机械明细编辑、JSON导入与有效月值决策按项目/月持事务锁，导入多月按稳定次序先锁后验版本；确认通过后在同事务切来源并保存金额，其他格、明细与依据保留。

过程资料历史材料的手填值以项目、月份和列独立保存，读表与导出在有效历史快照之上逐格应用；保存核对原显示值并串行化，同月库存存在时拒绝写入。项目删除关联检查与操作历史包含该载体。

## 安全操作历史

core/history 在业务 session_scope 内观察变更，history_bindings 装配允许模型/字段，与业务同事务保存 operation_history。历史值留服务端；按在用账号事务锁串行写/撤销，核预期历史头、锁定目标/关联、完整值及 PostgreSQL xmin，整批通过才改。可信恢复凭原事务版本和完整值续接，遇实际行修改/版本断点停止；只在同账号、同方向、最近 barrier 后作用。旧条目缺凭据仍可安全单步，不推断跨动作续接、不批改生产历史。

同事务中的父记录也属于完整变更集合时，由该变更的完整值和版本验证，不再重复当作不变外部依赖；全部锁定校验后按外键依赖先删子后删父、先恢复父再恢复子，同事务失败整体回滚。外部依赖、原有字段规则及版本断点保护保持。费用新模型不猜测重放旧 `fee_manual_item` 历史；旧表与历史保留，结构不适用的撤销明确拒绝。

拟付款方式的账号锁、更新、barrier 和旧 redo 失效同事务；结构/规则变更不能猜测重放。deleted 与业务 voided 含义不同。现有 history_api、测试隔离和 rollback_db 继续保护真实撤销。

## 运行与资源

配置有效值沿 core/app_settings.py 的 effective 链，页面库值与 .env 职责见 [部署](guides/deployment.md)。PDF 使用 headless Chromium，服务账户必须能访问浏览器及字体；render.py 为避挂死保留的回收方式在改变生命周期前要核实际服务环境。打印版式来自 i8，IPP 接收不等于纸面完成。

共享Excel读表与单元格解析保留在import_kit/workbook、readers、parse；React425移除通用API/域映射向导及旧两域专属编排，不移除模型、历史批次/来源读取或机械JSON链。mod06_proc/mech_report的只读报表解析仍用于真实导出回读验证；模板生成及透视缓存回 [模板](reference/template-export.md)。真实资产由 report_export/resources.py 和文件字节定义，delivery 只作第三方来源，不能反推业务。有效分层、隔离、金额、撤销及模板测试保留；已退出文档机器链不再影响运行配置。

过程资料的库存读取仍经mod08数据主人；`load_process_rows`只投影所需九列并附同一调整痕迹，保原金额Decimal、ID行序和两次批量查询。普通库存规范行、原单/调整单及其他消费者保持原出口。库存扩展调整保存在旁路JSON中，旧amount-only记录原样兼容；core.money负责最终联算与舍入，React使用Decimal.js只预览。保存/撤销在原单行锁下验证源值与当前调整令牌，不修改导入原字段；调整后物料性质用于过程归类，多字段差异留痕随同一批量投影读取。

## React 表格与更新边界

PageSurface的首次发布由页面显式`data-page-loading`和`data-page-chrome`所指字体决定，各表负责自身布局和局部重试。QueryCache只唤醒准备检查；身份核验、已有内容保活和保存锁继续由各自主人持有。

历史台账用同一 AG Grid Community 承载输入、合计和虚拟窗口，合并布局用语义 HTML 表格，不依赖企业版。受管声明补丁只处理已采用网格版本与 TS7 严格可选属性的兼容；精确版本、补丁与升级核对回组件依赖及锁文件。

库存、通知书、付款流水、欠款双侧主表、机械公司汇总、收发结存、焊材/气体年度提取及月度会大表经`grid-presentation.tsx`装配表格呈现生命周期：页面提供业务列、数据及范围，内部统一列定义保留、尺寸所有权、测量列派生、挂载、首显与局部重试；`grid-layout.ts`仍持有深尺寸准备：文本短内容走字体测宽，长文本与富控件在最终宽度下有界实测；富控件通过所属React树的portal复用真实渲染器和上下文，不直接复制控件样式。统一应用正文/固定合计行高及表头后发布首显，保留虚拟滚动。工作区实际AG数据行以paint containment限定重绘范围，避免滚动时行内容使大区域反复绘制；离屏grid-layout-measure保持自然溢出，浮层沿原portal挂载。相同不可变输入及实际几何复用已应用布局；自然高度表的自身输出高度不作为尺寸失效输入，普通固定高度表仍响应高宽变化。表头按几何缓存；实际富控件字体在测量前等待，无关页面字体完成事件不使本表失效。同范围重读保留画面、当前编辑器及用户列宽，范围改变回顶部，切项目隐藏旧范围。输入期间延后替换渲染器定义；通知书稳定排序回调，避免无关渲染触发重排和整行重建。压缩滚动按真实可见行、表头下沿和原生滚动范围恢复，程序恢复的取整余差不再作为下一次锚点输入；字体取消的准备与已应用布局分开记录。通知书与欠款的PageSurface只等待现有工具区字体，不串联全局查询、表尺寸和额外双rAF；通知书表区及欠款双侧各自等待实际字体和尺寸应用，保留首次表框，局部失败提供重试。计数与侧标题字体随所属表准备；数据依赖动作沿原禁用语义。机械及材料报表沿同一工具区/表区边界发布；分组列保原结构，固定合计按pinned取值，富控件适配只支持当前实际使用的数据取值与渲染器。自然高度报表在当前已知行DOM、公开渲染队列及实际需要的横向滚动条占位完成后发布；机械同范围重读保留现有汇总输入。零租、包月及核对工作台原生表无需测量层改造。过程差异与特殊费用也复用共享准备，差异按网格挂载建立首次状态，费用展开状态参与富控件测量且行ID采用安全编码；费用工具区与表区按既有PageSurface模式独立首次发布。过程工具字体与自身数据并行，外框保持满内容区并等本表真实拟宽，其他保活页查询不阻塞；原生矩阵等实际字体完成后发布，浏览器auto表格算法处理内容与余宽；编辑会话只快照实际列宽并在离开后释放。AG Grid的列宽采用公开autoSizeColumns与原生flex，退役table-widths分配器；只在字体/数据/尺寸依赖变化时拟宽，不因滚动重算。非首屏的完整金额和标识由完整结果下限补足，富控件行高、锚点和手调宽度保护继续保留。天然稳定原生表保持原结构。当前完整覆盖、成本缺口及受控操作未验边界回TAIL-449证据。注册表页面使用普通 React.memo，台账独用项目 prop，历史上下文依真实依赖稳定，router/context/query 更新继续参与。库存枚举只在筛选弹层打开时按依赖计算，条件预编译，空筛选复用原数组与合计；机械下载继续消费全页 ledgerExportGuard。

减少动效通过 CSS 和始终存在的公共 MotionProvider 处理，避免动态插入 Provider 重建账号树、丢弹窗或草稿。首页复用通知书同一查询与失效链；i8 页展示本机配置、现有结果及执行记录，读取结果不代表调用外部接口。

账号重新核验后各字段不变时保留身份对象引用，避免所有保活页因同值新对象重绘；不可见窗口的聚焦事件不触发检查，同一在途检查合并重复聚焦。没有时间宽限或跳过已触发核验的访问保护，同账号仍按原语义恢复并重读。相同“全部项目”查询统一缓存键，默认在建项目与档案维护扩展形状保持各自口径。

AG Grid只注册当前采用的公共module与其依赖，含行样式、合并格、提示及所需命令能力；现有浏览器入口同时捕获缺module运行错误。布局观测区分当前准备与复用，复用不沿用旧的测量耗时；集采拟宽与原生矩阵各有自身计时，不把旧data属性或networkidle静默窗口算作本次工作。
