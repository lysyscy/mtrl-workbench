# 领域文档（本仓怎么消费）

> **读者**：要动某片区域、要给概念起名的 agent｜**回答**：动之前该读哪几份"领域口径"、冲突了怎么办
> **何时读**：修改业务含义、处理术语不清或核对决定冲突时；仅定位代码不用默认读取
> ⛔ 本页不新增口径：业务口径的主人永远是 `delivery/材料科业务全流程说明书.md` / `delivery/PRD/`。

## 一、本仓的布局（**单上下文**）

| 要读的 | 在哪 | 什么时候读 |
|---|---|---|
| **业务规则 / 字段含义 / 界面措辞** | `delivery/材料科业务全流程说明书.md` / `delivery/PRD/` / `MOD-*` | 动业务行为（钱 / 状态 / 用词）之前 —— ⛔ **别从记忆复述，回原文读** |
| **术语与用词** | 交付面《说明书》的用词 ＋ `.codebuddy/work/40-decisions/D29-文案审计口径-以熟手为准.md`（含**用词统一表**） | 写任何"上屏文字"之前 |
| **决策（＝ADR 那一类）** | `.codebuddy/work/40-decisions/D*.md` | 需要核对某决定的理由或准备推翻它时；与决定冲突先说明，按当前授权判断 |
| **工程侧底账** | `ops/README.md`（索引）＋ `ops/architecture.md` / `modules.md` | 摸架构 / 模块分工 / 起停之前 |

## 二、术语表：**本仓不单建 `GLOSSARY.md`**

⛔ **理由**：术语主人已经在 `delivery/`《说明书》/ `delivery/PRD/` ＋ `D29` 的**用词统一表**里；再建一份 = **第二套口径**（改一处漏一处，本仓最贵的病）。
⚠️ 真出现"概念没名字、说不清"时，**由 `/domain-modeling` 按需懒建**（⛔ 不提前建、⛔ 不为建而建）。

## 三、与决策冲突时怎么说

要推翻一条已定的决定（`work/40-decisions/` 里的）⇒ **先把冲突说出来**，格式照：

> _与 `D26`（导入只留通用面）冲突，但值得重开，因为…_

⭐ 决定件**只加不改**：被推翻的**不删原文、不加改写**，只补一行 `Superseded by:` 指向新的那份（这是本仓既有口径，⛔ 本页不复述 —— 完整口径与出处见 `.codebuddy/work/README.md` §二）。
