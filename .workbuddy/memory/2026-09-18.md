每表 = `项目 | 结余 | 1月…12月 | 合计`）。

**三条硬性**（《说明书》§7.1 ＋ 清单 §四-5）：认 `DATA_START` **文字**定位 · **尾块随行数派生** ·
**新数据区之外一格不留**。

**⭐⭐ 三个实测坑（都踩了、都修了、都加了断言）**
1. `insert_rows` / `delete_rows` **不搬合并区**（openpyxl 3.1.5 实测）—— 值与样式会搬、**合并区不会**
   ⇒ 尾块的合并必须自己按 offset 平移（片 4a 的过程资料才第一次真用上）。
2. `delete_rows` **留下空 `<row>` 元素** ⇒ `dimension` 是对的（`A1:O4`）但 **Excel 的 `UsedRange` = `A1:O9`**
   （用户看到数据下面空着 5 行、也进打印范围）⇒ 填完必须清末行以下的行属性。
3. ⭐⭐ `verify_filled` **必须读两遍工作簿**：`data_only=True` 只给值、**看不到公式** ⇒ 只用它时
   「还有公式 / 值覆盖不彻底」那条**永远不会报**（= 死代码，比没有还坏）。
   ⇒ **通法：守卫里凡"读产物"的检查，先问一句"这个 API 真看得见它吗"**。

**守卫主动拦下的错（这条设计留着）**：尾块里**我方未覆盖**的格出现**公式或数字** ⇒ **拒绝产出**。
0 行的边界样本当场触发（尾块上移后，模板原第 9 行的 `=SUM(D2:D8)` 变成了 `D2`）。

**「结余」列 —— 用户裁定 = 历史结余、由用户手动录入**（我先前推测的 `end_amt` 快照**作废**、已从代码删掉）
