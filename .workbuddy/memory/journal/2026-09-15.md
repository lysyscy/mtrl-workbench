## 用户追问排查 —— 「原型列表合计不置底」实测结论（含一处原型漏网）

**问题**：用户观察到 demo 原型「所有列表的合计都不会置底了」，问真实开发会不会出现。

**实测方法**：写 node 探针（复刻 `demo/_smoke.js` 的 DOM 桩 + `vm.runInContext`），把**全部视图**渲染后过一遍 `applySorts`，逐张表检查合计行的**位置**与**类名**。探针用完即删（`artifacts/` 本就不入仓）。

**实测结论（区分两种「置底」—— 这是关键）**：
1. **数据序置底**（钉在表尾、不参与排序）：✅ **成立**。26 个「含合计表 × 模式」组合里，25 个合计行都在 tbody 连续后缀位置；点击排序后仍在末行（MOD-04 实测）。

2. **视口吸附置底**（长表滚动时合计行贴在容器底部）：靠 CSS `.dt tbody tr.sumrow>td{position:sticky;bottom:0}` + 容器 `.tw{overflow:auto;max-height:calc(100vh - 330px)}`。
   ⇒ **前提是合计行带 `class="sumrow"`**（由 `sumRowOf` 注入；分组表传 `sticky:false` 才不给）。

**顺带发现的语义坑（值得写进口径）**：`position:sticky` **不等于**「贴容器底」—— sticky 只在**会发生滚动时**才把它拦住；**表格比容器短**时，合计行仍跟在最后一行数据下面，容器底部会留白 ⇒ 视觉上**像"没置底"**。若要"恒贴容器底"需换布局（`tfoot`／flex 撑开），属**新口径**、原型与工程都没做。
