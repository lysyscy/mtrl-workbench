## 二、设计：`backend/app/import_kit/`（五个底座件）

```
导入 = read(文件) → map(表头) → validate(行) → stage(暂存) → commit(落库)
       └─readers     └─mapping    └─validators   └─staging    └─commit
```

| 件 | 职责 | 契约（⛔ 实施前先冻结） |
|---|---|---|
| **`readers.py`** | 读 xlsx/xls；**前 N 行自动找表头行**；多 sheet 按名/唯一性选；产出「表头 ＋ 行 dict」 | `read(file, sheet=None) → Headers{列名→列号}, Rows[list[dict]]` |
| **`mapping.py`** | ⭐ **表头映射**：**别名库**（中英/简称/带尾缀「（元）」——m06 已有一份雏形）自动猜；未命中留给用户改；可标「忽略」；**按「来源标识」记住上次映射**（第二次导入 ≈ 零操作） | `guess(headers, target_fields) → Mapping{源列→字段│IGNORE}` · `apply(rows, mapping) → dict 行` |
| **`validators.py`** | 金额/日期/必填/重复/未知值 —— ⭐ **解析失败保留原始值并报行号，绝不静默猜**（沿用 m08 解析器「金额非数字 ⇒ 报错并指出行号」的既有口径） | `check(rows, spec) → {clean, problems[{行, 列, 原值, 原因}]}` |
| **`staging.py`** | 「预览不写库」暂存 —— **就是现有的 `app/core/preview_store`**（⛔ 不做第二份；m05/m06 已在用） | `save(token, payload)` / `load(token)`（既有签名不变） |
| **`commit.py`** | 单事务落库：**幂等 upsert**（键由调用方给）＋ **手动行/调整单保护**（现「重抓不动调整单」同款）＋ 结果报告 `{inserted, updated, deleted, kept, skipped}` | `commit(session, rows, key_fields, guard=...) → Report` |

**解析器统一出口**：金额/日期解析收编到 `import_kit/parse.py`（`parse_amount` 4 份 / 日期多格式 2 份 → 各一份），**与 i8 抓取解析走同一套** —— 两条路结果必须一致（「导入与抓取同一口径」是本仓既有铁律，m08 的「同一条解析管线」判据是其原型）。

## 三、四步向导 · 壳侧形态

复用 `legacy.js` 既有的 `lgSteps / lgPick / lgNotice` 骨架（m05imp 已是这个形态）：

1. **① 上传解析**：选文件 → `parse` → 展示「找到的表头行 + 每列猜到哪」；
2. **② 表头映射**（⭐ 新增的一步）：表格「源列 → 目标字段 / 忽略」下拉，自动猜好的可改；**必填字段没映射 ⇒ 不能进下一步**（显式，不猜）；
3. **③ 预览校验**：数据预览 ＋ **行级问题清单**（行号 / 列 / 原值 / 原因）——用户可「修表重传」（校验前不碰库，重传零成本）；
4. **④ 确认落库**：单事务 ＋ 幂等 ＋ 结果报告；带批次/回滚的域（m05/m06）保留其回滚。

**映射记忆**：`mapping` 结果按「来源标识」（文件名模式或用户选的来源）存后端，下次自动预填 —— 仍是**显式的**（界面上展示当前映射，可改），不是静默猜。

## 四、三条硬约束（对齐用户引用的设计，落成本仓口径）

1. **⛔ 永不静默猜**：只有两条合法路径 —— 映射确认后落库，或校验清单里显式列出待人处理；解析失败**保留原值**显示，不悄悄置空/置 0。
2. **无效列原样保留**：未映射列 ≠ 报错丢弃；「刻意不采」的列要在预览里**列名可见**（m08 曾有 `ignored_headers` 的做法，收编为通用能力）。
3. **可中断可重来**：校验通过前**不碰数据库**（纯内存/暂存）；确认才单事务落库；配合幂等键，同一文件反复导不产生脏数据。

## 六、映射引擎 `import_kit/mapping.py`（本期新增）

```
源表头 → normalize(归一化) → profile(内容画像) → guess(打分·出建议) → 人确认 → apply(按映射取行)
                                                    ↑
                                      profile_store（记忆：表头指纹 → 映射）
```

| 件 | 职责 | 关键决定 |
|---|---|---|
| `normalize()` | 表头原文 → 比较键：去空白/换行、全半角统一、大小写折叠、**剥单位与括号**（`金额（元）`→`金额`）、去尾部「编号/名称/合计/小计」等**可配后缀词** | ⛔ 归一化**只用于比较**，展示永远是原文（用户看得到"系统按什么认的列"） |
| `profile()` | 逐列**内容画像**：试解析前 N 行 ⇒ `日期/金额/年月/枚举/编号/文本/空列` ＋ 空值率 | ⭐ 用来**交叉验证**：名字像日期、值却是文本 ⇒ 降置信并标「需你确认」（防"名字认对、列拿错"） |
| `guess()` | 四级命中：① 归一化相等 = 1.00；② **包含词**命中（m04 `_HINTS` 那类实拍长表头）= 0.90；③ token 交集/前缀 = 0.70~0.90；④ 类型画像吻合 = ＋0.05（不吻合 = −0.2） | 三档语义：**≥0.9 自动**（仍可改）· **0.7~0.9 预选但标"需确认"** · **<0.7 不预选**（⛔ 不猜，留空让人选） |
| `apply(rows, mapping)` | 按映射取行；未映射列 → `raw` 原样保留 | 与既有 `ParsedSheet.raw`（m04）同款 |
| `profile_store` | 记忆：**表头指纹**（归一化后表头序列的 sha1）→ 映射；**另存来源标识** | 命中 ⇒ 预填并标「来自记忆 · 可改」；指纹匹配率（Jaccard）**<0.6 就不用记忆**（表变了别拿旧映射硬套） |

**域声明（`SPEC`）留在域内**（⛔ 不塞进底座）：字段清单/必填/别名/幂等键/保护规则/是否有批次。
底座只做通用事 —— 与 `D22` 的"口径归机器守卫"同一条纪律。

- **别名不许用"表头长句里的片段"**：片段看着更"宽容"，实际是把**别人的列**吸过来；
- **"多认出一列"不等于更聪明**：认列数当择优函数时，**被数据污染的列**天然更容易"多认出一个"
  ⇒ 择优前必须先把"像数据的行"挡在门外；
- **同一件事两个主人必分叉**（本仓老坑的又一例）：`mod04_plan/importer.py` **自己那条路是对的**
  （它早就会判"续行"），而通用面那条路**判据弱一档** ⇒ 两条路结果不一致。⇒ 修在**通用层**，全仓受益。
- **判据要盯"落库值像不像那一列的东西"**：本次新判据（`test_plan_import_realfile.py`）
  直接断言"**收款单位（供应商名）绝不许落成单据号**"—— 比"表头行行号对不对"更贴用户的痛。
