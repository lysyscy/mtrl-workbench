## 三、改造契约（第一版 · 只管"表外壳"，行模板仍留在页内）

```js
/* ⭐ **表格件**（`TAIL-64` · 2026-09-24）—— 一张表的**外壳**统一由它渲染：表头 / 行 / 空态 / 合计。
   ⭐ 抽它的真理由 = **虚拟滚动只需要挂一处**（本件内），以及「表该怎么开」只有一个口径。
   契约：`TBL({head, rows, empty, sum, key})` ⇒ 返回完整 `<table …>…</table>`（⚠️ 不含外层 `.tw`）。
   ⛔ 与 `sumRowOf` / `thCount` 的分工：那两个是**纯算法**，本件只管**拼装**（别把求和挪进来）。 */
const TBL=({head='',rows=[],empty='',sum='',key=''})=>{
  const cls=key?' class="dt" data-sort data-sort-key="'+key+'"':' class="dt"';
  return '<table'+cls+'><thead><tr>'+head+'</tr></thead><tbody>'
    +rows.join('')+(rows.length?'':empty)+sum+'</tbody></table>';
};
```

⭐ **为什么第一期只做外壳**：行模板（`rows` 里的每一段）各页差异大，**先统一外壳**＝把 `data-sort` / `class` / 空态 `colspan` / 合计位这四件"每页都写一遍"的东西收进来，收益已经落到"虚拟滚动挂一处"；行模板的进一步配置化（列定义数组驱动）留第二期，那时 `TBL` 的签名从 `rows:html[]` 换成 `cols:[{t,r,s}]`。

## 五、四个必踩的坑

1. ⭐ **每张表先选路（同步 or 登记）** —— 判据 = **该页有没有被 `_smoke.js` 的业务断言覆盖**：
   · **有断言覆盖**（`_smoke.js` 里出现 `V.mNN()` 或该页的表头常量）：**双边同步改**（照 P0 / P1a 的做法），
     让那批断言继续跟着壳走；
   · **纯展示 / 无断言**（静态说明表、配置表）：**只改壳 ＋ 登记偏离**（`ui_parity_expected.txt` 加一行、写理由）
     ⇒ 省一半工作量。
   ⛔ **不许两处都不做** —— 改了壳既不同步也不登记 = 未登记漂移，`U1` 当场红。
   ⚠️ **`V.*` 里插/删行会让其后所有行算漂移**（`core.js` 头部记着：当年在 `V.m01` 插一行 ⇒ 冒出 **66 条**）
     ⇒ 同步那条路要**同一次改完两侧**。
   ⭐⭐ **2026-09-29 实测出一条更省的做法（`P2③ m07`）**：`U1` 是**按行号对位**比的 ⇒ 只要**两侧在同一个位点改掉同样的行数**
     （一起插 / 一起删 / 一起改写），其后的行**一起平移** ⇒ 那些行配对的**仍是原来那一对**、指纹不变 ⇒
     **已有登记一条都不必动**（本片三张表改了 6 处、只新增 5 条登记 ＋ 消号 3 条幽灵）。
     ⚠️ 反之——**只在一侧加减行**——才会**级联**成几十条漂移（`P2①`/`P2②` 两片就是那么踩的）。
   ⚠️ 一次改**多处**时，⛔ **别用「替换第一处」的脚本**：2026-09-24 实测踩过 —— `V.m10` 与 `V.m14` 都有
     `bd np` ＋ `table class="dt cond"` ⇒ 脚本命中了排在前面的 **`V.m10`**（把它改成半成品，
     `_smoke` 报 `Unexpected token '<'`），而真正的目标 `V.m14` 反而没改到。
     ⇒ 脚本的 `old` 必须**带足定位上下文**（或限定在目标切片范围内）。
   ⚠️ 改完必跑 `doc_audit --ui`：**原型侧的语法错 `syntax_audit` 的 `Q2` 查不出来**（它只查壳），
     只有 `_smoke` 能兜住。
2. ⛔ **交付面 = WPS 云同步树** ⇒ 备份/中间产物⛔ 别落交付面，一律落仓库侧；只改既有文件的既有内容。
3. ⚠️ **新件没人调用会红 `W1`**（`wiring_audit`：口径性函数零调用方 ⇒ 铁定死代码）⇒ **件和调用方必须同一批落地**。
4. ⚠️ 改原型后必跑 `doc_audit --ui`（交付面四检）—— 它是唯一能发现「壳里加了动作/原型没同步」的尺子（`U1` 查不出 `ACT`/`CHG` 顶层 const）。
5. ⭐⭐ **抽通用件会让「钉源码形态」的判据假红** —— 判据必须**结构无关**（P0 实测：2026-09-24）。
   表外壳抽进 `TBL` 后，`ACC-FEE-MON-001/001-01` 当场红：它钉的是
   「切片里必须有 `data-sort-key="m09:awf"` 字面」，而那串**搬进 `TBL` 之后切片里就没有了**。
   同函数另一条钉 `${list.length?list.map(` 的也红（进了 `rows` 数组后 `${` 没了）。
   ⇒ 正确钉法（照 `dlExport` 那次的既有范式）：**切片委托该件** ＋ **件的内核里真做了那件事**，
   用 `tests/shell_src.py` 的 `*_kernel()` 把两段拼起来看；每条被改的判据都要补
   **反向灵敏度**（去掉内核那段 / 去掉委托 ⇒ 必须红）。
   ⛔ 反例（会让 `TAIL-64` 做不下去）：为省事把判据改回钉字面 ⇒ 等于宣布**以后不许抽通用件**。
6. ⛔⚠️ **壳与原型"同源不同形"：同一个 `rows.map(...)` 在两侧可能是「语句体」与「表达式体」两种箭头**（`P2④ m05` 实测踩到）——
   壳：`${rows.map((r,i)=>{ const z=…; return \`<tr>…\`;}).join('')}`（**语句体** ⇒ 换 `TBL` 后闭合写 `` `;}) ``）；
   原型：`${rows.map((r,i)=>\`<tr>…\`).join('')}`（**表达式体** ⇒ 闭合只写 `` `) ``，**多一个 `}` 就报错**）。
   ⇒ 照抄壳那一套写进原型 ⇒ `_smoke` 报 **`missing ) after argument list`**（整支 `rc=1`）。
   ⭐ 为什么危险：`syntax_audit` 的 `Q2` **只查壳**（`node --check` 壳的内联脚本）⇒ **原型侧的语法错它看不见**
   ⇒ **改完原型必跑 `doc_audit --ui`**（`_smoke` 是唯一兜得住原型语法的尺子）。

### 7.6 ⭐ P5-a 的**函数级**施工步骤（2026-09-30 读完机制后落下 · 接缝是干净的）
