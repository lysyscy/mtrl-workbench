## 2. 整体程序结构

### 2.1 运行时拓扑

```
  科室 2 人 · 浏览器（仅 Chrome/Edge 新版）
                 │  内网 HTTP（OPEN-T6：不上 HTTPS）
                 ▼
   ┌──────────────────────────────────────────────┐
   │ 后端单进程（uvicorn，单 worker）              │
   │  · FastAPI 应用（MOD-01…MOD-15）             │
   │  · ★ 无调度器：抓取一律纯手动（D9）           │
   │  · ★ 前端 = 原型壳（原生 JS · 同进程静态托管）      │
   │  ⚠️ 单 worker：进程内共享连接池与缓存，      │
   │    避免多进程重复接管（无定时任务）            │
   └───┬──────────────┬───────────────┬───────────┘
       │              │               │
       ▼              ▼               ▼
  PostgreSQL 16    i8（纯 HTTP）   打印机（IPP 直投）
  同机服务         登录态 Cookie     本地渲染 PDF 后投递
  行锁 / numeric   失效自动重登
```

**关键形态约束**：
- ★ **前端 = `demo/` 原型本体接数据**（§9 D18）：壳 = `backend/app/web/index.html`（原型**整体复制**），**只换数据源**；原型的筛选 / 排序 / 合计 / 勾选逻辑**一行不改**；判定与落库**一律走后端**（复用同一批纯函数）。
- ★ **无定时任务、无后台调度** —— 抓取一律由**人在页面上点击**触发（D9）。⇒ 服务内**不存在自动顶号**的可能，i8 登录只在"人主动点抓取"这一刻发生。
- ⚠️ **但手动抓取仍会顶号**（i8 登录含 KillOnlineUser 强踢）⇒ 界面必须在抓取前给出**明确提示与二次确认**（"此操作会挤掉该账号的其他在线会话"），且**抓取失败/超时不得自动重试登录**（重试会再次顶号）→ 见 §6.5。
- **抓取一律走纯 HTTP**（登录态会话，不起浏览器）；服务运行在 **Session 0** ⇒ 打印渲染也要在会话 0 内成立 → 见 **§8 风险 R1**。
- **长任务短占用**：抓取/打印**先取完数据、关掉写事务再做渲染与投递**（不持写事务）。

## 4. 开发流程（每片都照此循环）

```
写代码 → 立即验证（lint / 启动 / pytest / 冒烟）→ 一句话汇报
         ↑                                                    │
         └──────── 本片收尾：跑四态报表 → 汇报「本轮改了什么 + 四态数字 + 下一步」
```

| 纪律 | 内容 |
|---|---|
| **验收先行** | 每片先建断言（哪怕先「待建」态），再写实现；**不许"先实现完再补测试"** |
| **绑定成对** | 每个测试声明「**用例号 + 判据点号**」；**只挂用例号不给过** |
| **小步汇报** | 每完成一个可验证单元就报一行；不堆未验证代码 |
| **变更控制** | 单次修复范围限**单模块/单文件**；改共享函数须验证**所有调用方** |
| **合入门禁** | 自动化测试**全绿才能合入**；金额计算函数首行标注「已人工验证边界」 |
| **不越界** | 发现新问题 → **先报、不动手**；口径空白 → **标待确认回问** |

### 6.9 本机环境坑（换机需复核）

| 坑 | 应对 |
|---|---|
| Bash 缺 coreutils | 前置 `export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Program Files/nodejs:$PATH"` |
| **给 Windows 程序传路径必须用反斜杠** | Bash 只负责 `cd` 与重定向；路径写成 `D:\工作\...` |
| ⚠️ **空输出 ≠ 绿灯** | 该有输出却空白时，**先看输出文件是否报错**再下结论 |
| **`sc.exe` / `cmd.exe` 在安全策略黑名单** | 服务操作一律用 **PowerShell cmdlet**（`Get-Service` / `Stop-Service` / `Set-Service` / `Get-CimInstance Win32_Service` / `Get-NetTCPConnection`）；⚠️ 被拦时整块 stdout 为空但**其中 cmdlet 可能已生效** ⇒ **必须事后复查真实状态** |
| PowerShell 不回显 stdout | 结果**落盘再 Read**；写盘用 `[IO.File]::WriteAllText(..., UTF8Encoding($false))` |
| **pip 配置 / `alembic.ini` 须纯 ASCII** | 中文注释会让 Windows 以 cp936 读取时**整份配置失效** |
| 依赖源 ★ | **D10 已定案：走国内镜像**（清华 TUNA / 阿里云 PyPI）。⚠️ 配套**三条加固**（否则失去可追溯性）：① venv 级 `pip.ini` 把 index **钉死到选定镜像**（不配置多源回退，避免来源漂移）② `requirements.txt` **全部 `==` 精确锁版本** + 生成 `requirements.lock`（含哈希）③ **新增依赖前跑 `pip-audit`** 并产出依赖审计报告入库（补回底线「依赖来源」要的可追溯性） | 用户拍板 2026-09-15（**覆盖**工程底线「只来自 PyPI 官方源」）；加固依据 = 底线·依赖 |
| 文件删除 hook | 多路径单次删除会整体失败 → **逐项删除** |

## 7. 验收标准

### 7.1 机制（`PRD/验收/README.md` §三）

| 环节 | 契约 |
|---|---|
| 绑定 | 每测试**成对**声明「用例号 + 判据点号」—— 一条判据点 ↔ 一个测试 |
| **四态** | **绿**（跑过且通过）· **红**（跑过且失败）· **待建**（判据已定、断言未建）· **未绑定**（既没跑过、也没登记待建） |

| 先判壳 | 命中行里**只要有壳** ⇒ 这条仓库即认定为**具体小微** ⇒ **走新建小微行**（`parent_shell_id`＝壳），**不进 ≥2 分支** |

### 17.3 四种处置（`≥2` 就是本节要补的那一种）

| 命中情况 | 系统怎么做 | 现状 |
|---|---|---|
| 恰好 **1 条**且是**占位行** | **扶正**：`未建仓-N` → 真实仓库名（`promote_placeholder`，**系统写入**） | 已接 |
| **≥2 条**（非壳行同名） | ⚠️ **报出来、要人指认** | ⛔ **只报不选** ← **本节要补的入口** |
| **0 条** | 未建档 ⇒ 报出来（提示先跑「同步常用项目列表」） | 已接（报出来） |
| 1 条但**已有真实仓库名**且 ≠ 本次 | 异常 ⇒ 报出来（决策 2：普通项目 ↔ 仓库 **1 : 1**） | 已接（报出来） |
| 仓库名单里查不到该仓库名 | 报出来（名单可能没更新 / 仓库已作废，**不臆造**） | 已接（报出来） |

### 17.4 「指认入口」是什么

**定义**：针对 17.3 表第 2 行（全名命中 **≥2 条非壳档案行**）给用户的**人工指定**入口 ——
让他指明「这条陌生仓库，该写到**哪一行**上」。

**为什么会 ≥2**：这类全名**本该是壳**（小微一对多），但名字里没带「小微」⇒ 建档时三类判定判成了
**普通项目** ⇒ **同名的多条普通项目行并存**（决策 1 的兜底情形）。系统**无法自己决定**挂哪条、
也**不该猜** ⇒ 交给人。

**现状：只报不选**（已核代码）：

- `plan_recovery` 把它放进 `unresolved`（原因原文：*同一全名命中 N 条非壳档案 —— 疑似名字没带「小微」的壳，
  需人工确认类型*）；`summary_text()` 逐条写进**抓取回执**；
- ⚠️ **它不阻塞入库** —— 链路 B 是在数据**已经入库之后**补档案，失败只降级（原因文字里就写着
  「本次数据已照常入库」）。**这与付款侧链路 C 的门禁（一行卡住 ⇒ 整批不入库）完全不同**；
- ⚠️ **现状缺口（本轮一并补）**：服务端渲染路径（`m07/router.py`）有 `summary_text`，
  但**壳侧抓取**（`app/web/index.html::whFetchBackend`）**只报条数**，回包的 `recovery`
  **根本没露出来** ⇒ 站在壳上抓收发结存，**看不到「待人工 N 条」**。所以入口不是「加个按钮」，
  得先把这句话露出来。

**落点与形态（已确认）**：

| 项 | 定案 |
|---|---|
| 入口落点 | **`m01` 项目档案页**（`m01` 已接线）—— 扶正本来就是该页的行内动作（原型里 `未建仓-` 行的「扶正」按钮就在那一列），候选的几条档案行也在同一页看得见 |
| 顺带补 | 材料侧抓取回执（`m07`/`m08`）补一句「**待人工 N 条，去 `m01` 处理**」把上面那个缺口堵上 |
| 原型对照 | ⚠️ 原型 `promote` 弹窗画的是**选「真实仓库名」**（已知是哪个占位行，缺的是仓库名）= **「命中 1 条」**的形态；而 ≥2 条要选的是**「哪条档案行」**（已知仓库名，缺的是挂哪行）⇒ **原型里没有精确对应物** |
| 形态做法 | **照原型的「样子」**（同一个信息块 ＋ 一个下拉 ＋ 取消/确认两键），**只把下拉的语义从「仓库名」换成「档案行」** ⇒ `chain_audit` 里那条标 **`形态不同`** 的才转正 |

**后端（待做）**：① 「候选清单」端点 —— 该全名下的档案行（`id` / 类型 / 仓库名 / 展示名 / 状态 / `phid`，
并标出哪几行是**占位行**）；② 「指定扶正」端点 —— 把这条真实仓库名写到用户指定的那一行；
⚠️ 占位行 ⇒ 走**系统扶正出口** `promote_placeholder`；非占位行 ⇒ **明确报错拒改仓库名**（§2.3.1 / §9.4）。
