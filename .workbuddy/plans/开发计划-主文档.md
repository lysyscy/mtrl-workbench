## 2. 整体程序结构

### 2.1 运行时拓扑

```
  科室 2 人 · 浏览器（仅 Chrome/Edge 新版）
                 │  内网 HTTP（OPEN-T6：不上 HTTPS）
                 ▼
   ┌──────────────────────────────────────────────┐
   │ 后端单进程（uvicorn，单 worker）              │
   │  · FastAPI 应用（MOD-01…MOD-15）             │
   │  · ★ 无调度器：抓取一律纯手动（D9）           │
   │  · ★ 前端 = 原型壳（原生 JS · 同进程静态托管）      │
   │  ⚠️ 单 worker：进程内共享连接池与缓存，      │
   │    避免多进程重复接管（无定时任务）            │
   └───┬──────────────┬───────────────┬───────────┘
       │              │               │
       ▼              ▼               ▼
  PostgreSQL 16    i8（纯 HTTP）   打印机（IPP 直投）
  同机服务         登录态 Cookie     本地渲染 PDF 后投递
  行锁 / numeric   失效自动重登
```

**关键形态约束**：
- ★ **前端 = `demo/` 原型本体接数据**（§9 D18）：壳 = `backend/app/web/index.html`（原型**整体复制**），**只换数据源**；原型的筛选 / 排序 / 合计 / 勾选逻辑**一行不改**；判定与落库**一律走后端**（复用同一批纯函数）。
- ★ **无定时任务、无后台调度** —— 抓取一律由**人在页面上点击**触发（D9）。⇒ 服务内**不存在自动顶号**的可能，i8 登录只在"人主动点抓取"这一刻发生。
- ⚠️ **但手动抓取仍会顶号**（i8 登录含 KillOnlineUser 强踢）⇒ 界面必须在抓取前给出**明确提示与二次确认**（"此操作会挤掉该账号的其他在线会话"），且**抓取失败/超时不得自动重试登录**（重试会再次顶号）→ 见 §6.5。
- **抓取一律走纯 HTTP**（登录态会话，不起浏览器）；服务运行在 **Session 0** ⇒ 打印渲染也要在会话 0 内成立 → 见 **§8 风险 R1**。
- **长任务短占用**：抓取/打印**先取完数据、关掉写事务再做渲染与投递**（不持写事务）。

## 4. 开发流程（每片都照此循环）

```
写代码 → 立即验证（lint / 启动 / pytest / 冒烟）→ 一句话汇报
         ↑                                                    │
         └──────── 本片收尾：跑四态报表 → 汇报「本轮改了什么 + 四态数字 + 下一步」
```

| 纪律 | 内容 |
|---|---|
| **验收先行** | 每片先建断言（哪怕先「待建」态），再写实现；**不许"先实现完再补测试"** |
| **绑定成对** | 每个测试声明「**用例号 + 判据点号**」；**只挂用例号不给过** |
| **小步汇报** | 每完成一个可验证单元就报一行；不堆未验证代码 |
| **变更控制** | 单次修复范围限**单模块/单文件**；改共享函数须验证**所有调用方** |
| **合入门禁** | 自动化测试**全绿才能合入**；金额计算函数首行标注「已人工验证边界」 |
| **不越界** | 发现新问题 → **先报、不动手**；口径空白 → **标待确认回问** |

### 6.10 本机环境坑（换机需复核）

| 坑 | 应对 |
|---|---|
| Bash 缺 coreutils | 前置 `export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Program Files/nodejs:$PATH"` |
| **给 Windows 程序传路径必须用反斜杠** | Bash 只负责 `cd` 与重定向；路径写成 `D:\工作\...` |
| ⚠️ **空输出 ≠ 绿灯** | 该有输出却空白时，**先看输出文件是否报错**再下结论 |
| ⚠️⚠️ **临时脚本一律写 `.workbuddy\work\00-scratch\`，⛔ 别写 `%TEMP%`** | `%TEMP%`（`C:\Users\…\AppData\Local\Temp`）**在工作区之外** ⇒ 每条读写它的命令都**必须走审批**，而审批弹窗**常常没弹出来就超时** ⇒ 命令被取消、脚本却已经落在盘上（**留下清不掉的垃圾**）。2026-09-20 实测连踩两次。<br>⇒ 应对：① 脚本写 **`.workbuddy/work/00-scratch/`**（在工作区内 ⇒ **免审批**；已进 `.gitignore` ⇒ `git status` 干净；⚠️ 旧落点 `.workbuddy/scratch/` **已废**、别再往里写）；② 清理用**编辑器 Delete**（或文件删除工具），⛔ **不要**用 shell 的 `Remove-Item "%TEMP%\…"`（会再触发一次审批）。 |
| ⚠️ **审批超时 ≠ 用户拒绝** | 提示是 `Permission request timed out with no user response` ⇒ **别当成"被否决"**，也别重试同一条命令；先想**是不是路径出了工作区**，换个免审批的写法。 |
| **`sc.exe` / `cmd.exe` 在安全策略黑名单** | 服务操作一律用 **PowerShell cmdlet**（`Get-Service` / `Stop-Service` / `Set-Service` / `Get-CimInstance Win32_Service` / `Get-NetTCPConnection`）；⚠️ 被拦时整块 stdout 为空但**其中 cmdlet 可能已生效** ⇒ **必须事后复查真实状态** |

| **pip 配置 / `alembic.ini` 须纯 ASCII** | 中文注释会让 Windows 以 cp936 读取时**整份配置失效** |
| 依赖源 ★ | **D10 已定案：走国内镜像**（清华 TUNA / 阿里云 PyPI）。⚠️ 配套**三条加固**（否则失去可追溯性）：① venv 级 `pip.ini` 把 index **钉死到选定镜像**（不配置多源回退，避免来源漂移）② `requirements.txt` **全部 `==` 精确锁版本** + 生成 `requirements.lock`（含哈希）③ **新增依赖前跑 `pip-audit`** 并产出依赖审计报告入库（补回底线「依赖来源」要的可追溯性） | 用户拍板 2026-09-15（**覆盖**工程底线「只来自 PyPI 官方源」· 见 §9.0）；加固依据 = 底线·依赖 |

## 16. `TAIL-40` 口径：**剔除规则落库** ＋ `m14` 规则配置（✅ **已实施 · 2026-09-18 销号**）

> **性质**：**零契约改动** —— 不动《说明书》§4.2.2 的取值表、不动判定规则，只把「**规则从哪读**」由
> **模块常量**换成「**库 ＋ 出厂默认**」，并给配置页补上**真增删改**。
> ⚠️ **实施流水**（逐轮的验证数字、真机记录、两处 `U1` 漂移怎么处理）**已下沉归档件**（见 §16.4 末），
> 本节只留**长期有效的口径**。

### 16.1 为什么要有它

剔除规则原先**硬编码**在 `classify.py` 的 `DEFAULT_RULES`（业务类型 5 项 / 付款项目名 2 项 / 单据名称关键字 / 录入人 1 项）
⇒ **与决策 1「规则必须可配置、不硬编码」相悖**：改一条规则就得改代码、重新发布。

### 16.2 设计（5 条 · 长期有效）

1. **规则来源 = 「库 → 出厂默认」**：库里有 ⇒ **以库为准**；**库空 ⇒ 回落 `DEFAULT_RULES`（＝ §4.2.2 那张表）**
   ⇒ 首装行为即符合 §4.2.2，不必人工录一遍（与 `core/app_settings` 的「库 → `.env`」同款思想）。
   ⛔ **备选（库空 = 不剔任何东西）不采用** —— 那会让首装行为**悄悄偏离口径**。
2. **一条规则 = 一行**：`kind` ＋ `values`（`｜` 分隔的**原文**）＋ `meaning`（业务含义，**纯展示、不参与判定**）＋ `ord`
   —— 与 §4.2.2 表形态、原型行形态同构；**同一 `kind` 允许多行**，判定按 `kind` **合并命中值**。
   ⚠️ 写入一律规整成**全角 `｜`**；**解析时半角 `|` 也认**（手输常见）—— 认不出分隔符会让整条规则**静默不命中**。
3. **判定出口一个字不改**：仍是 `classify.match_exclude_rule`（规则由 loader 注入，默认真实实现读库）；
   ⛔ **不得在编排层另写一份剔除判定**（本仓老纪律：同一件事不许实现两遍）。
4. **改规则 ≠ 重算历史**：已产生的剔除标记（`exclude_source=rule`）**不受影响、也不重算**
   ⇒ 写侧**不触发任何重算**；页面与回执**必须讲清这一句**。
5. **模块归属**：**表与仓储放付款域**（`mod03_notice`）—— §4.2.2 原文即「剔除规则本身属付款域」，
   而抓取管线（付款域）要用它、配置**页**在 `MOD-14` ⇒ 依赖**单向** `mod14_config → mod03_notice`，**不成环**。
   ⚠️ **这条实施时改判过**：原设计写「放 `mod14_config`」，但那样 `mod03` 要读它、`mod14` 又要读 `mod03` 的规则值对象
   ⇒ **循环 import**。落地形态 = `backend/app/mod03_notice/rules_repository.py` ＋ `backend/app/mod14_config/rules_api.py`。
