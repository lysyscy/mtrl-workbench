## Problem Statement

材料工作台已经在日常使用。现有原生前端依靠共享状态、HTML 字符串生成、手工绑定和重画后的恢复机制承载复杂业务；连续编辑、草稿、切项目后的异步结果、滚动和跨页刷新需要较多专门维护。

使用者需要继续使用现有系统，同时获得一套更容易维护、能够稳定承接现行业务的前端。重做必须保护已确认的金额、权限、保存、撤销、导出及来源保护语义，并避免把新界面做完后才发现无法与实际后端配合。

本次目标是降低前端后续修改和回归的成本，并适合主要依靠 AI 持续开发维护的方式。标准 TSX 与直接类型检查是技术选择的考虑因素，实际维护收益仍需在本项目验证；编译速度、代码行数减少或框架更新本身不作为完成判据。

## Solution

以用户于 2026-10-22 改选的 React + TypeScript 7 + Vite 方向，独立建设新前端；旧前端继续正常使用。新前端从首个完整业务页面起连接隔离后端与专用测试数据库，持续验证读取、操作、保存、重新取数和导出，逐批覆盖现行范围。

保持现行业务和已认可的视觉基线，完成代表性页面验证、全范围迁移、整体验收和可回退的发布准备后，才安排正式入口切换。正式切换后仍需核对运行资源并做现场检查；经过日常使用确认后再退出旧前端。规格确认、开发、隔离验证、正式切换和旧版退役分别记录。

## User Stories

1. 作为日常使用者，我希望新前端开发期间旧系统照常可用，以便正常办理业务。
2. 作为维护者，我希望新前端的代码、依赖、预览和构建与正式运行资源隔离，以便开发不影响正在打开的页面。
3. 作为验收者，我希望从独立预览入口检查新前端，以便区分试用页面与正式系统。
4. 作为使用者，我希望保留现行页面职责和入口，以便沿用熟悉的业务操作路径。

## Implementation Decisions

### 已确认方向与本草案提出的实现边界

1. **技术方向已确认：React + TypeScript 7 + Vite。** 使用函数组件、标准 TSX 与 ES Modules 组织页面。业务判定、权限、金额、事务及操作历史继续由现有后端承担。
2. **React 版本基线：19.3.1，React DOM 同为 19.3.1。** 官方将 19.3.1 标为当前 Latest 稳定发布，官方包声明确认两个包同版。采用浏览器客户端应用，不以 Next.js、React Server Components 或 React Compiler 为开工前提。该基线已随主体规格确认；当前只核对了官方发布资料，尚未做安装、构建或项目兼容验证。
3. **TypeScript 版本基线：7.0.2。** 官方 npm 注册表的 latest 元数据返回 7.0.2；以该稳定版承担 TS/TSX 严格类型检查。该基线已随主体规格确认。Vite、React 插件、React 类型声明及其他工具的具体版本在首批工程中验证，再将依赖声明与锁文件一起固定。React 类型声明版本独立于运行时补丁版本，不能机械套用 19.3.1。类型检查与构建分别执行，构建成功不能代替类型检查。
4. **工具链适配与后续升级。** React 的标准 TSX 由 TypeScript 直接检查，不需要单文件模板专用检查器。依赖旧 TypeScript 编译器 API 的工具仍可能需要官方 TS6 兼容包；仅在真实工具缺口出现时按官方方案隔离其依赖，主类型检查保持 TS7，不因此把主线退回 TS6。当前不依赖 TS 7.1 Beta、Canary 或编译器内部补丁；使用标准模块、严格类型检查，清除弃用配置，为后续升级减少阻力，不承诺无改动升级或固定升级日期。
5. **独立开发、旧版持续使用。** 实施获准后使用同一 Git 仓库的独立分支和独立 worktree，由 Codex 管理工作副本并在创建后报告实际绝对路径；不另建独立 Git 项目，也不在正式运行目录切分支开发。新前端在该副本中的仓内长期位置为 `apps/frontend/`，组件内部按 `src/`、`tests/` 分工，依赖声明和锁文件位于组件根；构建输出留组件自己的 `dist/` 并忽略 Git，发布时再按已验证流程交付。现有后端路径保持。源码、依赖环境、构建目标和预览服务不得覆盖正式在用文件。此项针对本次新任务，不改变其他在途任务的隔离或串行约定。
6. **隔离联调从首批开始。** 预览连接真实后端实现的隔离实例与专用测试数据库；所有写入验证先确认实际连接目标及清理所有权。另一进程的写入不能依赖测试进程的回滚夹具保护。测试环境使用测试身份、构造数据或经授权的来源副本；凭据及真实业务数据不进入源码、浏览器夹具或公开证据。
7. **正式外部动作独立控制。** i8 登录/抓取、真实打印投递、生产导入和业务写入按当次明确授权执行；隔离验收用固定响应、样本和可检查的投递替代边界。查询库内数据与触发外部抓取必须区分，不因使用请求库引入自动登录、抓取或失败后重试外部动作。
8. **现行接口优先复用。** 首批核对页面依赖与后端返回；需要响应类型、兼容字段或资源出口调整时，以保持旧客户端兼容为前提，保留服务端校验与错误语义。接口 JSON 形态、金额文本及缺失/空/零的含义逐字段核对；类型声明不能代替运行时校验。前端重做不预设数据库结构迁移。
9. **视觉基线延续。** 保留已认可的字体、主题变量、颜色和页面职责；优先将现有布局表达迁入组件。不得把重写当成重新设计全部页面的授权；需要改变熟悉的流程、业务入口或整页风格时，先给可运行的只读样例确认。Excel 字体、模板与打印版式不随网页技术迁移调整。
10. **界面组件与数据所有权明确。** 页面持有筛选和编辑上下文；草稿以账号、项目、月份和记录身份区分。组件身份及行 key 稳定，遵守 Hooks 规则；避免组件重建、过期闭包或 Effect 更新覆盖后续输入。写动作由明确事件触发，组件挂载与开发检查不触发重复保存、付款或外部动作。保存返回后只更新它所属的记录与上下文，不覆盖后续输入；离开、撤销或丢弃草稿沿现行行为处理，不新增自动保存或自动丢弃规则。
11. **服务端数据管理建议采用 TanStack React Query。** 由一个出口统一请求、错误、查询身份、写后失效与操作历史刷新，避免再复制一套服务器数据。账号/项目/月度等影响结果的条件进入查询身份；退出账号清理对应数据。写后按现有全站新鲜度语义使数据失效并重取，不先缩窄为未经验证的依赖清单。窗口聚焦等后台刷新须避开活动编辑；外部操作不用普通查询默认重试。该库尚未安装，需随首批实际验证。
12. **共享客户端状态按需建立。** 默认使用组件状态、reducer 及必要的 Context 维护编辑状态；只有出现剩余的真实跨页客户端状态需要时才评估额外状态库，不把导航、查询缓存和草稿分别重复存储。
13. **表格组件尚未定案。** 首批以历史台账连续编辑和复杂报表验证成熟表格的适配。AG Grid Community 的 React 适配为首选候选；若存在必须手工维护的大量补丁，再评估 TanStack Table + TanStack Virtual 等 React 可用方案。后者需要另外组织编辑与虚拟滚动，不能假定更省维护。按现行编辑、冻结、合计、动态行高、虚拟化、中文输入、键盘、主题及可访问行为作决定，不并行建设两套通用网格。
14. **表格功能与许可逐项核对。** AG Grid 企业版的范围选择、增强剪贴板等不当作基础版能力；本规格不授权采购。需要额外许可或改变操作体验时，先提交具体缺口、替代方案与影响。特殊报表可继续用语义 HTML 表格表达合并布局；不要求所有表套同一数据网格，也不承诺网页具备 Excel 原生体验。
15. **通用控件与导航建议。** 路由采用 React Router；弹窗、选择器等在首批按实际缺口评估 React 可用组件，并接入既有主题和键盘规则。具体组件库与依赖版本随首批组合验证固定，不为采用控件替换所有布局或额外建立通用界面框架。
16. **保持写入与回执语义。** 写入须回后端真实状态；保存成功但后续读取失败与服务端拒绝必须分开。保留现有幂等号、记录版本/冲突凭据、权限和操作历史接线；不使用本地乐观金额替代已经保存的事实。前端编辑草稿撤销与服务器业务撤销清楚区分。
17. **分阶段交付完整业务能力。** 先验证公共骨架与历史台账读写，再验证机械费/复杂报表，随后迁移付款及其关联与其余模块。每阶段完成可操作、可保存、可复读、可拒绝、可导出的实际路径；不先做完所有静态页面再联调。具体任务与已批准依赖见本文Further Notes中的票索引；本轮建票不授权实施。
18. **旧版变化持续核对。** 保留固定调查基点，按后续版本差异吸收旧版修复和业务决定；逐阶段核迁移面。以业务需求和现行裁定判定预期，旧版缺陷不作为需要忠实复刻的效果。既有暂缓票仍按原状态管理，本规格不自动销号或重开其他治理事项。
19. **生产交付仍为静态前端 + 既有后端。** 新增 Node 构建链只用于开发与构建，不增设生产 Node 常驻服务。登录与 Cookie、资源版本、路由刷新、下载、主题及缓存需要在 FastAPI 提供实际构建产物的环境中验证；正式部署资源落点及 URL 留到发布接线时核定，本轮只补充源码目录建议，不修改现有入口。
20. **发布与回退保持数据兼容。** 验收通过后准备完整、版本一致的构建产物，验证切换与回退；避免逐文件覆盖产生新旧资源混用。正式切换按后续明确授权安排，核对旧页面/未保存编辑的处理，再核实际运行资源和关键路径。前端回退恢复资源和入口，不恢复数据库以覆盖切换后的正常业务写入。
21. **旧版退出有边界。** 在新前端完成约定日常使用及现场检查后，才按当时批准的清单退出旧实现、预览服务、重复依赖与临时样例；已接受的决定和必要证据进入现行资料或历史记录，旧版本由 Git 保留，不长期维护未使用的备用前端。
22. **前端依赖管理采用 pnpm 12.14.0。** 官方 npm latest 元数据本次返回该稳定版本。在前端组件的 `package.json` 用 `packageManager` 精确固定 pnpm，提交 `pnpm-lock.yaml`，复现安装使用 `pnpm install --frozen-lockfile`；不用 npm/Yarn/Bun 另生成并行锁文件。各 worktree 分别维护自己的依赖链接和构建环境，可共用 pnpm 内容寻址 store，不共享可变的 `node_modules` 目录。当前只有一个前端包，先按单包管理，不为此引入额外的全仓构建编排平台；pnpm 需要的配置按该版本要求设置。后端继续使用 uv 及既有 Python 锁文件，不迁入 pnpm。当前 Node 实测为 24.21.0；pnpm 仅发现宿主命令入口，未执行安装或版本切换，pnpm 与 Vite/插件的组合仍需在获准后的首批工程中验证。

## Testing Decisions

### 验收入口（已获用户确认）

| 入口 | 验证对象 | 能证明什么 | 不能替代什么 |
|---|---|---|---|
| 浏览器操作 | 可见页面、表单、选择、草稿、焦点、切换和回执 | 用户实际能完成目标动作及相应异常处理 | 模拟接口不能证明后端写入、权限和真实事务 |
| 后端接口与隔离数据库 | 真实后端入口、保存、金额、权限、撤销、重新读取 | 请求落到正确对象，后端状态与回执一致，失败不产生部分写入 | 不证明真实 i8 登录、实体打印或正式环境运行 |
| 导出文件与实际构建产物 | 实际下载文件、生产构建、FastAPI 提供的资源与入口 | 文件内容/范围正确，构建产物能够按生产方式使用 | 不证明纸面打印效果、新机部署或未经授权的生产动作 |

优先通过上述现有外部入口验证，不为框架切换建立额外通用测试接口。少量难以从浏览器清楚定位的纯逻辑与组件交互可用 Vitest 定向覆盖；测试关注行为结果，不要求特定变量名、DOM 拼接方式或组件内部组织。

### 必须保留的保障

- **连续编辑：** 保存前一格时继续输入下一格、Tab/鼠标切格、中文输入法合成、月份排序变化与按钮点击，焦点、草稿和目标行保持正确。
- **异步归属：** 切项目/月度后旧读响应、旧保存响应和旧错误均不覆盖当前范围；保存仍处理其原记录。退出账号后不发布旧账号结果。
- **保存结果：** 保存成功与保存后刷新失败区分；服务端拒绝、记录版本冲突、权限失败、重复点击不造成错误写入或隐瞒失败。
- **金额与业务操作：** 金额文本、空值/缺失/零、统计、付款、撤销/重做、关联记录和失败回滚与现行后端口径一致；前端重做不改变金额计算主人。
- **新鲜度：** 本页及跨页写后复读，账号切换、抓取/导入回执及操作历史摘要刷新正确；编辑过程中的自动刷新不得冲掉后续草稿。
- **长表：** 普通与虚拟窗口下的选择、批量动作、动态行高、冻结列、合计、排序、滚动与定位一致，未渲染行不被当成不存在。
- **机械费与导入：** 草稿/已保存/有效月值分层、原始来源保护、冲突与减少确认、预览/确认写入及失败整批拒绝保持现行含义。
- **界面与键盘：** 1080P 为基础，覆盖本次触达的窄屏和缩放；主题、字体、长项目名、金额精度、浮层可见、Tab 焦点及弹窗关闭归还符合既有要求。
- **导出：** 实际下载并读取文件，对照同一筛选范围的行集合、数值及必要顺序；模板外观、机械费四页和集采打印版沿现有要求核对，不用按钮可点击代替文件验收。
- **生产形态：** 从实际构建文件启动隔离后端，验证登录/过期、Cookie、深链接或页面刷新、主题、版本资源缓存和下载；纯 Vite 开发模式通过不算发布形态通过。

### 复用的既有测试经验

- 历史台账已有模拟接口的真实浏览器回归，覆盖直接编辑、记录凭据、成功与拒绝回执；用于保留 TAIL-394/396 对项目归属、响应、焦点和后续草稿的保护。

- 机械费工作区、来源保护、报表及导出已有界面与后端/文件回归；沿相同业务后果移植。

- 旧壳源码读取与拼接类检查按消费对象分类：旧版继续使用时保留有效检查；新前端采用适合其外部行为的检查。结构假红应调整靶点并保留原缺陷检测能力，不能批量删除断言以换取全绿。

### 分阶段验收与最终完成条件

1. **组合可用：** 首批将类型检查、构建、运行、历史台账完整读写及复杂表格适配跑通，记录具体版本、选择依据和未验项；完成前不扩大全站重复建设。
2. **逐批闭环：** 每阶段在隔离环境完成成功、空/错/拒绝、保存复读和相关导出；明确尚未迁移能力，预览中不得用模拟保存冒充实际保存。
3. **整体验收：** 全部在范围内能力有可追溯的验收结果；执行新前端完整检查、后端完整回归及跨模块关键业务链。失败、未执行和环境阻塞分别记录，不以覆盖率、历史四态或测试总数代替结论。
4. **行为对照：** 关键金额、行集合和导出用固定输入对照后端及现行判据；旧版与新版出现差异时按业务主人判定，不能仅凭与旧版相同宣称正确。
5. **性能核对：** 采用相同数据、环境和操作记录旧新版页面进入、筛选、编辑与滚动表现；调查明显退化并解决或提交具体取舍。暂不虚构毫秒阈值，不宣称框架天然加速。
6. **切换准备：** 在隔离环境验证生产构建、资源一致性、发布与回退，并准备未保存编辑和旧浏览器页面的处理方式；用户完成预览确认后才提出正式切换。
7. **正式切换后：** 获得当次授权再执行，核实际提供的构建版本和关键路径。真实写入、外部抓取、实体打印等现场项目按各自授权与条件列明；隔离通过不能作为这些项目已经完成的证据。
8. **退役条件：** 新前端完成事先列明的日常使用场景、无未关闭的阻断问题、现场未验项已有明确结论或边界，并再次核回退需要后，才退出旧实现和临时资源。
