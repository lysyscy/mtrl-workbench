# 本 effort 的质量判据与代表场景

主人分别为[代表场景](../tails/issues/TAIL-485-前端体验代表场景.md)和[质量判据](../tails/issues/TAIL-486-质量判据与取证深度.md)。按地图最新授权由主控裁定技术取证；这不是新增全仓规则，也不代签用户主观体验、业务变更或实质剩余风险接受。

## 九维适用与停止条件

| 维度 | 此项目的可观察判据 | 所需证据/何时止 |
|---|---|---|
| Q1 性能 | 当前真实数据规模下，已选动作能到正确可见终点；能辨认网络/计算/布局成本 | 当前生产构建、设备/浏览器/视口/字号、动作、数据/缓存记录。先筛查代表；需要优化才做同条件重复对照。没有当前性能根因则保持，不用旧毫秒或统一FPS签通过 |
| Q2 交互 | 普通输入不等其他格保存，写入成功与未知区分，等待不误报空，连续画面稳定 | 优先复用已有失败→修复证据；最新通知书单格端点补一次连续输入/未知结果连通。反馈或首读已变路径做代表，不穷举每格 |
| Q3 一致性 | 同义状态/主题/格式有现行主人，页面差异有业务原因 | 源码追所有者与消费者；无变更的八主题/列宽/多队列旧决定保留，新可见矛盾才补视觉验证 |
| Q4 可用性 | 常规1920×1080 CSS、1.12应用字号下必要信息/动作可达；宽不足横滚按当前规则 | 真实副本代表页与任务弹窗观察；金额/编号自动布局完整、人工缩窄许可裁剪不误判。保鼠标、普通文本和原生控件，不恢复退役键盘增强 |
| Q5 维护性 | 具体规则变化能找到权威主人和必要消费者，不需猜测来源/状态/运行身份 | 全库具名责任表、真实新缺陷与旧决定对照。文件长/重复/候选数量不触发重构；低成本错误指针可局部修正 |
| Q6 正确性 | 金额/空0/对象/范围/状态及导出依现行业务契约 | 高后果链复用同输入旧测试及原回执，证据缺失选现有隔离测试；新增风险用最小反例。模拟回执不当真实业务成功 |
| Q7 容错 | 失败可解释和恢复；旧请求不串范围；未知写入不盲重投 | 对已识别可达失败定向注入；无需统一重写队列。规则新增未知结果、项目坏200边界单独核后再定措施 |
| Q8 回归 | 测试确实保护风险，运行环境/选择/退出/报告可信 | 优先修491取证基础，再跑选定原测试；空选择/跳过/环境失败不当通过。必要检查通过且实质发现关闭即止 |
| Q9 数据/权限 | 服务端校验身份与对象，写入原子，测试目标明确隔离 | 明确文件/实际engine/schema及副本身份；金额/历史冲突/权限/导出代表。正式迁移、真实i8与物理打印仍另授权，外部未验不伪装完成 |

P1–P5用实际变化原因评职责，不要求全站一种表格/队列；P6先量再优化；P7先现有框架/官方机制；P8有界批次；P9先定契约与所有权；P10选择能暴露具体风险的最低有效层。当前已有React/Query/AG Grid/AntD、Decimal/SQLAlchemy及Pydantic足以承载发现的局部问题，没有选择换框架/引入状态库/通用配置平台。

## 场景选择与样本

以所有16路由的静态职责登记为广度；运行选择有不同表格/保存/读取机制的代表，不把每个页面强制生成同一矩阵。默认桌面沿项目现有1920×1080/1.12；浏览器版本、CPU/内存、构建和主题由实际采集记录，不能假用历史设备。正常规模取当前只读来源复制的真实范围，峰值只称“当前副本可得最大/历史可得”，不足时明示，不造行数凑峰值。

| 场景 | 选择理由与起止 | 保留契约/所需层 |
|---|---|---|
| 通知书首次进入、返回、精确搜索 | 共用深表格+本地过滤；导航/输入到当前正确结果和合计绘制 | 记录当前总/显示行数；旧1261/266仅来源线索。首进/暖返回分开，当前布局标记与两帧，不能仅networkidle |
| 通知书连续两格和丢回执 | 7156a5ae最新金额入口还缺浏览器联通 | 已有真实副本两项测试；输入/焦点、单次POST、可靠回读与后续草稿，金额组合复用后端81项历史证据 |
| 库存筛选与行/合计 | 当前高规模候选、延后过滤及全量有效值转换 | 当前副本行数、动作到正确结果；已有本地筛选及保持金额测试。没有热点证据不改rowBuffer/缓存/分页 |
| 集采主表与子表打开 | 第三类原生列宽/轻表格、任务弹窗与已深化workspace | 当前主表与实际子明细数量、摘要/按钮可达。恢复同ID写一次沿17495586同源码旧证据，不重复整套 |
| 过程矩阵/机械汇总代表 | 多层列、矩阵与轻量月页，区别于通知书 | 实际非空月份/项目，布局与范围正确；后端机械签名/累计与导出在数据库/成品层负责 |
| 大表/年度自然高度代表 | autoHeight、整页滚动和范围切换 | 当前可得最大真实样本；无第二规模时保缺口，不由9项目预测任意规模 |
| 规则新增未知结果 | 新的可达恢复风险 | 合成/隔离一次成功后丢响应和再次保存，核新增ID/行数、不重算旧剔除。先定真实后果再选最小修复 |
| 项目坏200/用户重复赋值 | 读取边界和低频动作的不同风险 | 项目必用字段最小坏响应判断是否局部失败；用户服务端赋值非toggle已核，无业务后果不建新协议 |
| 油卡非空数据 | 历史浏览器样本空，不能沿空表签完整业务 | 先核当前副本是否存在非空充值/发票；若缺，保真实GUI缺口，金额/转账/收票等用既有隔离服务测试。真实旧接续仍归474 |

## 验证层与复用

1. **静态基线**：三份分区已覆盖每个在用责任；旧已完成/保留项目逐项核版本和消费者。未逐行审计之处明确标出，不用范围全覆盖冒充深度全覆盖。
2. **工具反例**：491的合成源/目标、pytest环境、指纹修改/新增/删除；完全不连接业务库。先使取证入口可信，才建立后续副本。
3. **后端新增运行缺口**：源文件与目标守卫通过后，选现有身份/项目删除、金额/历史冲突、库存投影、机械来源、油卡转账、导出与schema drift的代表；精确节点及理由写具体运行票。已同源码、同预期通过的通知书与集采/油卡深化不机械重跑。
4. **前端运行**：统一新建disposable真实副本、外呼阻断，生产构建；可复用同源码的既有窗口/恢复证据，新增联通和当前显示/性能缺口单列。定向只读动作trace可以在可丢弃可写副本上取，但明确这是“只读动作”，不冒称旧frontend_measure要求的冻结只读owner，不绕其守卫。
5. **导出**：选择各数据源/模板类的已有文件层合同，核金额/范围/缓存与实际可打开；纸面/i8版式仅旧具名范围，不能外推。新输出仅本轮受管组。

所有运行记录源/dirty、目标、命令、退出与清理。失败先判环境、夹具、旧预期或产品，不抹掉原结果。发现新风险才扩大；低影响文档只查语义/引用和真实钩子。已有检查无输入变化则复用，不追覆盖率或测试数。

## 需要用户的边界

当前选景和验证设计不改变业务或体验取舍，无需新的“是否开始”确认。若新证据要求改变金额、归属、权限、状态或已定布局，或必须接受实质剩余风险/大迁移成本，先用具体事实、候选、影响及推荐请求裁定；等待时继续无关已授权批次。外部现场验证暂未授权，保为具名未验边界，不让它阻断纯工具和本地隔离改进。
