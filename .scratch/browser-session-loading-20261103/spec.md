# i8 浏览器登录态复用测试与页面稳定加载

2026-11-04 · 正式规格 · 用户已确认验收入口。本文持有共同范围与验收依据，[总票 TAIL-475](../tails/issues/TAIL-475-i8会话复用与稳定加载.md)为 effort 入口，[六张实施票](ticket-plan.md)各自持有进度；发布不代表实现、真实验证或部署完成。

## Problem Statement

用户希望验证 i8 抓取能否复用日常浏览器已经建立的登录态，减少为抓取重新登录、影响正在使用的会话。目前 i8 HTTP 客户端可复用其自身按账号保存的会话缓存，但没有直接接入日常浏览器会话的现成入口；缓存缺失或失效时仍可能重新登录。后端缓存命中不能证明浏览器会话已被复用。

欠款台账等页面一次进入期间，汇总、筛选与表格陆续显示，部分内容改变布局，造成反复跳动。用户要求采用成熟数据工作台的做法改善全站同类问题，明确接受筛选栏、页签先出现、表格随后出现；目标是稳定且有清楚反馈的分区加载。

## Solution

本 effort 有两个可独立推进的方向：

1. **i8 会话复用可行性验证**：沿已有浏览器会话、既有取数及解析链做最小只读取数，核对身份、请求范围和结果；不能复用时明确停止并记录原因。交付可复现方法与适用边界，是否推广到日常抓取另行决定。
2. **全站同类加载体验改善**：欠款台账先打样，再沿页面／表格共用机制推广。框架和筛选可以先可用，数据区域在稳定占位内独立加载；首次无数据、已有结果更新、切换查询、空结果和失败分别表达。正常编辑与保存继续保持连续。

成熟案例提供骨架、局部加载提示、表区遮罩及顶部细加载条等不同组合。工程选择依据当前场景与已安装组件，不要求所有区域同时到齐，也不照搬其他产品的延迟、缓存或轮询参数。

## User Stories

1. 作为 i8 使用者，我希望抓取测试使用浏览器已有登录态，以便验证日常登录能否直接复用。
2. 作为 i8 使用者，我希望测试核对账号、组织与服务器，以便结果来自预期身份和范围。
3. 作为 i8 使用者，我希望只读取最小必要范围，以便验证可行性而不改变业务记录。
4. 作为 i8 使用者，我希望会话缺失、失效或不可访问时明确停止，以便知道复用是否真正成立。
5. 作为 i8 使用者，我希望成功有实际读取及来源核对依据，以便区分真实成功、空响应和权限失败。
6. 作为 i8 使用者，我希望保留原浏览器会话和未保存状态，以便继续日常工作。
7. 作为 i8 使用者，我希望报告不暴露会话凭据，以便安全交接结论。
8. 作为后续维护者，我希望得到可复现步骤及已验证限制，以便决定是否接入日常抓取。
9. 作为工作台使用者，我希望进入页面先看到稳定框架与可用筛选，以便识别页面和加载范围。
10. 作为工作台使用者，我希望表格及统计在预留区域加载，以便已显示内容不被反复推挤。
11. 作为工作台使用者，我希望各区域可以独立就绪，以便已可用内容不等待无关请求。
12. 作为工作台使用者，我希望短请求不会明显闪现加载提示，以便操作保持连贯。
13. 作为工作台使用者，我希望返回已看过的页面时保留内容和位置，以便继续核对。
14. 作为工作台使用者，我希望同条件更新保留上次成功结果，以便刷新期间仍能阅读并理解更新状态。
15. 作为工作台使用者，我希望切换项目或期间时旧结果不冒充新结果，以便金额和归属不被误读。
16. 作为工作台使用者，我希望未加载、真实空结果与读取失败清楚区分，以便不把未知当零或无记录。
17. 作为工作台使用者，我希望次要区域缓慢或失败时原位反馈，以便其他区域继续使用。
18. 作为工作台使用者，我希望主要读取失败后有对应重试入口，以便恢复当前任务。
19. 作为编辑者，我希望加载与读回保持草稿、输入位置、滚动及实际列宽，以便连续编辑不受干扰。
20. 作为使用较大字号或较小窗口的用户，我希望加载反馈与内容始终可读、可达，以便正常完成工作。
21. 作为减少动态效果的用户，我希望无需依赖持续动画也能理解状态，以便安静地使用工作台。
22. 作为验收者，我希望看到完整变化过程和具名覆盖范围，以便判断跳动改善及剩余缺口。

## Implementation Decisions

### i8 会话复用验证

- 复用现有 i8 请求、响应校验与业务解析能力。浏览器接入只提供本次读取所需的已有会话上下文，优先用宿主支持的接入通道；不默认新增浏览器服务、复制完整用户配置或改变安全设置。
- 为测试明确装配“仅复用已有会话”的边界：无会话、身份不匹配或响应判定会话失效时停止，禁止调用登录／强踢。关闭强踢本身不等于禁止重新登录，不能以现有客户端自动重登后的成功作为复用证据。
- 按用户当前 i8 页面和已收录契约选一个最小只读代表，优先精确对象查询或明确范围的小列表；需要分页时按其既有契约核完整性。POST 接口也先核业务语义为读取。
- 核对页面当前账号、组织和目标服务器，以实际业务响应及页面对象交叉核对；HTTP 200、取得 Cookie 或空列表均不足以单独判成功。有效空响应的既有复核不扩为登录或整批抓取重试。
- 会话材料限本次临时使用，不持久导入后端会话缓存，不在文档、日志、截图或 Git 中披露。保护原标签及未保存状态，不通过退出／重新登录准备测试。
- 结果区分已验证可复用、仅在具名条件下可复用、已验证不可用及未验证，记录去敏范围、接入方式和限制。既有产品内 i8 操作的登录／恢复策略保持独立，推广生产入口另行决定。

### 页面加载与反馈

- 沿现有 React、Ant Design、AG Grid Community、查询缓存及页面／表格准备链解决；共用机制持有呈现，页面提供数据依赖与区域边界。不另造业务表格或请求系统。
- 框架与数据区域独立发布，保留字体、主题、字号和布局就绪约束。身份／权限未核实的内容继续按原规则隐藏并暂停动作，加载改善不得提前开放访问或业务操作。
- 首次无结果时，结构可匹配的区域用简洁骨架，其余在预留容器内用局部加载提示；占位消费真实内容区、字号及已知结构，不伪造金额、行数或百分比。
- 避免已显示内容被反复撑开、收回。未知行数不要求预知最终长表高度，结果到达后合理接管空间；短表自然结束、长表沿原滚动规则，不为稳定而永久留整屏空白。
- 同条件重访／后台重读保留成功结果、筛选、滚动和草稿，不重新整页隐藏。必要更新提示不新增布局行；普通行内保存及其读回沿既有静默规则。
- 切换项目、月份等查询身份时保留筛选与表区空间，隐藏旧范围业务值和编辑入口，等待对应结果；晚到响应不能串范围。本地筛选／排序保持原行为，不增加整表淡出淡入。
- 同一查询的金额、合计和状态保持一致；独立次要区域不阻塞整页。决定权限、金额或可操作性的必要依赖仍须就绪后才开放相应动作。
- 未加载、真实空、错误与部分可用分别表达。次要区失败原位重试；主要读取失败在所属区说明原因和恢复入口。同条件刷新失败可保留上次结果并说明更新未成功，不能冒充最新结果。
- 使用现有组件的克制动效并支持减少动态效果；短请求避免加载提示闪现，不为动画延迟已就绪内容，不做大表逐行入场或整体位移，不新增通用自动轮询、任意缓存期限或自动重试策略。
- 保护完整金额、列宽偏好、固定合计、中文输入、输入位置、在途操作及未知写入结果；不为加载反馈改变业务字段、排序、统计和导出范围。

### 范围与集成

- 全站同类问题先从欠款台账三类汇总与双侧台账打样，再按共用机制／实际差异选择代表。通知书／库存列表、过程／机械工作区、集采／油卡明细及只读报表用于识别呈现类型，复用相同机制的页面不重复造改动。
- 以当前过程观察与源码共同确认原因，不能仅凭有多个查询就定根因。原性能 effort 已关闭，本次不扩为新一轮全站性能优化。
- i8 验证与加载改善互不阻塞，后续分别拆成可验收切片；一方缺外部条件不阻塞另一方。本规格不要求数据库迁移，新增业务含义或授权变化另行明确影响。

## Testing Decisions

2026-11-04 用户确认两处验收入口：i8 沿既有取数／解析链做已有浏览器会话的最小只读验证；页面沿登记真实副本浏览器入口观察全过程，保护草稿与列宽。测试断言可观察行为，不以源码形状或自造回包替代产品结果。

### i8：已有会话 → 既有取数与解析结果

- 主要证据为已核浏览器会话完成真实只读取数，核同一身份／组织／范围的对象，并核本次未调用登录或强踢。工作台自身登录态或独立自动化浏览器登录缓存不是本次对象。
- 既有离线会话缓存测试可借鉴可控传输和登录替身；保留其原有缓存登录／恢复契约。仅为严格复用边界补有效会话读取、缺失／失效停止、拒绝错误目标、未重登及未持久导入等必要行为覆盖，不检查私有字段或函数文本。
- 先离线验证严格模式保护，再做一个具名真实代表；不可用就记录缺少条件和未验项，不用模拟成功或新登录补成复用成功。解析沿既有数据源校验，不执行同步、采用、付款、打印或正式落库。

### 页面：真实页面入口 → 操作 → 完整呈现过程

| 场景 | 可观察完成条件 |
|---|---|
| 首次进入 | 框架与筛选可识别，数据区有稳定边界和反馈，无反复撑开／收回已显示内容 |
| 分区先后就绪 | 已就绪区域可用，后续区域原位接续，数据依赖动作仍受保护 |
| 切项目／期间 | 保留表区空间，旧值及编辑入口不冒充新范围，晚到响应不串范围 |
| 返回／同条件刷新 | 复用内容、筛选和位置，反馈不清空或重新隐藏整页 |
| 真实空结果 | 读取完成才显示空态，金额和合计沿真实口径 |
| 慢请求／失败 | 有限区域继续加载或原位报错／重试，关键与次要失败影响范围清楚 |
| 编辑／保存读回 | 保草稿、输入位置、主动滚动与实际列宽，普通保存无额外占位提示 |

- 复用登记真实副本、现有浏览器夹具、表格呈现及布局检查。写入代表只在每例核验的可丢弃副本执行，预览的外部动作熔断保持，独立 i8 真实验证另行运行。
- 欠款台账为第一完整样板；之后按实际受影响共用机制选页面代表，维护覆盖及未验清单，不凭单页通过宣称全站已验，也不预设全部页面×状态组合。
- 窄／矮窗和大字号按本次影响选必要代表，桌面沿项目既有基线；减少动态效果核可理解、可用。覆盖自然高度与内部滚动的不同类型，保护现有表头／合计。
- 受控延迟／读取失败可辅助诊断，但须记录条件，不能冒称真实业务写入、权限或外部接口成功；正常真实读取链另有代表证据。
- 闪动／跳动观察全过程，必要时用连续帧／录屏及关键区域几何辅助。最终截图、networkidle 或单一布局分数不能替代过程验收，不设无依据的时间／像素门限。
- 永久测试只补实际缺口，如范围隔离、严格复用失败或草稿保护，不逐张断言骨架像素形状。实现时执行受影响类型检查、构建及现有必跑检查，通过后按项目够用即止原则收尾。

## Out of Scope

- 工作台 UI 自动化的日常浏览器登录态复用框架。
- 自动登录／强踢 i8、测试失效后回退登录、复制完整浏览器配置或持久导入会话。
- 自动推广至全部生产抓取入口，或承诺全部浏览器／账号／服务器长期可用。
- 正式业务写入、外部审批／付款、实际打印、生产部署或服务切换。
- 业务计算、金额精度、归属、权限、字段、排序、合计、导出或正常保存／撤销流程的重写。
- 新业务键盘增强、新主题、整页风格重做、行入场、全站轮询、通用缓存期限、完整浏览器矩阵或固定性能提升承诺。
- 恢复已关闭性能 effort，或要求全部旧功能重新验收。
