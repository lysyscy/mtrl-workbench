# Edge 日常抓取验收范围

本文件描述待批准动作，不是安装或外部读取授权。当前源码候选未部署；真实日常能力须以下验收完成后判断。

## 可审阅对象

源码为 `apps/browser-extension/manifest.json` 与 `service_worker.js`，使用说明为同目录README。最终候选完成后按实际源码散列复制到主检出 `var/browser-extension/releases/<digest>/`，只包含这三份文件和散列清单。该目录是待安装/在用组件的固定位置，随扩展消费者管理，不登记成30天自动清理证据；卸载且无恢复用途后才能退出。源码唯一维护源仍为Git任务分支。

扩展固定ID为 `jfkgliolimmpceandogfimjkadplidem`，权限只有activeTab、scripting、storage；仅接受本机工作台8000/8065入口消息，无cookies、debugger、webRequest或全站权限。选定标签的既有会话由浏览器自己携带，后端不取得Cookie。首次安装需Edge开发人员模式和加载解压扩展，选定i8标签需点击扩展图标授予activeTab。

## 一次真实验收

1. 用户批准上述安装/权限以及本次真实读取范围后，核当前Edge已有i8业务页的站点和可见账号/组织；不替用户执行登录或强踢。
2. 以用户此前指定的当前Edge站点为本次唯一目标，正式工作台配置保持原值。将已核目标、i8用户名和月份2026-11写入登记run的私有work范围JSON；不提交真实身份文件。
3. 通过统一预览入口新建真实可丢弃数据库副本，并启用具名browser-notice-check。只开放指定月份通知书抓取及必要连接控制，普通HTTP登录和其它写动作继续拒绝。
4. 在同一Edge中使用实际工作台页面，选浏览器已有会话并连接；从原“按月抓取i8”按钮取2026-11。请求自动经扩展执行，不用Agent逐条转交响应；沿原解析和通知书落库流程，仅写本次副本。
5. 从工作台读回实际结果，核取数范围与身份、返回与落库/忽略信息，记录有无登录/强踢/重定向。不能只凭200、零条或绿色连接状态判成功。缺真实代表则如实记录未验。
6. 结束后正常断开和停止预览，由原工具清理自建schema；保留脱敏文字结论。真实业务回包与截图仅留私有受管证据，扩展的去留按用户批准的安装用途处理。

## 使用差异与限制

第一次安装后，每次需要重新建立连接时：在i8业务标签展开账号面板、点击扩展选定标签，在工作台“i8接入”点连接。随后各已接线的抓取按钮仍按原操作使用，无模型参与。页面/会话关闭或失效后停下，由用户重连；不会自动退回HTTP登录。打印/PDF保持原策略，本次不验、不执行。

本轮只以通知书作为真实日常链代表，不声称全部业务种类、超大xlsx或其它i8部署均已现场验证。正式服务部署另行授权。
