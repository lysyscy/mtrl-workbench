# Excel加载项：开发、安装、维护和原表适配评估

评估日期：2026-10-15。用户认可流程方向，仅授权评估，暂不实施。本文评估此前建议的Office.js任务窗格加载项，不将VBA/XLAM、COM或VSTO等不同方案混为同一种安装方式。

## 结论

技术上有条件可行，能保留原生Excel编辑，读取当前工作表的值进行系统核对；当前原表具有可适配路径，但不能承诺全月份、全结构零确认自动识别。它属于中等开发和维护投入，安装部署比普通网页功能复杂。主要新增成本是原表结构适配、HTTPS与认证、Office侧栏生命周期及旧结果失效，不是重写核对规则。

建议的成本控制：首版采用“读取当前表/选区→点一次核对→侧栏对照和定位”，修改后标明待复核；随后才补自动重核。它已经可以免去每轮保存重传文件，不需要为此先实现所有编辑事件的自动同步。完整月度存档、跨窗口自动选单和多人协作不计入基础首版。

长期部署渠道尚未落实，不能把两台Windows的试点旁加载等同于受支持正式部署；在此项、HTTPS/登录和真实Excel取值验证完成前，不宜承诺直接推广。

## 原表适配判断

结构证据复用 `evidence.md` 与 `source-structure.json`，已核原件SHA未变，不重复运行同一批检查。

| 原表特点 | 适配办法与成本 | 判断 |
| --- | --- | --- |
| 一个工作表含多个项目、项目写在合并标题 | 识别项目分段，提取候选名称，复用已有项目匹配；不确定的对应关系集中确认 | 可以适配，需开发分段读取；未用真实项目档案证明命中率 |
| 重复两级表头、少量缺表头旧表 | 每段定位表头；缺表头时由用户选区并确认列对应，不要求改原文件 | 常见月表可规则适配，缺头旧表需辅助指定 |
| 小计、合计、说明混在明细之间 | 先做行分类预览，汇总不重复进核对，未知行明确保留 | 可以适配；不能只筛形似单据号的行 |
| 无号明细、编号栏填写文字 | 保留原行、收款单位和金额，显示未匹配/待核输入 | 可以展示与提示，不能自动补出正确通知书 |
| 公式及金额 | 读取Excel当前计算值，保留公式和来源地址供诊断；错误值不可当零；手动计算模式须明确结果尚待计算 | 不需要导入导出转换；当前值与计算事件仍需Excel现场验证 |
| 隐藏行、筛选、月份标题不一致 | 明确核对工作表/选区及包含的隐藏行，月份以用户选择为准并提示矛盾 | 能读取和呈现结构；业务范围不能仅凭可见性或标题猜测 |
| 原有格式、批注和人工付款备注 | 原生Excel负责显示和编辑；助手只读需用的值与结构，保留上下文，不据备注认定系统已付款 | 避免格式往返问题；无需重建整张Excel样式 |
| 修改、插删行、排序和工作表切换 | 结果绑定工作表与当次输入版本；结构变化后重读范围，不沿用旧行号展示通过 | 可以设计；是自动复核版的重点开发与回归成本 |

八月183个非空行中134行为明细候选是原件结构盘点，不是Office.js解析成功率或已通过业务核对的行数。1月无标准表头、3月开头不完整等情况使“任意历史表一键全自动”缺乏依据。

## 开发预算

以下为结合实际模块与工作量的工程估计，非实测工期、报价或承诺。一人日按一名开发者约8小时有效工作估算，不包含组织IT审批等待和第二台机器未知故障；阶段数字为累计预算，不相加。

| 阶段 | 范围 | 累计估计 |
| --- | --- | --- |
| 技术验证 | 一个任务窗格在本机加载；连通拟用HTTPS入口/登录；读取真实表的当前值、公式结果及选区；不做完整产品 | 0.5–1.5人日 |
| 可用首版 | 原表常见结构识别及范围确认、选区/整表手动核对、原报/系统对照、定位、修改后待复核、后端复用、通知书粘贴选单衔接、首轮现场验证和安装说明 | 4–7人日 |
| 自动复核版 | 再覆盖输入、批量粘贴、公式重算、插删排序、多表切换、断线和旧响应失效，并做现场回归 | 6–10人日 |

首版预计组成：Excel任务窗格与定位约0.5–1人日；原表分段/列/行分类约1–2；后端核对、系统账号和HTTPS接线约1–2；通知书粘贴选单与相关界面约0.5；隔离核验、Excel现场和安装材料约1–1.5。工作有交叠，范围取舍影响总计，不能把这些分项当固定合同计价。

月度核对结果存档及其与现有计划的版本/替换关系，若另行纳入，暂估另需1–2人日且先确认保存契约。自动跨窗口推送勾选不在本次预算，继续采用用户认可的单据号复制粘贴。

## 安装与部署成本

可用同一HTTPS入口同时提供加载项网页和本系统API，在服务端转发现有HTTP后端。这样无需重写FastAPI，也避免把任意跨域放行当成接线方案。具体网关产品/证书来源尚未选择或安装。

| 场景 | 要处理什么 | 预估与边界 |
| --- | --- | --- |
| 本机试点 | 受信任HTTPS证书、XML manifest旁加载、加载项内本系统登录、Office.js网络访问 | 服务端准备好且策略允许后，单机首次配置约0.5–1.5小时；不是本轮实测 |
| 第二台电脑试点 | 服务器名称/地址可达、证书主机名正确并受信任、Office与WebView/API条件、旁加载策略与本系统登录 | 同样前提下约0.5–1.5小时/台；Office与组织策略未知，可能形成阻塞 |
| 长期正式部署 | 确认组织支持的加载项分发渠道；验证租户、管理员及许可条件，或重新评估其他加载项技术路线 | 不能在条件未知时估算落地日期，也不能把共享文件夹目录当作官方支持的生产部署 |

无需将每份工作簿上传到微软云端才能核对，可让加载项只把本次需要的计划字段发给本系统；但Office.js脚本及Office服务依赖另有联网条件。完全断网可用尚未证明。

## 维护成本

- 正常页面与后端规则更新：以服务端发布为主，用户重新打开侧栏加载新版本；不应每次重装，但缓存与前后端版本要处理。
- manifest中的地址、权限、功能区命令变更：可能涉及重新分发或安装；以最终选择的部署渠道为准。
- 原表继续使用同类标题/列时，用户改金额、加行不应要求维护程序；表头和版式出现新变体时，需补适配及真实样表回归。
- 证书到期或更换服务器：需续期、核主机名和信任；改服务器地址可能同时影响manifest。
- Office/WebView更新：不需要每次重做全套，但实际读取/事件/登录异常时需要现场复现。自动复核版的维护面明显大于点击核对版。
- 侧栏运行与事件：默认任务窗格运行时结束后订阅不再有效；重新打开必须重读。若将来另用共享运行时，需单独验证生命周期，不能预设关掉侧栏仍持续核对。
- 账号或会话问题：按本系统身份重新登录；浏览器可用但Excel侧栏失效是可能的独立问题，不应要求用户反复重装Office。

相较单一网页，长期增加了Office宿主、证书/来源、分发渠道和缓存四类维护面。现无运行数据，不编造固定“每月维护几小时”；普通一处模板别名或界面修正可按小时级预留，平台/组织策略故障可能按天级处理，此为预算判断。

更新与事件来源：[加载项部署及更新](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/manage-deployment-of-add-ins?view=o365-worldwide)、[Excel事件生命周期](https://learn.microsoft.com/en-us/office/dev/add-ins/excel/excel-add-ins-events)。

## 权限与正式实施前的证据门槛

Excel专用API即使只读也要求manifest声明ReadWriteDocument；因此“实现只读取原表”是代码行为约束，不能承诺平台授权本身是只读。[微软权限说明](https://learn.microsoft.com/en-us/office/dev/add-ins/develop/requesting-permissions-for-api-use-in-content-and-task-pane-add-ins)

后续如另获实施授权，应先验证以下实际结果，再决定是否投入完整首版：

1. 本机任务窗格能稳定加载，所需脚本网络可达，HTTPS/项目登录连通。
2. 原表选定范围的明细与金额、公式结果、项目分段及源地址可核；没有识别的内容有明确反馈。
3. 修改后旧结果不继续显示为已核实；点击复核拿到当前值；结构变化不会定位到错误行。
4. 试点与正式部署渠道各有证据，第二台电脑的限制被实际核实。
