# 油卡管理规格

用户已于2026-10-29确认整体设计，2026-10-31三轮grill-me已确认统一充值金额、新报表公式、独立双表、筛选、逐列编辑及新增/转账/档案流程。转入/转出类型固定，“转账”使用独立次级按钮。此前净充值/纯平账的拆分口径不再作为实施基线。本规格固定建设范围，现行业务定义归[油卡需求](../../docs/requirements/oil-cards.md)，术语归[GLOSSARY](../../GLOSSARY.md#油卡)，源码及源资料证据归[研究记录](research.md)，界面安排归[界面记录](map.md)。用户已授权派Sol xhigh开始开发与隔离验证，首票453实施中，未执行真实接续或部署。

## Problem Statement

材料管理人员目前用Excel管理油卡充值、开票和调账，另用本地助手下载、识别、改名和整理发票，再人工登记台账。实体卡、当前使用项目和每笔费用归属混在名称映射中；换卡、改项目或沿用当前映射可能改变历史显示，停止用卡的项目也可能继续进入匹配候选。

发票文件和已记金额缺少稳定关联及跨批次去重，用油金额又需要进入特殊费用和会议大表。继续人工分别维护容易重复计入充值、错挂项目或丢失历史依据。用户只负责充值与开票，不管理加油消费明细。

## Solution

新增油卡工作区，管理实体油卡、用卡账户、当前及历史关联、统一金额及其充值/转款/调整依据、发票与分配。账户支持归档和重新启用，自动匹配只考虑在用账户；归档账户仍可人工补挂迟到发票。

用户可粘贴交付链接或上传PDF。系统下载或接收后识别、核对、按唯一归属自动登记并归档；不明确的记录留待处理。一张发票可分配给多个用卡账户，分配合计等于票面含税金额；重复输入不得重复记账。原件持久保管，显示及导出名可随经确认的归属调整。

特殊费用用油由当月充值发生额（含调整、转入和转出）加当月自定义额组成；会议大表由截至所选月累计充值金额、同期累计特殊费用自定义额及截至该月的大表额外自定义额组成。开票仅用于核对，不冲减报表自动部分。两处自定义额支持正数、负数、零和各自备注；特殊费用按月发生，大表额外值沿用最近一次金额及对应备注，填0清零。

首次接续保留四张活动表的有效记录和原始依据，排除存档工作表。期初、归属冲突和旧手填总额先列入核对清单；已有PDF优先补关联，不重复增加开票金额。

## User Stories

1. 作为材料管理人员，我希望在工作台内统一查看油卡充值与开票，以便减少Excel和文件夹之间的重复登记。
2. 作为材料管理人员，我希望建立关联正式项目的可命名用卡账户，以便区分用卡人、用途和成本归属。
3. 作为材料管理人员，我希望同一项目能有多个用卡账户，以便保留项目内部的分账。
4. 作为材料管理人员，我希望实体卡与用卡账户分别管理，以便同卡跨项目使用时保持账务清楚。
5. 作为材料管理人员，我希望卡号未知时也能先建档和记账，以便接续已有的有效核算记录。
6. 作为材料管理人员，我希望完整卡号按文本保存、尾号仅作显示，以便避免截断、科学计数法和错认卡片。
7. 作为材料管理人员，我希望调整卡片的当前使用归属时保留历史每笔归属，以便历史统计不随档案修改改变。
8. 作为材料管理人员，我希望维护主副卡及换卡关系，以便换卡后继续使用原账户而不重复统计金额。
9. 作为材料管理人员，我希望归档不再使用的用卡账户，以便自动匹配排除旧账户。
10. 作为材料管理人员，我希望归档账户可以重新启用，以便业务恢复时继续使用已有历史。
11. 作为材料管理人员，我希望人工把迟到发票明确挂回归档账户，以便处理旧项目的后开发票。
12. 作为材料管理人员，我希望用卡账户归档与项目档案归档分别管理，以便停止用卡不影响项目的其他业务。
13. 作为材料管理人员，我希望登记充值的日期、卡片、账户、金额及必要备注，以便查询实际入卡记录。
14. 作为材料管理人员，我希望内部调拨同时记转出和转入，以便项目之间调整归属而不增加公司充值总额。
15. 作为材料管理人员，我希望只维护一个统一金额并保留变动依据，以便按实际账务核对，而不区分净充值和纯平账。
16. 作为材料管理人员，我希望首页按主副卡分组查看用卡账户的完整历史账务和开票核对结果，以便核对未闭合的账务。
17. 作为材料管理人员，我希望补录、更正旧账并查看调整依据，以便修正实际发现的问题而不受月份锁死限制。
18. 作为材料管理人员，我希望更正支持安全撤销，以便误操作后能恢复一致的账务及统计。
19. 作为材料管理人员，我希望批量粘贴发票交付链接并发起下载，以便一次处理收到的多张发票。
20. 作为材料管理人员，我希望识别发票号码、开票日期、含税金额和卡号，以便把票面信息登记到对应油卡。
21. 作为材料管理人员，我希望识别和归属均明确的发票自动完成登记及归档，以便减少逐票操作。

28. 作为材料管理人员，我希望一张票的多项分配整体保存，以便失败时不留下半张票的账务。

30. 作为材料管理人员，我希望查看并导出规范命名的原件，以便发送、报账和线下存档。
31. 作为材料管理人员，我希望文件名包含卡尾号、项目简称、金额和票号，以便容易辨认并避免重名。
32. 作为材料管理人员，我希望一票多项目的文件名显示“多项目”，以便不把整张票误认成某一个项目的金额。
33. 作为材料管理人员，我希望退款、红冲和作废关联原记录并保留原件，以便追溯真实业务的后续变化。
34. 作为材料管理人员，我希望特殊费用用油按确认后的金额口径取得当月自动部分，以便无需再次手填。
35. 作为材料管理人员，我希望特殊费用自定义额按月维护且支持正负、零及备注，以便说明当月额外金额。
36. 作为材料管理人员，我希望会议大表按项目累计至所选月份且包含往年，以便反映正确的累计用油金额。
37. 作为材料管理人员，我希望大表额外金额及对应备注可以沿用、修改或填0清零，以便维护截至该月的补充金额而不逐月重复相加。
38. 作为材料管理人员，我希望未来月份已录数据不进入较早月份的大表，以便历史查询的截止范围准确。
39. 作为材料管理人员，我希望只接续四张活动表的有效记录，以便系统不引入被排除的存档及临时核对区。
40. 作为材料管理人员，我希望无日期的原始记录保留原标记并单独核对期初，以便不编造明细日期或摊入错误月份。
41. 作为材料管理人员，我希望旧PDF优先补档关联已有开票记录，以便避免补文件时重复增加金额。
42. 作为材料管理人员，我希望旧手填总额、自动部分和候选自定义差额同时可核对，以便采用新公式时保持接续可解释。
43. 作为材料管理人员，我希望源资料归属冲突单独列出，以便人工裁定后再接续。
44. 作为材料管理人员，我希望页面和导出消费同一份有效数据，以便两处结果可以互相核对。
45. 作为材料管理人员，我希望发票原件与台账一起备份且可取回，以便持久保存业务依据。
46. 作为材料管理人员，我希望在主卡、用卡账户以及每笔充值和发票分别维护自由备注，以便记录各自信息而不互相覆盖。
47. 作为材料管理人员，我希望充值、发票使用AG Grid列头筛选及“仅此项”，按字段区分只读、下拉和必要手工输入，已采用的编辑操作完成后自动保存，以便方便核对并控制误改。
48. 作为材料管理人员，我希望明细合计随筛选变化、台账始终导出全部有效记录，以便局部核对与完整留档各自清楚。

## Implementation Decisions

- 新增独立油卡领域，持有实体卡、用卡账户、当前/历史关联、账务记录、发票、金额分配、批次结果及期初来源；项目身份复用现有主数据，显示名称不作为写入身份。
- 卡号保留原文，支持现有16位、19位及未知占位场景；尾号不作唯一键。主副卡和换卡关系不自动产生第二份充值、开票金额。
- 业务服务统一处理归属、金额、幂等和保存结果。查询、账户维护、账务、发票接收/确认/续办、文件查看导出以及两处自定义额及备注通过受现有身份保护的业务接口暴露。
- 自动匹配以可靠票面信息和在用账户为边界，多个候选不猜配；归档账户仅由人工明确选择补挂。历史关联更正保留前后依据。
- 下载、识别和持久归档由同一发票接收流程协调，外部请求不持有长数据库写事务。一张票的多项分配整体保存；明确失败、结果未知和已写入后读回失败分别处理。
- 发票号码及原件身份跨批次稳定；显示/导出名与原件身份分开。重复输入不增加金额，同票号内容冲突留待核对；更正和撤销不能破坏原件。
- 用卡账户只维护一个统一充值金额，含调整与转入转出；开票另列并核对差额，不冲减充值列。两张报表按需求已确认的当月/累计公式取值。原始变动及内部调拨双方可追溯，转入/转出类型固定、不能自由选取或切换；调拨行内更正日期或金额时两端一起更新，归属修改对应一侧，整笔撤销两端一起办理。实际退款、红冲或作废通过关联原记录的后续记录或状态反映。
- 特殊费用及会议大表通过油卡领域服务消费确认后的自动金额，不跨域直接查询另一模块的数据表。两处自定义额和各自备注独立保存，特殊费用是当月发生额，大表是截至该月最近一次额外金额；0终止旧值带入。
- 特殊费用用油联动采用稳定业务身份，不能靠可改名称识别既有手填项，也不能把旧完整金额直接当新自定义额。旧值先生成原总额、自动部分和候选差额的核对清单，确认后转换。
- 操作人、版本冲突、操作历史和跨页刷新复用现有机制；账户、卡片、账务、分配、自定义额及备注的更正接入安全撤销，文件副作用不假定能由数据库撤销自动重建。
- 前端复用现有页面注册和账号工作区；2026-10-31用户经对照后选定现有AG Grid，Univer不进入正式选型。逐列编辑、日期与文字并存、表内新增草稿自动入账、独立次级转账按钮及档案行内维护已归[油卡需求](../../docs/requirements/oil-cards.md)；优先复用项目既有能力与成熟组件，不为整块操作重造编辑引擎。主副卡信息、独立备注、累计/月份及筛选/全量导出口径也归需求，布局归[界面简报](map.md)。保草稿和未知回执保护，不新增自写跨格键盘模式。两处用油自定义金额及备注集中在油卡页维护，原特殊费用和会议大表消费联动结果，按需求退出原总额直接编辑入口。
- 充值与发票同页左右均分，两表独立操作；筛选采用需求已确认的即时勾选、日期树、数值候选及关闭规则。优先复用项目既有能力与成熟组件，布局沿付款通知书页的现有适配方式，不增加临时展开单表模式。
- 表头筛选作为可复用模块提供小接口，列取值、字段类型与状态归调用页面配置，不依赖油卡字段、业务接口或账务公式；充值和发票为本期实际消费者。先借鉴既有表格、筛选及成熟组件的能力，保原生列定义、列宽恢复和各表独立状态，不重造表格引擎或描述语言。其他页面后续可按需接入，本期不扩大为全站推广。当前勘查未发现必须先做全站重构的前置，必要的局部准备在对应首个真实功能票内先做。
- 初次接续单独核对来源、有效范围、归属和期初；原始行保留可追溯身份。未知日期保持未知，未确认映射不猜配；已有PDF补关联不重记金额。持久归档及备份需覆盖数据库索引和原件。

## Testing Decisions

测试边界沿用用户已确认的“后端业务验证＋页面/导出代表路径”。优先从油卡业务服务/API这一主接缝验证输入、保存回执、查询及报表可见结果，不为每个内部辅助函数另建测试面，也不按用户故事数量机械增加用例。

- 账户、卡片和账务：在隔离数据库验证同卡多账户、历史归属保护、归档退出候选、人工补挂和重新启用；按本轮收束后的口径检查统一金额、调拨和公司合计，不验证内部表布局或函数名。
- 发票流程：从接收入口验证识别、确认、归档及账务结果；覆盖跨批次去重、同票冲突、一票多分配合计、原子失败、未知回执与中断续办。下载适配器使用受控输入验证响应处理；另用有效交付链接验证当前真实下载能力，两种证据分别记录。
- 用油派生：组合验证月度与累计、含往年、未来月排除、自定义正负/零以及金额和备注一起带入。原有费用历史检查中已有真实事务撤销、空/零/负数和跨年范围的先例，可复用相同隔离与断言方式。
- 页面和导出：正式接入后使用现行真实可丢弃副本入口，核单格与多格编辑完成后自动保存及读回、异常待确认，以及筛选后合计与全量台账实际下载；导出值与其明确范围的权威业务结果核对。隔离交互原型只比较组件操作，不替代这些业务验收。大表已有成品工作簿和值断言的先例，沿用真实出口而不检查源码形状。
- 首次接续：以四张活动表和已有PDF作本机只读核对样例，验证范围过滤、期初标记、已有开票补关联及旧总额候选差额。保护业务原件，真实接续前交付核对表，不把隔离样例通过写成生产接续已完成。
- 归档和恢复：核规范文件名、原件可取回、同票冲突保护以及备份同时包含账务索引和原件；不把短时下载缓存当作永久档案。

金额验收样例均为合成数值：

1. 已确认统一金额样例：起始数0，充值10,000、调整增加200、开票3,000，核对显示充值10,200、开票3,000、差额7,200。
2. 已确认报表样例：无更早数据，本月充值含调整为10,200、特殊费用自定义50、大表额外自定义1,000时，特殊费用10,250、会议大表11,250；开票不冲减这两个结果。
3. 按确认公式推导的跨月样例：次月充值发生额4,900、特殊费用自定义-20、大表额外值未修改，当月特殊费用4,880、截至该月大表16,130。将该月大表额外值改为0后为15,130，后续继续沿用0。
4. 转账成对保持：任一侧更正日期/金额后两侧一致，归属更正只改变对应一侧，撤销不能留下单边账；类型不可自由切换。
5. 发票分配样例继续有效：一张10,000元发票分配甲6,000、乙4,000；重复处理合计不变，分配合计不等于10,000或保存失败时不留下半份账务。
