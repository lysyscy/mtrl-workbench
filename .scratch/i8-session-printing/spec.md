# 工作台 i8 会话统一与付款通知书批量打印

2026-11-20 · [TAIL-503](../tails/issues/TAIL-503-i8会话统一与通知书打印规格.md) 的共同规格。业务口径来自本次访谈。源码盘点基点为 `271fc440cd10e9fe9720c68f0a6c237247113cad`，登记时远端主线为 `86bf7df6b856d8aaffd29edf0f311c57091ed08e`。实施时核对实际集成基线。

## 问题

材料工作台已有 i8 浏览器会话通道，但各操作对它的使用不一致。付款通知书的批量打印和「只导出 PDF」绕过当前会话选择，会直接登录 i8，遇到在线冲突时可能顶掉浏览器里的会话。已经使用浏览器通道的入口，目前在首次连接或换标签时也可能要求用户到 i8 页面点击扩展，再回工作台点连接。

2026-11-20 的一批 35 张通知书执行期间发生了 i8 强踢。工作台记录 19 张获 IPP 接收、16 张在 Windows 打印环节失败。后者的回执只保留 Windows 错误，丢失了前一档 IPP 失败原因。用户还观察到部分单据使用 A3。PDF 渲染设置为 A4，IPP 投递未指定用纸，设备留存的相关作业只标记默认纸型，具体 A3 作业与触发条件未验证。

## 方案

统一材料工作台和浏览器扩展的 i8 会话选择与连接流程。用户正常登录 i8 后，工作台默认在需要时自动使用浏览器已有会话。连接有阻碍时，界面显示需要的动作，并在动作完成后自动接上。直连由用户主动选择，顶号只在本次操作遭遇在线冲突且用户明确确认后执行。

付款通知书先准备整批 PDF，再按 A4 投递。弹窗实时显示准备和投递阶段的计数，异常单据可由用户决定重试或移除。进入投递后，服务继续处理原批，刷新页面可查原批进度和逐张回执。

## 用户场景

1. 作为工作台用户，我希望所有实际访问 i8 的操作使用同一处会话选择，以便我能预期每次取数怎么连接。
2. 作为平时已经登录 i8 的用户，我希望默认复用这个网页登录态，以便继续使用原来的 i8 页面。
3. 作为已安装并授权扩展的用户，我希望点抓取、打印或导出时自动连接，以便省掉日常点扩展和点连接的步骤。
4. 作为同时打开同站多个 i8 标签的用户，我希望工作台自动选一个可用页面，以便省掉为同一个登录态反复选择标签。
5. 作为暂时没开 i8 页面的用户，我希望发起操作时在后台打开配置的 i8 页面，以便继续留在工作台。
6. 作为打开工作台时扩展尚未获准访问 i8 的用户，我希望知道在哪里完成授权，以便恢复自动连接。
7. 作为需要在 i8 登录或点击扩展的用户，我希望工作台自动检测操作完成，以便返回时直接看到连接结果。
8. 作为临时断网或遇到标签休眠的用户，我希望工作台自行恢复可用的浏览器会话，以便减少重复设置。
9. 作为等待连接的用户，我希望看见当前在等什么，并能取消等待，以便改变主意时停止本次操作。
10. 作为已经确认操作的用户，我希望连接就绪后自动开始一次，以便少点一次确认。
11. 作为发出操作后遇到页面刷新或网络中断的用户，我希望先取得原请求的状态，以便避免重复提交。
12. 作为主动切到工作台直连的用户，我希望仅在 i8 报账号已在线时收到顶号确认，以便判断是否让原会话下线。
13. 作为拒绝顶号或取消当前操作的用户，我希望浏览器里的在线会话继续可用，以便当前操作安全结束。
14. 作为付款通知书操作人，我希望打印和 PDF 导出都使用当前会话读取版式、详情及签名，以便两种操作遵守相同的会话选择。
15. 作为发起批量打印的用户，我希望先看到待打印的范围，再看到「准备 PDF 19/35」一类的真实进度，以便知道当前做到哪一步。
16. 作为准备阶段遇到会话断开的用户，我希望看到中断原因和「已投递 0 张」，以便重连后决定如何重新发起。
17. 作为遇到一张异常单据的用户，我希望看到单号和原因，并能重试全批或移除该单后再确认剩余批次，以便正常单据可以继续办理。
18. 作为打印付款通知书的用户，我希望每份作业明确要求 A4，以便出纸尺寸符合要求。
19. 作为当前打印通道不能保证 A4 的用户，我希望在出纸前停下并看到换通道或导出 PDF 的选项，以便自行处理。
20. 作为打印已经开始的用户，我希望弹窗显示「投递打印机 6/35」一类的真实进度，以便区分准备与出纸请求。
21. 作为刷新工作台的用户，我希望回到原批的进度和回执，以便知道每张单据处于什么状态。
22. 作为需要补打的用户，我希望区分打印机已接收、明确失败和结果待核实，以便只对核实需要补打的单据重新发起。
23. 作为仅下载 PDF 的用户，我希望看到生成结果并在下载失败时重试下载，以便已经生成的文件可以直接取用。
24. 作为排查打印故障的人，我希望回执留下投递通道、可得的作业号和各次失败原因，以便对照工作台和打印机记录。

## 实施决定

### 共用 i8 会话入口

- 工作台凡是实际向 i8 发出业务请求，都通过同一个服务端会话入口解析模式并创建客户端。覆盖通知书取数、打印和仅导出 PDF、常用项目和仓库查询、库存、收发结存、机械费、采购合同和应付及其关联流程，以及其他同类既有入口。读取工作台本地台账、配置和执行记录沿各自的本地接口。
- 默认选择「浏览器已有会话」。缺会话模式或模式无效的业务请求由服务端提示刷新或重新选择，不能沿旧默认进入 HTTP 登录。选择浏览器模式后，连接、登录或目标站点异常均由该模式处理，直连要由用户主动切换。
- 工作台直连沿现有规则复用本人独立会话。i8 明确报告在线冲突时，工作台先暂停本次操作，再由用户确认「让现有会话下线并继续」。确认限定当前工作台身份、i8 站点、账号和这一项操作，只可消费一次。业务接口自带的允许强踢参数不能替代这次确认。
- 保留工作台的账号绑定、站点核对、分页和各业务原有的范围确认、读取与采用边界。浏览器通道在已授权的 i8 页面使用原有登录态，凭据和 Cookie 留在浏览器，扩展只搬运获准的只读请求和响应。放行签名图时依现有 i8 契约验证来源、路径与响应类型，保留两侧的请求限制。

### 自动连接

- 扩展授权范围限于工作台配置并核对过的 i8 站点。安装或更新时可完成浏览器要求的授权；已有所需权限时，扩展可以自动发现可用标签。设定不同 i8 站点后按新站点的授权和会话重新连接。
- 本轮按同一浏览器用户配置、同一配置站点只有一个 i8 登录态设计。同站多个标签按同一登录态处理，自动选可用标签。无需额外选择标签、确认登录账号或打开账号菜单。实际使用的账号及组织由浏览器当前 i8 登录态决定，工作台本地配置不充当账号核验结果。
- 发起操作时如果找不到匹配标签，在后台打开配置的 i8 页面，保持工作台焦点。复用现有查找、连接和恢复生命周期，等待页面可用；并发等待共用连接尝试，避免同一次等待反复打开页面。
- 权限未授予、登录过期或浏览器只能提供点击扩展的授权方式时，当前操作显示具体指引。等待期间观察授权、标签与连接状态，在用户完成操作后自动继续连接。连接到正确站点和可用登录态后显示就绪。工作台在这个过程只复用或等待用户建立正常登录态。
- 等待绑定到当前已确认的操作和范围。关闭弹窗、取消、切换模式或切换身份使等待失效。仍有效且尚未发出请求的操作，在连接就绪后提交一次。请求已经发出时，恢复通道只用于核对原操作及结果，业务入口不能把恢复事件当成再次提交。

### 批量打印与 PDF 导出

- 用现有通知书勾选规则确定范围，确认时冻结本批单据集合。准备阶段按 i8 版式取版式、单头、明细、流程和签名图并生成 PDF，整批准备完成后才允许投递。浏览器会话失效等整批错误须穿透逐单容错和签名图片处理，保留实际停止原因。
- 正常留白沿既有 i8 版式及流程规则解释。应取得的资料或签名无法取得时，指出异常单号与原因，准备阶段已投递数保持为零。用户可重试原范围，或移出异常项、重新确认剩余集合后继续。发现批次范围变化时以新确认的范围为准。
- 弹窗将「连接 i8」「准备 PDF」「投递打印机」显示为实际阶段。准备和投递各显示当前完成数及总数，失败显示阶段、单号、原因与可采取的下一步。「只导出 PDF」共用 i8 取数及制单，并沿用逐单生成和下载结果的现有规则。
- 投递前锁定当前批次采用的通道和 A4 要求。能明确设置 A4 且支持该设定才可开始。若当前通道无法确认 A4，暂停投递并提供切换到支持 A4 的通道或导出 PDF 的选项；PDF 页面的 A4 设置和设备此刻的默认纸型都不能代替投递请求的用纸约束。自动分流也须遵守该条件。
- 服务为已开始的批次和逐项投递保留稳定标识，工作台刷新后查询同一批。已进入投递的批次由服务处理，页面刷新不会启动另一批。服务或网络异常导致状态未知时，先查询原批和设备。用户核对结果后决定需要补打的范围。
- 回执区分「打印机已接收」「明确失败」「结果待核实」。只有设备提供进一步证据时才显示出纸完成。记录每个通道的投递结果和可取得的打印机作业号；后续通道发生异常时保留之前的失败依据。对可能已经被设备接收的作业禁止自动换通道重投。

## 验收与测试决定

优先从工作台真实入口发起操作。使用已登记的隔离工作台、带扩展的测试浏览器、模拟 i8 和可观察的打印机替身，核对页面反馈、真实业务请求次数、投递记录与刷新后的回读。复用已有浏览器会话和抓取入口回归、扩展浏览器样机、打印分流、签名和回执测试。只有高层验证无法稳定构造的故障分支才单独补充检查。

| 验收入口 | 代表场景与结果 |
| --- | --- |
| 现有通知书抓取入口 | 已登录且授权时，首次从工作台发起即可抓取。配置站点已有多个同站标签时无需选择。没有匹配标签时只在后台打开 i8，工作台仍有焦点。检查扩展按交付权限行为运行，样机只用额外测试权限选标签不足以证明免点击。 |
| 同一抓取入口的等待与恢复 | 模拟缺权限、需要点扩展、i8 登录过期或断开。页面显示与原因匹配的指引，完成后自动连接并发出一次已确认的请求。关闭等待窗口后迟到的就绪事件不会发单。已发出的请求遇断线或刷新时，只读回原结果。 |
| 共用入口和其他 i8 操作 | 核对所有实际向 i8 发请求的入口都进入同一策略。覆盖缺失模式、浏览器失效、主动直连及在线冲突，核对未经确认的强踢次数为零。确认后只对原操作执行，拒绝、取消或过期后不能沿用这次确认。业务原有的范围、权限、采用与本地写入条件继续验证。 |
| 通知书「批量打印」和「只导出 PDF」 | 让一批中途取签名失败和会话失效，确认停在准备阶段且实际投递为零。证明正常留白未被误判。移除异常单并重新确认后，核实仅准备并投递确认的范围。导出验证 PDF 可用及下载重试期间投递为零。 |
| 批量打印和 A4 | 用能检查请求的设备替身证明准备完成前没有投递，发出的每份打印请求明确要求 A4。构造 A4 不支持或无法确认的通道，证明零出纸请求、弹窗可切换通道或导出 PDF。 |
| 批量打印中刷新 | 投递进行中刷新，查询同一批，仍能看到原进度和逐张回执。分别模拟明确拒绝、设备接受、响应中断后的状态未知及后续通道异常，核对状态和各次原因，确认未重投已接收或待核实的作业。 |

隔离验证结论与现场验证分别记录。真实 i8 登录或抓取、实际出纸、生产发布与扩展正式加载，按项目既有授权和验证入口进行。现场核验以实际请求、回执或纸面证据为准。

## 范围外

- 分公司独立收发结存 EXE 和独立诊断脚本。
- i8 自身登录流程、账号管理、签名模板和通知书业务格式重做。
- 对历史 A3 单据逐张补录纸型、历史批次重新投递、补打或部署操作。

## 补充

- 复用目前的工作台会话提供者、扩展通道和后端客户端工厂。浏览器能否免点扩展取决于目标站点权限及当前登录态，首次授权、需要用户登录和临时权限指引均纳入实体验收。
- 此规格持有新增与变更的业务口径。实施时同步 i8 契约及通知书打印正文中关于手选标签、缺省直连、强踢和纸型的旧描述，并以集成验证确认生效。
- 同日理光设备的只校验请求已接受显式 A4，校验本身未创建打印作业。历史作业已知的仅是接收、完成或取消等留存状态，缺少涉及 A3 单据的实际纸型及纸盒证据。
