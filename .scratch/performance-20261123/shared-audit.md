## 本轮对照和反例

固定基点 `c2208bcb`，生产构建目录 `flow-doc-text` 与 `shared-final-091` 的 Vite manifest SHA-256 前 12 位分别为 `05710a26dc79`、`10e822459dd9`。同一台 Windows，Chromium 159，1440×900，CPU 降速 2 倍，MiSans，新建浏览器 context，拦截全部网络，仅放行固定本地夹具。测试金额读回及导出请求均由拦截器回答。原始报告在本机性能工作树 `.artifacts/runs/perf-study/reports/`，脚本、构建与夹具在同组 `work/`。浏览器时间含业务代码、框架及绘制等待，不作现场 INP。

先输入「合成供方1」，等该结果和表尾发布，再输入「合成供方17」。记录输入事件至第一帧、正确结果就绪和期间最长帧。两轮不加计数探针；另外用同一浏览器入口观察 `toLocaleLowerCase` 调用，区分少做的实际工作与整页时间波动。

两组均核了五个落点的命中数、实际挂载 ID、行高、列宽及固定表尾。另一次改成不相关词再清空，两个版本分别回到完整 5,000 和 1,543 行；计数探针中清空时两版的归一调用完全相同，不能把清空时长的波动归给缩查。候选只保存当前业务范围和上一结果。缩小、扩展、空结果、换词、清空、全命中引用、新行集与新展示字典由 `grid-search.test.mjs` 覆盖。搜索时钟仍归原入口。

回包反例在真实页面先锁定关键词，再离开、挂起返回时的 GET 并替换响应。通知书保持同一批 ID，只改变两行的供方，从选中 ID 1 改为 ID 2；集采合同主行未变，只对调项目显示名，旧、新各有 37 行且 ID 集不相交。流水继续验证读回改变同 ID 供方、中文组字、导出 ID 与重置。通知书组字期间金额和导出动作保持锁定，集采另验日期两种写法、未确定金额、换账号、草稿和未知写入后的读错重试。本地证据为 `ui-common-*-search-base.json`、`ui-final-*-search.json`、`ui-common-counts-*.json`、`ui-final-notice-reread.json`、`ui-final-contract-dictionary.json` 等。

### 同一单格变动的字宽

付款弹窗的固定列按选中行、应付覆盖、字号和字体就绪周期复用。当前输入文字及格式化表尾单独测量；输入不合法时表尾仍为“待核对”。草稿合计按当前行显示的输入依次验证并以整数分相加。96 行逐键输入两次，原来每键测量 113 次，其中 96 个是未变的单号；最终每键 5 次，其中单号 0 次。按最终版、基线、最终版交错复测，基线两键首帧 55、54 ms，最终两轮 50/48、42/38 ms；较早仅换缓存的交错样本耗时区间交叠，稳定收益是测量量下降。备注输入两版都没有字宽测量。结果仍挂载完整 96 行，合计 9,450.15；十列宽度逐项一致。

### 回页为何没有统一套用分段补丁

同一交互先挂起首读、离开、隐藏期间送回数据，再从侧栏返回。首反馈取选中导航可见的第一帧，完整就绪要求目标表实际可见、数据行挂载且尺寸发布。带阶段标记的独立构建只用于定位；以下配对耗时来自无标记的两版。

| 同机交错对照 | 导航首反馈 ms，前 → 后 | 完整就绪 ms，前 → 后 | 最长帧 ms，前 → 后 |
|---|---:|---:|---:|
| 25,200 行付款流水 | 60 → 65 | 1,468 → 1,605 | 639 → 751 |
| 5,000 张通知书，4,826 条当前行 | 355/355 → 350/374 | 1,509/1,523 → 1,488/1,558 | 355/355 → 350/374 |

流水剖析的一次样本在点击后 96 ms 进入字体准备，到 1,224 ms 完成首轮行高计算与应用，接着又进入一次尺寸准备；其中包含文本提取、单元格尺寸计划、canvas、DOM 和行高应用。通知书的另一次剖析最长帧 554 ms 出现在路由返回前段，直到 1,230 ms 才进入表格字体准备；后续还需测量带控件的单元格。改变规划循环只覆盖其中一部分。样本波动显著，通知书最终版另有 3,502 ms 就绪/1,129 ms 最长帧，保留为较差样本。流水从 304 行清筛回 25,200 行仍可出现数百 ms 长帧。两页均没有得到可归因的回页改善。输入指纹、按帧时间、导航与就绪及范围见 `*paired-*.json`、`*audited-*.json`、`*final-*-return.json`、`*shared-*-profile.json` 和 `ui-*-flow-clear*.json`。

### 暂留和整合边界

- 旧的分段排版、隐藏页延迟建表补丁均未应用。前者还需区分为何一次回页准备两轮、哪次宽度或数据真正改变，并验证中断、焦点和最终就绪；后者的首页收益要单列立即回表代价。
- 列宽与行高是不同机制。共享行高快速复用原已比较换行文本；富内容的标签、撤单原因、关联按钮或跨度，有可能在基础文字相同时改变几何。这是源码审查线索，尚缺同 ID、同范围下旧高度与重新挂载高度的实测反例，本次未改该判断。
- 通知书粘贴后仅显示已剔除/已撤单 ID 的 `pasteScope.includes`、批量读取中若干 `IN`（付款核对/撤销）及集采右侧纵滚均未证明同一迁移有净收益。前两项需要真实范围分布的隔离计时；纵滚需兼顾跨屏选区，不以全量取消挂载换数字。
- 已有项目验证指南在既有浏览器章节补一段普通改单格、清筛、隐藏到数回页的检查。未改变正式数据库、设备预览、全局技能或服务。此轮界面结果证明合成条件下的使用路径；上一轮的隔离 PG、真实 XLSX 依据沿用[原进度](progress.md)，未重跑正式业务。
