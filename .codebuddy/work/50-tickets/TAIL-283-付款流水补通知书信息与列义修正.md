# TAIL-283: 付款流水页补通知书信息，兼修「操作人／流水号」两处列义

**What to build:** 付款流水那一页光看现有九列对不上账 —— 补上这笔流水**来自哪张付款通知书**的几件事：通知书日期、通知书名称、收款单位、审批金额、分类（辅材/机械/集采）。同时把两处**一直在骗人**的列义改对：「操作人」现在显示的其实是创建时间，「流水号」现在显示的其实是数据库行号（真业务流水号在库里、导出却在用行号）。页面看到的、Excel 导出的、搜索匹配的必须是**同一个东西**。

**Blocked by:** None (can start immediately) —— ⚠️ 与 `TAIL-281`、以及在办的 m11/m05 壳改动可能同文件（`shell/core.js`、`shell/proj.js`、`index.html`、`shell/pages-a.js`），开工前先确认它们的处置，避免两批差异混成一票。

**Status:** ready-for-agent

- [ ] 五列上身且**一条流水一行、批量取数**（复用 `build_flows` 已预读的 notices 字典 ⇒ ⛔ 不许逐行查库 N+1，⛔ 不许依赖前端 `NO` 缓存有没有载入）：通知书日期（`doc_date`）· 通知书名称（`fields['BillName']`，与通知书列表同一取值口径）· 收款单位（`payee`，⛔ 不许拿集采供应商替代）· 审批金额（`amount_approved`）· 分类（沿用既有中文类别出口，⛔ 不另造枚举）。
- [ ] 「操作人」列显示 `created_by`（不是 `created_at`）；旧记录缺操作人**如实留空**；页面与 Excel 同义。
- [ ] 「流水号」列、关键词搜索、Excel「流水号」列三处都读**真 `flow_no`**；撤销按钮与 `export_flows(ids)` 的定位**仍是数据库 `id`**（⛔ 不许把文本 `flow_no` 当接口 id）；旧流水 `flow_no` 为空时给稳健显示（留空或经测试确认的回退），⛔ 不编造编号。
- [ ] **合计只加实付金额**：审批金额在同通知书的每行重复显示供对照，**不纵向求和**（1000 审批 + 两笔 300/200 ⇒ 合计 500，不是 2000）。
- [ ] `notice_id` 为 NULL 或通知书已失联的流水**照旧能查**（⛔ 不许被内连接过滤掉），新列留空或「—」，⛔ 审批金额未知**不伪 0**（别用 `numOr0` 糊过去）。
- [ ] 已撤销流水在「全部／已撤销」可见并带原因，不进生效合计；历史导入的空付款方式**保持不变**（⛔ 不兜底成「现汇」）。
- [ ] 页面结构跟着改全：`FL_THEAD` 表头 · 每行 `<td>` · 合计行（**金额列下标不再写死 4**）· `sumRowOf` 的 leadSpan · 空态 `EMPTYROW(thCount(...))` · 宽表横滚与固定列仍对齐。
- [ ] 新增金额列按**数值**排序（⛔ 不许字典序 `100 < 20`）。
- [ ] 导出与页面一一对应：仍只收**当前可见流水的数据库 id 顺序**，列头/字段/`MONEY_KEYS` 同步，金额是数字而非文本；补**逐格** Excel 测试（⛔ 不得拿 `test_tail04_export.py` 冒充 —— 那是收发结存/库存导出的）。
- [ ] 站点回归：`test_acc_flow_list.py`、`test_acc_flow_pst.py`、`test_wired_m05.py`、`test_page_m05.py`、`test_tail04_pages.py`、`test_shell_render.py`；「付款统计/欠款/多笔付款撤销」行为一律不变。
