## 范围与依据

[用户] 一人练手项目，优先开发速度与维护成本。本阶段只诊断、design、开票，下一轮串行实施；不修改产品、业务库、启停服务或推送。HEAD 019263e 的基线见 `.codebuddy/work/30-troubleshooting/实验-首次载入性能基线-20261012.md`。

测得第 5/6/7/8 页首次 546/3587/2770/1756ms。主因证据集中在库存全量 ORM、11.36MB 载荷，以及第 6/7 页多余依赖；同步 render 不是这四页当前最大的耗时。优先做下列三个可独立验收的切片，所有速度变化实施后复测，不订未测的倍数目标。

## 一、共享库存瘦读（TAIL-314，首批）

收益覆盖 m08 库存、m06 矩阵、m07 大表 / 提取，成本低–中。代码入口：`backend/app/mod08_inv/repository.py` 的 list_details / load_rows / to_row；`backend/app/mod08_inv/service.py` 的读端口；`backend/app/mod07_setl/inventory_extract.py` 的 load_amounts。

新增或收敛**明确的只读结果投影**：规范库存行只取消费者用的列，不物化 raw / created_at；提取只取原单入库四字段，复用 extract_amounts 分类与金额规则。经 mod08 数据主人出口供报表使用，保持既有完整 ORM 读取入口给真正需要 ORM / raw 的消费者。不要全局默认 defer 后让未知消费者触发逐行补查。

查明真实消费者后在单次请求内复用 adjustments 映射，去掉 api_inventory 的二次查询；小表重复仅顺手做，不开额外抽象。输出行序、JSON 形状、Decimal 精度、调整单字段与 count / projects 保持。

实测原型支持投影方向，但只是单进程对照；写接口、导出、抓取原始留存没有原型覆盖，须定向验证。m08 暂时仍全量载入，JSON/gzip与传输成本仍在，不能声称这张票解决全部首次等待。

## 二、过程资料自己取矩阵与差异（TAIL-315，依赖314）

收益高，成本中。入口：`backend/app/mod06_proc/service.py` 的 _load_report_data / _matrix_for / build_matrices；`backend/app/mod06_proc/domain.py` 的 build_matrix / diff_rows / diff_totals；`backend/app/web/shell/core.js` 的 reloadProc / PAGE_LOAD / 写后 reload；`backend/app/web/shell/pages-b.js` 的 procRows / procAgg；`backend/app/web/index.html` 的 V.m06。

一次请求内按仓库分桶库存、机械、有效历史，分别传子集给原矩阵函数，避免 15 仓库 × 原始/调整重复扫全量来源。保留完整有效项目候选与全部矩阵，不引入每项目缓存或懒加载协议。

matrix 响应同时给各项目页面所需的差异明细 / 合计，复用已有 diff_rows / diff_totals（单据差异，区别于导出的逐月差额表）。差异保持数据库 id、原值、调整值、差额、备注、操作人、时间及精确跳转原单能力。前端接该来源，解除 m06 对库存全量 payload 的依赖。机械 labels / sections / 录入动作仍需要的轻量 mech 路保留。

移除 m06 对“收发结存与大表”的加载依赖：当前 V.m06 矩阵已吃 PROC_MATRIX、差异吃 IVs，未发现 WHM / BIG / EXTM 的页面消费者。实施前核验所有 m06 BIND、批量导出与写后读取；不可只改 PAGE_LOAD 后空差异或将未加载当成零。不得改 index.html 切片而不核对原型约束；按实际需要在适配/BIND层接线，允许必要最小视图改动并同步对应判据。

[推断] 该切片有机会去掉 m06 的 11.36MB 库存传输与约 1.1s 大表第二组等待，但没有在运行页面实施对照，不能保证具体总耗时。

## 三、大表不预拉无消费者库存（TAIL-316，依赖314）

收益高，成本低。入口：`backend/app/web/shell/core.js` 的 PAGE_LOAD.m07 / LOAD_DEP / reloadM07；`backend/app/web/shell/pages-b.js` 的大表机械、提取与渲染；`backend/app/mod07_setl/api.py` / big_service.py 的读输出。

核验消费者后仅摘掉 m07 的“库存单据”依赖，让小体积 settlement / big / extract 在机械屏障满足后读取。当前提取已由后端从原单入库派生，页面用 EXTM / EXT_ANNUAL / EXT_TOTALS；未发现 V.m07 直接消费 IVs。保留机械6列：大表机械列仍从 MACH6 派生，不能因后端 big 有自动列就直接砍掉。

保留结余、年度筛选、机械及主材累计、手填带入与项目集合/顺序；不将屏幕全部迁移为后端 big.rows，不合并接口，不跨请求缓存。m05 的付款域屏障不动。此票与315没有业务前置关系，但改同一壳文件，按用户要求串行。

## 必须保持与验证

业务主人：`delivery/材料科业务全流程说明书.md` §5.2.3–5.2.5 / §5.3.3 / §5.7 / §9.2；对应 `delivery/PRD/02-功能规格/MOD-06.md`、`delivery/PRD/02-功能规格/MOD-07.md`、`delivery/PRD/02-功能规格/MOD-08.md`。以现行说明书与代码为准，旧注释里“截止月禁止手录”等已不适用。

- 差异跳转按数据库 id 定位，可返回/清筛选；导出逐月差额与屏幕单据差异保持各自语义。
- 逐路容错、PENDING清理、失败点名、重试恢复保持。既有 LOADED 重复进页复用、全局写后标脏与真实状态 reload 保持；i8 执行记录 ALWAYS_FRESH 不动。
- TAIL-313 的90条合同日期保护、168份合同与集采金额/发票/付款/原始数据不在任何票的写入范围。

每票：按真实消费面选测，不跑全量回归或变异；业务反例在 mtrl_workbench_test 回滚隔离，禁止普通测试误连业务库。314比对完整规范读结果（含有调整/无调整、入/出、JSON原始留存消费者）并确认没有 deferred N+1；315比对原始/调整/单据差异/导出、历史与库存来源、空/零、机械写后刷新及精确导航；316比对三个报表页块、年度/月份与项目顺序及失败重试。

实际服务验证只能在父对话另行安排加载当前代码后做；本阶段没有重启授权。复测保持本轮浏览器条件，记录首次、重复、刷新后，GET 数 / 载荷 / 失败与同步 render；速度下降要有同条件证据，不能只验字段相等。无需独立二次全面审查。
