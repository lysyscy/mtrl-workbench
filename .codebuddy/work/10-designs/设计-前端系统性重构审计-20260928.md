## §一 一句话结论

**前端不是"某个页面有问题"，是五笔系统性债（见 §三）**：① **一件套 4000 行**（`index.html` 里 CSS ＋ HTML ＋ 内联脚本混装，壳合计 **9784 行**）；
② **同类东西各写一遍**（`<table>` 44 处只有 5 页走公共表格件 · 展开区 21 处 · 弹窗 46 处 · `toast` 301 处 · 内联样式 **577** 处）；
③ **交互形态四种并存**（共用面板 / 原生 `select` / 弹窗 / 内联展开区），且"点开自己不变样"这类反馈缺失（2026-09-28 一天就修了两处）；
④ **判据很强但维护靠手工**（603 判据点 · 20 真机段 · 86 突变件全绿 —— 代价是每改一页要手写一堆断言，`U1` 登记簿是一本 **488 行**的活账）。

⭐ **判据这一层不用重做**（它是本仓最强的资产）；要重构的是**壳的结构与模式层**，而**判据正是这件事的安全网** —— 所以顺序必须是：**先抽公共件（有判据兜）→ 再统一交互（真机兜）→ 最后才碰版式**。

## §三 五笔系统性债（症状 → 证据 → 代价 → 手法 → 风险）

### 债 1 · 体量与分层：改一处要翻三个区
- **症状**：`index.html` 一件里同时住着 CSS、HTML 骨架、全部页面的内联脚本。
- **证据**：**3967** 行（2026-09-28 实测；审计当天 3982）· CSS 与脚本在同一文件、内联 `<script>` 起于第 **335** 行。
- **代价**：找"这个类的样式" → 翻文件头；找"这页的渲染" → 翻 2800 行后；**每次改动都在一个 4000 行文件里做字符串手术**（今天两次白屏的根子都在这里：模板字面量与 CSS/HTML 混装，注释写错位置就截断）。
- **手法**：拆件 —— CSS → `shell/app.css`；页面脚本按"域"分卷（⚠️ 但**先立判据**：`syntax_audit` 的 `Q3` 只允许壳目录出现 `<script src>` 登记过的件；`U5` 登记表要同步）。⚠️ **订正（2026-09-28 · 用户裁定 `A` 档 ＋ 开工前量测）**：① **CSS 不是重点** —— `<style>` 只 **296 行（7%）**，体量在**内联 `<script>` 的 3615 行**；② `P2-a` 收窄为 **`A` 档 = 只拆"非切片"那 ≈2400 行内联 JS**（工具 / 常量 / 面板 / 各页辅助 / `BIND`；⛔ **不碰 `V.*` 原型切片** ＝ 计划 §23 口径），拆完 `index.html` ≈ **1600** 行；③ 本行要求的两条前置（件清单自洽 ＋ `Q3` 允许清单）**已具备**（`tools/audit/shell_source.py` ＋ `syntax_audit` 的 `Q3`）；④ ➕ 拆件还有一条**必须**登记的：`main.py` 的**路由**（缺 ⇒ 浏览器 404 ⇒ `ReferenceError` 整支崩，离线看不见 —— 判据 `tests/test_shell_part_routes.py`）。
- **风险**：**高**（拆件会动 `SHELL_PARTS` / `U5` / 全部按行号定位的判据）⇒ ⛔ 必须单独一批、且**先补"件清单自洽"判据**。

### 债 2 · 重复模式：同类东西各写一遍
- **症状**：表 / 展开区 / 卡头工具条 / 空态，每页自己排版。
- **证据**：§2.3（44 表 · 21 展开区 · 46 弹窗 · 577 内联样式）。
- **代价**：**风格漂移是必然的**——2026-09-28 一天里出现的两个真问题（卡头越塞越多、控件离它管的对象越来越远）都是这一类；改一处口径要 grep 全场。
- **手法**：按"出现次数 × 改动频率"排序抽件：① **展开区件**（21 处，今天刚改过 2 处 ⇒ 收益立刻可见）② **卡头件**（卡片标题 ＋ 工具栏分区 ＋ 展开态按钮 `.on`）③ `select` 清点。
- **风险**：中（抽件会让"钉源码形态"的判据假红 —— `TAIL-64` 已经踩过两次，解法是判据改"**委托 ＋ 内核真做事**"两段式）。

### 债 3 · 交互形态不统一：学一种不通用
- **症状**：同一个"选项目"在四处用四种形态（共用浮层面板 / 原生 `select` / 弹窗 / 内联展开区）；"点开的按钮自己不变样"。
- **证据**：`projPanel` 13 处 · `<select` 52 处 · `modal(` 46 处 · `fbar` 21 处；今天修的两处（`ledPjToggle`/`ledExpToggle` 无 `on` 态）。
- **代价**：用户**每页都要重新学**；"看着能点却没反馈"最容易让人以为坏了（守则 §5.5）。
- **手法**：定一张**形态表**（什么场景用哪种形态：选 1 个 = 面板；选多个 = 弹窗；参数 = 内联展开区），然后逐页对齐；把所有 toggle 按钮统一带 `.on`。
- **风险**：低-中（多为显示层，但有"改动用户已接受的形态"的风险 ⇒ 逐页给用户看一眼）。

### 债 4 · 可读性：注释的重量与切片的重
- **症状**：壳里注释密度极高（本仓**特色也是负债**：每个"为什么"都写在代码旁，但切片因此变重、`U1` 漂移面变大）。
- **证据**：`m05` 切片 206 行 / 原型 165 行，其中 **174 行是已登记漂移**（绝大多数是注释与文案）；今天两次重构后 `V.m05` 达 **16.5k 字符**（判据里的切片哨兵当场误报）。
- **代价**：🔸 双刃 —— 保留（新人能读懂"为什么"）vs 精简（切片轻、漂移少）。**判读：保留，但把"历史叙事"下沉到 `journal`/台账，代码里只留"这一行为什么这么写"**（与 `TAIL-133` 的减重同一口径）。
- **手法**：逐页做一次"注释分级"（行为理由留在代码 / 故事与历史指回文档）；⛔ 不是删注释。
- **风险**：低（但会动 `U1` 登记，需逐条审）。

### 债 5 · 维护效率：强判据 ＋ 手工维护
- **症状**：判据点多（603）但**没挂判据的页也真实存在**（`imp`/`set`/`m13` 是 U1 为 0 的面）；`U1` 登记簿靠人工增删；死代码 47 项积着。
- **证据**：§2.4；`imp` 493 行、`set` 203 行却**没有原型可比**（它们的安全性完全靠 `tests/test_imp_*` 与真机段）。
- **代价**：**"判据绿 ≠ 这页合规"**（审计清单 `G9` 早写过），新页尤其危险。
- **手法**：给"没有原型可比的页"补**页级判据**（`imp`/`set` 各挂一组：页级禁用文案 ㉙ ＋ 结构断言）；死代码 47 项按 `W2` 清单清。
- **风险**：低。
