## 三、设计（6 个决定的落法）

### 3.1 门禁抓多宽（`Q1` = 甲）

**只抓"翻账本"（`repository`）**：`app/modNN_xxx/**` 内部 ⛔ 不得 `import app.modZZ_yyy.repository`（`ZZ_yyy` ≠ 自己那个包）。
- `domain` / `models` **照旧允许**（乙案会把 46 处正当引用拖进来 ⇒ 不值）。
- ⛔ **`app/` 顶层不在扫描面**（`core_bindings.py` 是**装配层**，它就是**故意**直连各包 `repository` 的地方 —— 规则 C 只扫 `app/mod*/**`，装配层天然豁免，**不用往名单里塞条目**）。
- ⛔ **自己包的 `repository` 不受影响**（判据要排除"本包前缀"）。

### 3.2 出口的形态（**四条纪律** —— 有条是踩过的）

出口 = 对方包的 `service.py` 里一个**再导出的函数**：

```python
def all_projects(session, **kw):
    """⭐ 包间出口：全部已建档项目。"""
    from app.mod01_projects import repository as R      # ⛔ 每次经模块取，别写模块级别名
    return R.all_projects(session, **kw)
```

| # | 纪律 | 为什么 |
|---|---|---|
| ① | **写成函数**（⛔ 不是模块级赋值 `all_projects = R.all_projects`） | 模块级别名会在 import 那一刻把函数对象**绑死** ⇒ 测试 `monkeypatch.setattr(repository, "xxx", …)` **再也打不着**（2026-09-30 实测：**12 条判据当场红**，症状是 `session=None` 一路传到真查询里） |
| ② | **函数体内 import `repository`**（⛔ 别在模块顶层 import） | 避免 `service ⇄ repository` 顶层互引 |
| ③ | 出参**照实**回（不做形状转换） | 转形是**壳适配层**的活；后端出语义（`mod11_jc/service.py` 文件头那条口径） |
| ④ | ⛔ **不写"只为转手而转手"的出口** | ⭐ **用户 2026-10-02 明确否掉**过这种方案（"逼大家去开个只会转手的窗口 = 把翻账本改名叫走窗口，结构没变好"）⇒ 见 §3.3 的取舍判据 |

**取舍判据（本节的核心）**：**一个出口值不值得开，看"它服务几个调用者 / 有没有第二份重复"**，不看"好不好看"：

| 情形 | 判 |
|---|---|
| **多件共用** ／ **已经有第二份重复实现** | ⭐ **值得开**（出口 = 一处定义） |
| **只有 1 个调用者，且对方只是读一下** | ⚠️ **要辨**：若那 1 处本来就在写"薄名函数" ⇒ 换转发对象即可；否则**优先考虑登记为例外**，⛔ 别为它单开一层 |
| **已登记的设计选择**（有文件头理由 ＋ 单向不成环） | ⛔ **不加转发**，登记为**按设计的例外** |
