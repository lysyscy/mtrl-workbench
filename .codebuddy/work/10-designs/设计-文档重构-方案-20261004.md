## 十一 ⭐⭐ 提案：建"票体系"（＝主文档"清淤"的**结构性解**，⛔ 不是另一件事）

### 1 先纠一条：`work/10-designs` 到底"件件被引用"吗？（本轮自己复量 · 只读）

  **a 活文档**（会被 `T3` 扫的：根 `README.md` / `ops/*.md` / `plans/*.md` / `MEMORY.md`）· **b 纪律/按需**（`细则` / `IDE-细节` / `rules` / `work/README` / `skills`）· **c 留痕**（`journal` / `plans/archive` / `backups`）· **d 工具与测试** · **e 其它 work 件**。
- **结果**：⭐ **12 / 33 件**连一个"活文档 / 纪律档"引用都没有（**纯过程件**）；**21 件**有活文档引用，而**绝大多数那条引用 = 主文档 `§15 §四` 的销号行在写"施工图 = 某件"**。
- 活文档里引用 `10-designs` 共 **59 处**，其中 **50 处集中在主文档**（其余：`README` 3 · `阈值表` 4 · `ops/deployment` 1 · `MEMORY` 1）。

  ⇒ 解法不是"别归档"，是**给一张旧→新映射表**（你已点头 ③）。**你的直觉是对的，是上一轮的口径放太宽了。**

### 2 为什么"票体系"就是①的正解

- **现在**：一张尾巴 = 主文档表里**一行**，而那一行要装下"事项 + 来源 + 不做会怎样 + 落点 + 阶段 + 销号依据" ⇒ `§15 §四` 的已销号行普遍 **1000–2400 字**（字墙的**最大来源之一**）。
- **票体系**：一张票 = **一个文件**（正文自由写、**只追加**）；主文档只剩**一张薄索引**（一行一票：编号 / 一句话 / 状态 / 指针）⇒ ⭐ **字墙从结构上不可能再长出来**（这是**根因解**；§五 甲类的清淤只是**止血**）。

### 3 票体系长什么样（本仓版 · 照参考项目的**形态**，⛔ 不搬它那套 `*.mjs`）
