## 一、用户提出的三条（原话）

1. 「缺**贸易公司发票金额**；贸易公司发票金额**也要进子表**」
2. 「**导入后会怎样**这一行，**可读性太差**」
3. 「**贸易公司名 / 合同日期**这两列应该也是**不写库**，他们**也不用来认行**」

## 二、现状（核过码的事实）

| 列的现有口径（`imp_spec.impacts`） | 实际对不对 |
|---|---|
| 材料名 / 付款方式 / 备注 / 存档 / 存档序号 / 寄回时间 ⇒ 「会写进台账（覆盖原值）」 | ✅ 对 |
| 供应商发票金额 / 贸易公司发票金额 ⇒ 「写进子表（不改合同上的金额）」 | ✅ 对 |
| 供应商合同总价 ⇒ 「只用来对号 … 一个字不改」 | ⚠️ **不全**：贸易公司合同下它**会**被写进「合同金额」（空才填）——2026-09-26 方案② |
| **贸易公司合同总价** ⇒ 「只用来对号」 | ⚠️ 没说清它是**贸易公司合同的钥匙** |
| **合同日期** ⇒ 「只用来认行」 | ❌ **错**：它**不参与对号**；真实用途 = **给新加的发票行当发票日期** |
| **供应商** ⇒ 「只用来认行」 | ❌ **错**：它**不参与对号**，导入**完全不用它** |
| **贸易公司名** ⇒ 「只用来认行」 | ❌ **错**：导入**完全不用它**（用户判断正确） |

⭐ 结论：现有那一行文案**既有说不全的、也有说错的** —— 这正是用户觉得"读不懂"的根因：
一行小灰字里塞了**四种不同性质**的信息（写库 / 进子表 / 当钥匙 / 完全不用），还用了同一套句式。

⭐ 另一件事：**贸易公司发票金额在域契约里是有的**（`FIELD_LABELS` 有它、逐列后果也有它）。
界面上"看不到它"的原因 = **② 这一屏只列「你表里有的源列」** —— 表里没有那一列 ⇒ 它就永远不出现
（用户会以为"系统不支持它"）。

## 三、设计目标（一句话）

**让一个第一次用的人，扫一眼就知道：① 我表里这每一列会被系统怎么用；② 系统总共要哪些列、我缺哪一列、缺了会怎样。**

## 四、屏幕结构（三段，从上到下）

### ① 开头一句（已有，保留）
> 「横看 = 你表里的每一列 · 系统只给建议，选哪个由你定」

### ② 「去向」图例（**新增** · 一条，四类，不啰嗦）

| 标记 | 一句话意思 |
|---|---|
| **写台账** | 会盖掉台账里这一格的原值 |
| **进子表** | 往发票子表里**加一张票**（不改合同上的金额） |
| **当钥匙** | 拿它去**找**台账里那张合同；合同上的原值**不动** |
| **不参与** | 这一列导入**不用**（台账里的值不变） |

⚠️ 颜色只跟语义走（守则 §4「颜色语义统一」）：**写台账=橙**（会改动）· **进子表=蓝**（新增）·
**当钥匙=灰蓝**（只读）· **不参与=浅灰**（无动作）。⛔ 不用红/绿（那是"错/成功"，语义会打架）。

### ③ 逐列映射（**保持既定版式**：源列横排、属性在行上 —— 用户已三次确认）

```
┌──────────────┬──────────┬──────────┬──────────┬─────────┬─────────┐
│  你表里的列   │ 合同日期 │ 材料名称 │ 供应商…  │ 合同总价│ 发票金额│
├──────────────┼──────────┼──────────┼──────────┼─────────┼─────────┤
│ 系统认成      │ 合同日期 │ 材料名称 │ 供应商   │ 供应商… │ 供应商… │
│ 导入到        │ [不参与] │[材料名称]│ [不参与] │[供应商…]│[供应商…]│
│ 去向          │ 不参与   │ 写台账   │ 不参与   │ 当钥匙  │ 进子表  │
└──────────────┴──────────┴──────────┴──────────┴─────────┴─────────┘
```

改动点（相对现在）：
1. **「导入后会怎样」那一行长句 ⇒ 换成 4 个短标签之一**（悬停才给完整一句，含"为什么"）：
   - 合同日期 → 「**不参与**」，悬停：「导入时不用它改任何东西；**新加的发票行**会拿它当发票日期」
   - 贸易公司名 → 「**不参与**」，悬停：「导入不用它（台账里这格由**抓取**写）」
   - 供应商 → 「**不参与**」，悬停：「导入不用它（台账里这格由**抓取**写）」
   - 供应商合同总价 → 「**当钥匙**」，悬停：「正常合同：拿它找台账里那张合同，合同上的数字不改；**有贸易公司的合同**：它会被写进台账「合同金额」（该格为空时才填）」
   - 贸易公司合同总价 → 「**当钥匙**」，悬停：「★ 有贸易公司的合同**用它**找台账里那张合同（合同金额那格是空的，靠它才对得上号）」
2. **必填列**（合同价）在标签旁加一个小「**必填**」角标 ⇒ 缺了当场红字说明（已有此逻辑，保留）。

### ④ 字段清单（**新增** · 解决"缺贸易公司发票金额"）

一条可折叠的「**本系统要哪些列（13）**」，逐行给：**列名 · 你表里有 / 没有 · 去向**：

| 列名 | 你表里 | 去向 |
|---|---|---|
| 合同日期 | 有 | 不参与（发票行日期用它） |
| 材料名称 | 有 | 写台账 |
| 供应商 | 有 | 不参与（抓取侧的事） |
| 贸易公司 | **没有** | 不参与（抓取侧的事） |
| 供应商合同总价 | 有 | 当钥匙（贸易公司合同下会填「合同金额」） |
| **供应商发票金额** | 有 | 进子表 |
| 贸易公司合同总价 | 有 | 当钥匙（有贸易公司的合同靠它） |
| **贸易公司发票金额** | **没有** | **进子表** ⇒ ⭐ **你缺这一列**：有贸易公司的合同，结算按它的发票合计 ⇒ 建议把这一列补进表里（或导完在页面上手工录发票） |
| 付款方式 / 备注 / 存档 / 存档序号 / 寄回时间 | 有 | 写台账 |

⭐ 「没有」的列**不报错**（有些列本来就不需要）—— 但**有贸易公司的合同**缺「贸易公司发票金额」时给一句**提醒**（不拦）。

## 七、能机器判的判据（守则要求"能机器判的别靠自觉"）

1. 去向标签**只许四种**（`写台账` / `进子表` / `当钥匙` / `不参与`）—— 出现别的措辞 ⇒ 红；
2. ② 这一屏**不许出现"认行"**二字（那是已被证伪的说法）⇒ 红；
3. 字段清单必须**列全域契约的全部字段**（数量与 `imp_spec.FIELDS` 一致）⇒ 少一个 ⇒ 红；
4. 「贸易公司发票金额」的标签必须是**进子表**（用户本次报的问题）⇒ 写错 ⇒ 红。
