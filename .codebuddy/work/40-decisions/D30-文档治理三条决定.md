## 〇 · 一句话

**目录不搬、状态不换、机器不自动动手。** 三条都为同一个目的：
把「这份文档过没过期」「还有谁在用它」**从靠回忆变成机器回答**，而「搬不搬」**仍然是你的决定**。

## 一 · 决定一：不搬目录骨架（两轴并存）

**决定**：文档仍散在现有各处，**层白名单与既有尺子口径一个字不改**。
「谁读·何时读」继续决定**目录**（这是本仓现有四层的轴）；「会不会变」决定**状态**（新增的那一轴）。**两轴并存，不换目录轴。**

**理由（2026-10-05 实测）**：
- 你最初想要「根目录只有两个文件夹放文档」。但量出来：**根目录散落 0 件、命名不规范的 0 件、同名标题重复 0 组、路径死链 0 条** ⇒ **"乱"不是真病**。
- 真病是**散**：81 件散在 **12 处**。而收成两个文件夹 = 81 件重归类 ＋ 层白名单重写 ＋ 既有 16 把尺子改口径。
- 参考方法（另一个项目已落地）以「**这句话会变吗**」切分，与本仓的「谁读·何时读」是**不同的轴**，不是同一件事的两种说法。

**代价（如实记）**：目录仍有 12 处，"一眼看全"这件事**没有解决** —— 解决它的是「每条路都有人给入口」，不是把目录压扁。

**什么时候该重新考虑**：① 你仍然强烈想要"打开仓根就两个文件夹"；② 散在 12 处造成的实际成本**超过**一次大搬迁的成本（请量出来，不要凭感觉）。

## 二 · 决定二：保留五档状态词，只补两档判据

**决定**：`草稿 / 在研 / 已定稿 / 已实施 / 已归档` **五档一个字不改**；只给其中**「已定稿」「已实施」两档补上"该不该降"的机器判据**。

**理由**：
- 「已定稿」「已实施」是**本仓独有的两档**，而且它们精确对应"结论已落地、该收起来了"这个动作 —— 那正是 2026-09-22 就写进 `work/README.md` §二、**至今没有判据执行**的那条规矩。
- 换成参考方法的三档（活 / 档案 / 过程件）**会把这个信息抹平**：那三档里没有"已定稿"与"已实施"的位置。

**代价**：与另一个项目的状态词**不一样**，换项目时要重新记一遍。

**什么时候该重新考虑**：若"已定稿"与"已实施"长期**分不出区别**（即两档实际都退化成"已完成"）⇒ 那就该合并，而不是继续各补判据。

## 三 · 决定三：降档只报不动

**决定**：机器**只报**「这份该降档了 ＋ 理由 ＋ 落地位置」，**搬运由你触发一条命令执行**。
搬运必须**可逆**（仓外留原文 ＋ 仓内留索引 ＋ 原文仍可从 git 历史取回）；⛔ **真删必须你点头**。

**理由**：
- 你要的是「**心里有底**」。**文件被自动搬走本身就会让人不放心** —— 尤其你已遇到过"设计件被当死重清掉"（那份《文档重构方案》机器引用 0 被移出仓外 ⇒ 四张票的依据当场悬空，闸门全绿无人看见）。
- 「只报不动」既免掉"判断"（标准是机器给的，不是 Agent 自由发挥），又保留"决定权在你"。

**代价**：多一步你点确认；而且"该降档"这件事**不会自己消失**，黄灯会一直亮着直到你处理。

**什么时候该重新考虑**：如果黄灯长期堆积到"根本不看"⇒ 该考虑**自动搬运可逆那一类**（但 ⛔ 仍不得自动删）。

## 四 · 决定四：与另一个项目只借方法，不搬骨架

**决定**：借它的**两条判据**（① 这句话会变吗 ② 同一句话只许有一个家）与**状态流转思路**；**骨架不照搬**。

**理由**：本仓是 6 处目录 ＋ 16 把尺子 ＋ **交付面当业务唯一真源** ＋ 五批治理票；那套骨架是 4 区域 ＋ 中文目录名 ＋ 另一套工具链。照搬 = 把本仓攒下的机器眼**全部重写**，而收益是"两个项目长得一样"—— **心智一致的价值，低于守卫还在的价值**。

**逐项对照（2026-10-05 实测，不是印象）**：本仓**已领先 5 项**（权威归属表且更强 · 任务单只追加不改 · 废词门禁且是常设 · 记忆分长期与当日 · 制度写成"改完跑哪条命令"）；**换轴 1 项**（本仓四层 vs 参考三层）；**覆盖面窄 1 项**（状态标头只在 work 区）；**缺 2 项**（旧路径→新路径映射表 · 「谁在引用」查询工具）。

**代价**：两个项目**长得不一样**，换项目时要重新认一遍目录。

## 五 · ⛔ 明确不做（写下来，免得下次又被提）

- ⛔ **不收成"根目录两个文件夹"**、不搬目录骨架。
- ⛔ **不换状态轴**、不引 frontmatter（已有更严的一处元信息 ＋ 已有尺子只认那四个词 ⇒ 再加 ＝ 两个元信息源）。
- ⛔ **不自动搬文件**（见决定三）。
- ⛔ **不把「零机器引用」当删除/降档的依据** —— 它只是信号。
- ⛔ **不上 CI**、不引多人协作流程（owner/reviewer/审批）。
- ⛔ **不为了文档而文档**：只长期维护「让未来的你 / Agent 少解释一次、少迷路一次」的信息。
