## 一、用户原话（2026-10-01）

> 「请你审计时先**以使用者的角度**想想，**页面上的文字对业务流程已经清楚的使用者到底是干扰还是指导**」

⭐ 读者画像 = **已经清楚业务流程的人**（本系统就科室 **2 人**，都是一线材料科同事）——
他们**比系统更懂业务**，缺的不是业务知识，是"**这个系统怎么用 / 为什么是这个数 / 点了会发生什么**"。

## 二、判据（一句话）

| 这句在说 | 判 | 例 |
|---|---|---|
| **业务常识**（材料科本来就知道的） | ⛔ **干扰 ⇒ 删** | 「欠款 = 其他支出金额 − 付款」「i8 合同价 = 供应商价」 |
| **系统特有行为 / 后果**（不看就**会做错或会误解**） | ⭐ **指导 ⇒ 留**（能短则短） | 「重抓 i8 / 重导历史**不覆盖**手录值」「有一个非法金额 ⇒ **整批都不写**」「同月+同名 ⇒ **改它**、不是再添一条」「**空格不写**（空 ≠ 0）」 |
| **为什么这样设计**（机制辩解 / 工程理由） | ⛔ **删**（那是答给提问者的） | 「这是旁路载体」「铁律 5/6」「（决策 4）」 |
| **内部编号 / 内部叫法** | ⛔ **删**（守则 §3.1 / §2.5） | `DEV-P-06`、`R8`、`§5.2.5 ③`、"链路 C" |
| **已能从界面看出来的**（表头 / 控件标签 / 颜色标记 / 默认值） | ⛔ **删** | "行数随点随加减""日期必填"（校验会提示）|
