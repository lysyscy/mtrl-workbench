## 裁定

1. **AI 只在"确定性引擎认不出某列"时出场**，且**只出建议**：
   建议一律进「**需你确认**」档，⛔ **永不自动落库**、⛔ **永不覆盖**确定性引擎的结论。
2. **默认关**（配置项 `IMPORT_AI=off`）—— 关了以后**零外部调用**，系统与现在完全一致。
3. **实现走本地模型（推荐）**：Ollama ＋ `qwen3:4b` / `gemma3:4b`（或 `qwen2.5:7b`），
   HTTP `http://127.0.0.1:11434` —— **不花钱、数据不出机器、断网可用**。
4. **失败/超时必须静默降级**回确定性结果（⛔ 不能因为"AI 挂了"就导不了表）。
5. ⛔ **不用免费云端 API 作默认**（理由见下）；若用户坚持，必须：仅在**手工点「AI 帮我看看」**时发送
   **表头名 ＋ 2~3 个样本值**（⛔ 不发整表）、并在留痕里记一笔。

## 为什么不是"统统不要 AI"（原 `D23 §6` 的修订理由）

真文件实测（`识别样本-真实模板-20260922.md`）表明：
- **确定性能吃掉大头** —— `m11` 的两级拼名在真 `.xls` 上 20/19 列全中；
- 但**换了命名习惯的新表会全军覆没**（`m06` 三份真文件全拒，只因为模板里那批列叫「线上入库（不含税）› 主辅材」而不是页面列名）；
- 「补齐别名」能救已知命名，**救不了没见过的写法** —— 那正是"按语义对齐"这件事，是 LLM 的强项。

⇒ 所以立场从"不要 AI"改成"**AI 只能当建议、且必须可关可选**"。

## 三条路线的取舍（2026-09-22 评估）

| 路线 | 花钱 | 数据出机器 | 速度 | 判断 |
|---|---|---|---|---|
| A 纯确定性（别名 ＋ 拼名 ＋ 内容画像） | 0 | 否 | 毫秒 | **必做**（`B1`）· 覆盖真文件大头 |
| B **本地小模型**（Ollama） | **0** | **否** | 1~3 秒/次 | **推荐**：列映射是"分类/匹配"不是推理 ⇒ 4B~7B 够用 |
| C 免费云端（GLM-Flash / qwen-flash / Gemini 免费档 / Groq） | 0 | **是** | 快 | ⛔ 不作默认：财务数据外发 ＋ 限流易变 ＋ 给局域网交付面加外部依赖 |
| D 本地 embedding（bge-small-zh / m3e）做相似度 | 0 | 否 | 快 | 收益有限：只能判"像不像"，**分不清**「供应商合同总价 vs 贸易公司合同总价」这类结构性差异 —— 而这恰是台账里最常见的 |

**资源量级**（本地）：4B 量化 ≈ 3 GB 内存；7B 量化 ≈ 5~6 GB；纯 CPU 也能跑（每次调用数秒），有显卡更快。
调用内容只有**列名 ＋ 2~3 个样本值**（几十 token）⇒ 开销可忽略。

## 按需启动（用户 2026-09-22 追问：「能否只在需要时才启动 AI？」）

**能，而且是三段都按需**（⛔ 不做常驻后台）：

| 段 | 默认做法 | 更彻底的做法 |
|---|---|---|
| **① 调用按需** | `IMPORT_AI=ask`（**默认**）：界面在"有未识别列"时出一个按钮「AI 帮我看看这几列」，**点了才调** | `off`（全关）／`auto`（有未识别列就自动调一次，仍只出建议） |
| **② 进程按需** | Ollama **不设开机自启** ＋ `keep_alive=60s` ⇒ 跑完 1 分钟自动卸载模型（内存释放）；`OLLAMA_MAX_LOADED_MODELS=1` | 由后端按需 `Popen(['ollama','serve'])`，调用后 `ollama stop`；或改用 `llama.cpp` 的 `llama-server`（零常驻，代价 = 自己要带模型文件） |
| **③ 联网按需** | **只有首次拉模型要联网**（1.4~3.3GB），之后**完全离线可用**、数据不出机器 | —— |

## 实机结论（2026-09-22 读取真机 · 不猜）

| 项 | 实测 | 影响 |
|---|---|---|
| CPU | **AMD Ryzen 5 5600GT** 6C/12T（3.6GHz 基频） | 纯 CPU 推理够用（我们的用法见下） |
| 内存 | **16GB · 单条 2666MHz**（单通道） | ⚠️ 单通道是**主要瓶颈**；加一条同规格组双通道 ⇒ 推理约 +30~60%（可选，不必须） |
| 显卡 | 核显（512MB 报值） | Windows 上**核显不参与** LLM 加速 ⇒ 按 CPU-only 规划 |
| 磁盘 | C 盘仅剩 **17.1GB**／**D 盘 171GB** | ⛔ **模型放 D 盘**：`OLLAMA_MODELS=D:\ollama-models` |

**推荐模型**（按本机 · 纯 CPU 估算，一次 = 约 300 token 输入 ＋ 5 token 输出）：

| 模型 | 体积 | 生成速度 | 一次"选列"耗时 | 结论 |
|---|---|---|---|---|
| `qwen3:1.7b` | ~1.4GB | 12~20 tok/s | **2~4 秒** | ✅ 首选（够用、最快） |
| `qwen2.5:3b` | ~2.0GB | 8~12 tok/s | 3~6 秒 | ✅ 更准一点 |
| `qwen3:4b` / `gemma3:4b` | ~2.6~3.3GB | 5~8 tok/s | 6~15 秒 | 可用（疑难列才用） |
| 7B（Q4） | ~4.7GB | 3~4 tok/s | 20~40 秒 | ⛔ 不推荐 |

⭐ **让"无独显"几乎不影响体验的关键技巧**：不问模型"这列是什么"（自由生成，慢且不稳），
而是**给出候选字段清单让它选编号**（输出限 1~5 个 token）—— 上表右列就是按此算的。
这也顺带满足第 2 条硬性：**输出受控 ⇒ 建议不会跑野**。

## ⭐ 实机基准（2026-09-22 已测 · 本机 `qwen3:1.7b` · 素材取自真文件）

**问法迭代了四轮**（每轮都被实测打回，这四条**别重复踩**）：

| 轮 | 问法 | 结果 | 教训 |
|---|---|---|---|
| 1 | 一次问 8 列 ＋ 给 `{"列名": 序号}` 模板 | 0/8，模型把**模板**抄回来（`{"列名": "0"}`） | ⛔ **别给带占位符的 JSON 模板** |
| 2 | 改用"**按顺序输出序号数组**" | 4/8，从第 4 列起**整体错位 +1** | ⛔ **序号编码有歧义**（`0=忽略` 与 1..N 混在一起） |
| 3 | 改让模型**输出字段名** | 1/8，它把**列名**抄回来（镜像输入） | ⛔ 一次给 8 列 × 8 候选 ⇒ 空间太大、只会镜像 |
| 4 | **JSON Schema 约束解码**（`format` 传 schema） | ⚠️ 接口**接受**（实测能返回符合 schema 的 JSON） | 但那次调用**漏了 `think:false`** ⇒ 它先吐了一段 thinking（10.1s）⇒ **约束解码 ＋ `think:false` 要一起用** |
| 5 | ✅ **一次只问一列、只给 3~4 个候选**，要求 `{"pick": "候选里的某个"}` | **7/8 准 · 平均 1.7 秒/列** | ⭐ **这就是要落进代码的形态** |

**第 5 轮逐列结果**（对照 = 确定性引擎在同一批列名上的成绩）：

| 列名（新写法） | 真值 | 确定性引擎 | AI | 秒 |
|---|---|---|---|---|
| 分公司设备费 | 租分公司设备 | ✅ | ✅ | 2.1 |
| 内租机械计费 | 内租设备 | ✅ | ✅ | 1.7 |
| 详细付款方式 | 付款方式 | ✅ | ✅ | 1.6 |
| 本月应付金额 | 本月预付款金额 | ❌不猜 | ❌（选了"剩余付款金额"） | 1.7 |
| 剩余未付款 | 剩余付款金额 | ❌不猜 | ✅ | 1.6 |
| Supplier Name | 供应商 | ❌不猜 | ✅ | 1.4 |
| 审批状态 | 忽略 | ✅ | ✅ | 2.0 |
| 打印次数 | 忽略 | ✅ | ✅ | 2.0 |

⇒ **合计：确定性 5/8 · AI 7/8**；AI 补齐的正是"**没见过的写法**"那两列（`剩余未付款` / `Supplier Name`），
且**该忽略的两列没有乱认**（这正是最怕的失效模式）。

**耗时口径**（纯 CPU · 无独显）：冷启动 **5~7 秒**（含把 1.4GB 模型读进内存）· 热跑 **1.4~2.1 秒/列** ·
8 列串行一次 **14 秒**。⇒ 与 `qwen3:1.7b` 的推荐一致；**不必上 4B**。

**由此定下的调用契约**（`B1` 实施时照此写）：
1. **只发"确定性引擎认不出"的列**（通常 1~5 列）—— ⛔ 不要把整张表丢给模型；
2. **每列单独一次调用**，候选 = **最可能的 3~4 个 ＋ 忽略**（小空间 ⇒ 准且快）；
3. 请求固定：`think:false` · `format:"json"`（或 schema）· `temperature:0` · `num_predict ≤ 48`；
4. 结果一律进「**需你确认**」档（`conf` 上限 0.85），⛔ 永不自动落库；超时/报错**静默降级**回确定性结果。
