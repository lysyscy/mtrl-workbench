### 向导原稿的缺陷（按严重度）
1. **`Invoke-Step` 返回值被污染**（真 bug）：`& $exe @argv` 的 stdout 进了函数返回管道 ⇒ `$rc = Invoke-Step …`
   拿到的是「全部输出行 + 退出码」的**数组** ⇒ `if ($rc -ne 0)` 退化成数组过滤语义 ⇒
   **git clone 失败会被判成成功、selfcheck 失败会被判成成功**。修法：`| Out-Host`。另补 try/finally（原来抛错时 `Pop-Location` 不执行）。
2. **包自动探测写死 `D:\deliver`** ⇒ 本机（包就在仓旁边）`D:\deliver` 不存在 ⇒ 向导第一步就 `exit 2`。改成多落点扫描 + 校验 `-Pack` 指向的目录里真有 `repo\mtrl-workbench.bundle`。
3. **没有"清旧装"这一步**（原稿照空机器写）：① 不知道要先停 NSSM 服务；② 第 2 步见 `.git` 存在就"跳过 clone" ⇒ **老版本原地留下**；
   ③ 最狠 —— `ops\init_db.sql` 是**裸 `CREATE ROLE`/`CREATE DATABASE`（不可重跑）**，而 `deploy_restore` 第 5 步 `$null = Run psql …`
   **把返回码丢了** ⇒ 重装时 psql 一路报错、脚本当没事，接着对**旧库**跑 alembic ⇒ "看起来装上了"其实只是升级。新增 `-Clean`（显式开关，不默认开）。
4. **Python 版本没人管**：`deploy_restore.ps1` 第 3 步是 `python -m venv`（**只认 PATH**，没有 -PythonExe 口子）。
   本机 PATH 第一位是 `C:\Python314`（3.14.7），而项目是在 **3.13** 上开发的（原 venv 3.13.14）⇒ 会用 3.14 重建 venv，
   `psycopg-binary==3.3.5` 等带 C 扩展的件在 3.14 上不一定有 wheel ⇒ 装不上/跑不起来，而脚本照样报"流程走完"。新增 `-PyVersion` 版本闸（跑之前拦一道，可临时改 PATH）。
5. **库口令要打两遍**（`init_db.sql` 一次、`.env` 连接串一次），不一致 ⇒ 落地后端连不上库且报错难指向。新增 `-EnvFrom` 底本 + 按口令**预填**连接串 ⇒ 只打一遍。
6. 次要：`Get-EnvValue` 取值不掐行尾注释（旧 `.env` 有 `KEY=… # 注释` 这种）；`deploy_restore` 退出码 0 被当成"装上了"（已在向导里加注记，改以 selfcheck 五项为准）。
