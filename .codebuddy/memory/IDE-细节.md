## 三、虚拟滚动那一层：**四条铁律**（2026-09-25 `TAIL-94` 重写后 · 每条都踩过）

- ⛔ 滚动重画**不许** `$('#view').innerHTML=…`（会把真容器 `.tw` 一起换掉 ⇒ **打断滚轮手势**）；只许换 `tbody` 的行。
- ⛔ 滚动中**零 `scrollTop` 写入**（旧"锚定回拉"顶掉用户这一格的滚轮量 ⇒ 症状「**往下能滚、往上回不来**」）。
- ⭐ 文档**总高恒定**（`n*EH`）：下垫高吸收"真高 − 估算"差量、**贴底改由上垫高吸收**（末行必须是合计行）⇒ 窗口 = `f(scrollTop)` **纯函数**（无反馈环、双向对称）。
- ⚠️ 真机验收**必须 `page.mouse.wheel`**（程序化 `scrollTop` 是假证据）；**不许在"贴底"状态**起步测"滚得动"（贴底不动**是正确行为**）；护栏要复现用户**前置状态**（焦点/筛选/滚动位）。
- ⚠️ 宿主是 `backend/app/web/index.html`（⛔ 不是 `shell/*.js`）；改前 grep 外部依赖（`VS.rows/h/base/colN/pending` · `test_shell_render.py` 五条钉 · `_mut_vs.py` 钉的行）。⚠️ **改壳后先 `node --check`**；往"看着单行"的对象字面量（如 `ACT` 条目）里插东西前先确认它**是不是多行**（插中间 ⇒ 整个对象解析失败 ⇒ 壳全废）。

## 十三、`TBL` 调用收尾的括号（⛔ 已错 4 次 · 2026-09-29 从实战蒸馏）

把「表外壳」换成一个 `TBL({…})` 调用时，`rows:` 里带 `map(...)` 的那种，**收尾是一串 5 个括号**：

```
…</tr>`; })})}</div>`,
        ↑  ↑ ↑ ↑ ↑
        │  │ │ │ └─ 关 `${`（模板里的表达式）
        │  │ │ └─── 关 `TBL(` 
        │  │ └───── 关传给 TBL 的**对象字面量**
        │  └─────── 关 `.map(`
        └────────── 关箭头函数的**块体**（语句体 `{ … return …; }`）
```

- ⛔ 我**四次**都写成 `})}`（少两个）⇒ 报错形态各不相同但同源：`Invalid regular expression: missing /`
  （因为 `TBL(` 没闭合 ⇒ 后面的 `</div>` 被当代码、`/` 被当正则起始）。
- ⭐ **壳侧**：`syntax_audit` 的 `Q2` 一次就抓到（扫 `index.html` ＋ `shell/*.js`）。
- ⛔⛔ **原型侧 Q2 不查**（原型不在壳的件清单里）⇒ 只有**交付面四检的 `_smoke`** 能抓，
  表现是**早退**：`RUN FAIL: Invalid regular expression: missing /`、**没有汇总行**（⚠️ 没汇总行 = 没跑完，不是"过了"）。
- ⭐ 记住两件事即可：**① 数括号别凭手感；② 改了原型 ⇒ 必跑 `doc_audit --ui`**。

### `FBAR`（筛选栏外壳 · `TAIL-64` P4-a · 2026-09-30）的收尾

## 十八、`TAIL-233`（2026-10-06）蒸馏：变异件哑靶的**两个新机制**（判据件通用）

> ⭐ 触发 = 修「守尺子的变异自证」14 支里 4 支 ⇒ 查出**两族此前没记过的哑靶形态**。
> ⚠️ 本节是**机制**，不是故事；故事与逐支数据在 `journal/2026-10-06.md` 的 `TAIL-233` 节。

### 1. ⭐⭐ CRLF 靶件 ＋ `\n` 字面锚点 ⇒ **整件死在一个 assert，一条都没验过**

- **症状**：变异件只报一句「⚠️ 变异① 锚点没命中（`xxx.py` 变了？先核再改本件）」/「`M2` 锚点命中 0 次 ⇒ **锚点漂了**」
  ⇒⛔ **读起来像"靶漂了"，真因却是行尾**（本仓 `tools/` `tools/probe/` `tools/audit/` 的 `.py` 几乎全是 **CRLF**）。
- **机制**：异件按**字节** `decode()` 读源（`\r\n` 保留），而锚点写的是**带 `\n` 的源码字面** ⇒ 命中 0。
  ⭐ 8 个 case 里 7 个含换行 ⇒ 件死在**第一个** assert ⇒ **一条都没跑过**，而它看起来只"坏了一条"。
- ⭐ **分辨一招**：`Path.read_text()` **会**做通用换行转换（`\r\n`→`\n`，看起来在）；`bytes.decode()` **不会**
  ⇒ **"我量的时候在、它跑的时候不在"** 就是行尾。
- **修法**（两半都要）：比对前 `_norm()` 归一为 LF ＋ 写回 `_fit()` **按该件原本行尾**。
  ⛔ 后半句是必须的：否则一次变异就把 CRLF 件悄悄改成 LF ⇒ 收尾 **MD5 复原校验背黑锅**（报错指向复原、指向不到真因）。
  ⭐ `_mut_linewalls.py` 里早有现成配方（`_fit`）⇒ **同族复用，别另造**。
- ⚠️ **同族的第三个形态**：`splitlines()` + `join("\n")` ＋ `newline=""` ⇒ **整份行尾被写成 LF**
  （而 `replace()` 那几处幸免）⇒ 断言照样过 = **碰巧没露出来** ⇒ 拼的时候要**按源件行尾**（`nl = "\r\n" if …`）。

### 2. ⭐⭐⭐ `subprocess` 的 `UnicodeDecodeError` **不从 `run()` 抛出来** ⇒ 表象是「**没有输出**」

- **症状**：`subprocess.run(..., text=True, encoding="utf-8")` 拿回 `p.stdout == ""`、`p.returncode == 0`
  ⇒ 脚本报 `RuntimeError: xxx --json 没有输出（rc=0）`，⛔ **看着像"尺子/环境坏了"**。
- **机制**：解码发生在 `subprocess` 的**内部读 stdout 的线程**（`threading._readerthread`）⇒ 异常**被线程吞掉**、
  `run()` 正常返回、只是 `p.stdout` 空。⚠️ Windows 管道下子进程默认 **cp936**（`-X utf8` 不加时）。
- ⭐ **判法**：`p.stdout` 空 + `p.returncode` 是 0 ⇒ **先怀疑编码，别先怀疑子进程**。
  量法 = 直接 `capture_output=True` 取**原始字节**试 `decode("utf-8")` / `decode("gbk")`。
- **修法**（三件一起）：`-X utf8` ＋ 环境 `PYTHONIOENCODING=utf-8` ＋ `errors="replace"`（**当保险**）。
  ⛔ **只加 `errors="replace"` 不够** —— 实测那样能拿到输出、也能 `json.loads` 过，但里面是**替换字符**
  ⇒ 属"看着能用、其实内容已坏"。⚠️ 本仓 `MEMORY.md §四-1` 那条（`.json` 别文本替换）是同一族。

### 3. ⭐ 判据写成 `not any(...)` 时，**必须同时证明"红造得出来"**

- 本仓已有同族结论：「**只断言"坏事没发生"的自测 = 没有守卫的自测**」（`TAIL-236` ④）。
- ⭐ 本轮又中一次：某变异件的 M4 `replace` 目标串**命中 0 次**（那条缺口早被修掉），判据又查着
  **不在 `red` 里**的文本 ⇒ `not any(...)` **恒真** ⇒ 报 ✅ 也是假的（该件因此"5/5"里有 1 路是假的）。
- ⇒ **处方**：这类判据改成**两段式「造红 → 销红」**（`造红` 要求那条红**真的出现**，`销红` 要求它**真的消失**），
  靶**动态取**（⛔ 不写死整行：真源一改就漂）。⭐ 顺带把"从没被验过的那把尺子"补上了。
- ⚠️ 另一条同族：**判据的前置条件不许写成"世界的绝对状态"**（如"基线里不该有这条报法"）
  ⇒ 现实一正常地变化，它就自己把自己否决（本仓 `_mut_linewalls` 就这样哑的）⇒ 改成**相对**（记基线值、断言递增）。
