## §十七 写 / 跑**反向灵敏度（变异测试）**的四个坑（2026-09-16 实测，代价最高）

⭐ **通用前提**：变异 / 还原**一律走 bytes**（`write_text` 在 Windows 会把 `\n` 写成 `\r\n` ⇒ MD5 假 BAD）；
**核验范围与失败复跑只回 ops/agents/issue-tracker.md §四**；**变异点找不到 ⇒ 必须重写，不得当作已通过**；
**变异片段含中文时 ⛔ 不能用 `b"…"` 字面量**（bytes 只允许 ASCII ⇒ `SyntaxError` 报在脚本自身、
极易误判成"变异点写错"）⇒ 片段写 `str`、应用时 `.encode("utf-8")` 再 `_fit`。
判据先选能验证实际后果的最小层级：纯逻辑用单测，UI状态用隔离浏览器，真实约束用少量隔离集成。新改测试不强制独立变异；运行时机与反例选择回ops/agents/issue-tracker.md §四。

以下四条是"找不到 / 假绿"的**真实成因**：

1. ⛔ **本仓源码行尾不统一 ⇒ bytes 片段必须按目标文件归一。**   实测：`notice_pay.py` = **CRLF**（263 个 `\r\n`、0 个孤立 `\n`）；而
   `domain.py` / `merge.py` / `classify.py` / `notice_actions.py` = **LF**。
   ⭐ **根因（2026-09-17 查明）**：`git config core.autocrlf = true` ⇒ **被 git checkout 写出 = CRLF**、
   **工具新写 = LF** ⇒ 同包混行尾且**与文件类型无关**。
   ⚠️ **别用 `git status` 判断行尾**（`autocrlf` 下看不见）；**只信 `bytes.count(b"\r\n")`**。
   根治需加 `.gitattributes`（`* text=auto eol=lf`）—— **属仓库级改动，先问用户**。
   ⚠️ **症状极具欺骗性**：`grep` / `Read` 看着**一模一样**，但 `bytes.count()` **恒为 0**；
   本轮为此**卡了 5 轮**。⇒ 片段**一律按 LF 写**，匹配前用 `_fit(fragment, src)` 按 `src` 归一：
   ```python
   def _fit(fragment: bytes, sample: bytes) -> bytes:
       if b"\r\n" in sample:
           return fragment.replace(b"\r\n", b"\n").replace(b"\n", b"\r\n")
       return fragment.replace(b"\r\n", b"\n")
   ```
2. ⭐ **"铁律在两头"⇒ 单破任一头不露馅，须两头同破。**
   实测（`merge.py`「受保护字段不被覆盖」）：**主闸** = `SOURCE_FOLLOWED` 不含那些键；
   `PROTECTED` 的 `plan.values.pop(key, None)` **只是兜底**。
   ⇒ 单独破任一头 **rc=0（假绿）**、**两头同破 rc=1**。
   ⚠️ **纪律：设计变异点前先问"这条铁律有几道闸"**（脚本可用 `<<AND>>` 编双处替换）。
3. ⭐ **"整页 `in`" 是假绿温床** —— 同页两格数值不同、字符串会**互相喂饱**。
   实测：断言 `"3000.00" in html`，把实现改成"全部流水汇总"（=5000）后**仍然通过**
   —— 因为另一格（`统计付款金额`）正好也印了 3000。
   ⇒ **断言必须绑到那一格**：按 `<b>标签</b><span>值</span>` 结构取（本轮新增 `_cell_of()`）。
   ⚠️ 连带：**写断言前先看真实输出**（该页金额**无千分位** = `3000.00`，不是 `3,000.00`）。
4. ⭐ **"上层没变化" ≠ "下层没被调用"** —— 断言 `changed is False` 会被**下层另一道闸掩盖**。
   实测（`test_merge.py::001-05`「值没变就不动」）：把主闸改成 `if True` 后，下层
   `if not _same(current, new_value)` 仍然把写入拦下 ⇒ 原断言**照绿**。
   ⇒ **要断"根本没调用重算"，就用 spy 数调用次数**（`calls == []`），
   而不是断"结果没变化"。
5. ⭐ **测"取不到 / 不存在"这类分支，样本必须"过前面所有校验、只差最后一步"**。
   实测（预览暂存「取不到要报错」）：我原本用**不合法的 token** 去测 ⇒ 它**先被 token 形态校验拦掉** ⇒
   把实现改成"取不到就回落成空"**照样绿**（16 处变异里唯独 ⑮ 仍绿）⇒ 改用**形态合法但不存在**的 token 才测到。
   ⭐ 通法：**"坏样本"要坏在你要测的那一步上**，别坏在更前面（否则测的是别的东西）。

## §十八 真机验证（**是唯一能证明"实现真的对"的东西** · 2026-09-17 实测）

**为什么单独一节**：离线断言（含假会话 / 假 client）**天生看不见**三类问题 ——
① 真接口的**文件形态**（表头几行、列名怎么写）；② **数据库级的作用范围**（`FakeSession` 忽略 SQL `where`）；
③ **跨模块的次生影响**（本节 ③）。三轮真机已各抓出一类，代价都是"上生产才发现"。

1. ⭐ **两条链路要验、又不想重复强踢 ⇒ 共用一个 `I8Client` ＋ 代理吞掉 `close`**：
   ```python
   class _KeepAlive:
       def __init__(self, inner): self._inner = inner
       def __getattr__(self, name): return getattr(self._inner, name)
       def close(self): pass          # 故意不关 ⇒ 两条链路只登录一次
   ```
   把 `client_factory=lambda: keep` 传给 `run_fetch` ⇒ **每条仍走真正的全链路**（导出 → 解析 → 落库 → 建档），
   但 `KillOnlineUser` **只踢一次**。样板 = `tools/oneoff/_verify_auto.py`（2026-09-22 结构整改后从 tools 根移入 `oneoff/`）。
2. ⛔ **真机脚本别注入 `export=`**：那会**绕过"顺手取仓库名单"那一步**（它就写在 `export(...)` 之后、`close` 之前）
   ⇒ 链路的**自动建档就走不到了**，你会误判"自动建档没生效"。
3. ⭐ **自动建档会引入"共享 `phid`"这种次生影响** —— i8 侧**只有壳有项目编号**，新建的**具体小微继承同一个
   `phid`** ⇒ 取数参数**出现重复**（`13 条档案 / 12 唯一`）。**这类问题只会在建档动作真的发生后才出现**，

## §二十 「产物类」检查的两条通法（2026-09-18 实测 · 导出成品）

> 触发场景：**任何"生成一个文件/包"的功能**（导出、打包、生成的 xlsx / pdf / zip）。
> 两条都是"看起来验过了、其实没验"的形态，各踩过一次。

1. ⚠️⚠️ **「清单（声明）自己说自己」= 假绿。**
   实测：`ACC-SETL-001/001-08` 的判据点原文是「**产出物** = 分仓库工作簿 ＋ 1 个总表」，
   而断言只查了 `service.build_page_data()["manifest"]`（一张**清单**）——
   **导出功能一行都没实现时，本条照样是绿的**（导出按钮按下去拿不到任何文件）。
   ⇒ ⭐ **通法**：断言必须**让"清单"与"真产出"对账** ——
   拿同一份数据**真跑一次**产物生成，再核对「包内成员 == 清单条目」。
   本次补紧后**当场抓出两处命名不一致**（清单写 `…2026-08…`、真产物写 `…2026年8月…`
   —— 两处各写一份命名规则）⇒ 命名统一到 `domain.period_label` **唯一出口**。
   ⭐ 这与 §十二 的「断言要钉住那条逻辑本身，不要钉它的可观测结果」是同一条：**清单就是"可观测结果"**。

2. ⚠️⚠️ **存在性检查看不见结构错。**
   实测：素材包核对 `refreshOnLoad="1"` 用的是 `'refreshOnLoad="1"' in 字符串` ——
   字符串**在**、但那个属性**加错了元素**（`<pivotTableDefinition>` 上不合 OOXML schema），
   检查照样通过；而**用 `openpyxl` 把产物读回来**（不带 `read_only`，会解析透视）**当场报**
   `TypeError: TableDefinition.__init__() got an unexpected keyword argument 'refreshOnLoad'`。
   ⇒ ⭐ **通法**：产物类检查至少要有一步「**用正经解析器读回产物**」——
   它比任何正则/字符串检查都强，因为它替你把 schema 校验过了。
   ⚠️ 附带：`read_only=True` 会**跳过**这些解析 ⇒ 别用 read_only 当结构闸门。

## §十二 顺序纪律 ＋ 反直觉教训（**全文** · 2026-09-18 从 `MEMORY.md` 下沉，⛔ 不丢内容）

> 配套细节：§十六（写新页四坑）/ §十七（变异五坑）/ §十九（改尺子纪律）/ §二十（产物类检查）。

- ⭐⭐ **「判据绿」≠「链路对」** —— 判据测**零件（纯函数）**、**不测装配（它有没有被调用）**
  （实测：`ensure_batch_settled` 8/8 绿，**链路从没调用它** ⇒ 61 条未归属单据照样入库）。

  ⭐ **通法：多个"覆盖"维度必须各自独立成档，别让宽判据吃掉窄判据**

- ⚠️ **写断言要问"这是意图还是现象"**（**"修 bug 反而把绿改红"** = 标志信号）；改断言必须同步做**反向灵敏度**。
- ⚠️ **「整页 `in`」与「上层没变化」都是假绿温床** ⇒ ① 断言**必须绑到那一格**

- ⚠️ **「该有输出的命令返回空」≠ 绿灯** —— 先 `cat` 输出文件看是否报错。
- ⚠️⚠️ **「清单说自己」是假绿** —— 断言只查 `manifest`/声明而不验**真产物** ⇒ **功能没实现也照绿**

- ⚠️⚠️ **存在性检查看不见结构错** —— `'xxx="1"' in 字符串` 通过 ≠ 那个属性放对了地方
  （实测：`refreshOnLoad` 加在 `<pivotTableDefinition>` 上不合 schema，字符串检查照样过）。
