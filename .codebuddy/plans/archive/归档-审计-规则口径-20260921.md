## 二、发现的问题（每条：现象 → 证据 → 后果）

### ⭐⭐ F1（最严重 · 已经发生的真冲突）：我自定的规则**没有机器校验**，且**已经和你的最新裁定打架**

- **现象**：`MEMORY.md §八` 写着「⭐ 远端已配通（`origin` → gitee）⇒ **每轮收尾提交 ＋ 推送**」。
- **冲突**：你 **2026-09-21 定「先不提交，继续攒」**（记在计划/执行情况里）。⇒ 两条**直接对立**。
- **为什么没人发现**：`claim_audit` **只扫两份活文档**（计划 ＋ 执行情况），**不扫 `MEMORY.md`**；
  `MEMORY.md` 那条**没有任何尺子在看**。
- **后果**：自定纪律会**静默腐化** —— 而且它比文档更危险（文档只是描述，纪律是指令，我每轮会照着做）。
- ⚠️ **同类的可能还有**（需要你一次过）：`MEMORY.md §八` 其余各条（抽中立件 · 预览不写库唯一件 · 真机抓取必看两数 · 交付面无 git 的三查）。

### ⭐ F2：硬数字阈值**几乎全没有"为什么"**，也没有"谁改过"的记录

| 数字 | 含义 | 出处 | 有问题吗 |
|---|---|---|---|
| **400 / 600** | 单文件行数（黄/红） | ⭐ **我自定**（`MEMORY.md §八`） | ⛔ 值本身可疑（见第三节） |
| ±2 行 | 术语豁免窗口 | 我自定 | 无出处、无从复核 |
| 16 字符 | 豁免模式跨度上限 | 我自定 | 同上（`[^，。；\n]{0,16}`） |
| ≥60 / ≥15 / ≥100 | 主题变量数 / 路由件数 / 扫到模块数 | 我自定 | ⭐ 这三个是"**防止检查退化成空转**"的下限理由，但**没写下来** |
| 6 格 | `T6` 台账行最少格数 | 我自定 | 同上 |
| 10 套 / 4.5 | 主题套数 / 对比度 | ⭐ **用户** | ✅ 有出处 |

- **后果**：改阈值时**没有任何"这是谁的决定、为什么是这个数"** ⇒ 要么没人敢动，要么随手动（两种都坏）。

### F3：同一条规则**抄在 4 处**

`T5`（400/600 行）同时出现在：`tools/audit_meta.py:19`（实现）· `MEMORY.md:48` · `MEMORY-细则.md §廿一` · `CLAUDE.md:66`。
- **后果**：改一处必漂，全靠"铁律⑦ 改一处同步"**靠人记**。（本仓对"唯一的真源"极敏感，**这里却破例了**。）

### F4：**"只列不判红"的尺子常年亮黄** ⇒ 黄灯等于没人看

- `doc_audit` 疑似 **40 条** · `claim_audit` 黄 **20 处**（都在留痕区/已在说明它废了）。
- **后果**：黄灯**没有收敛机制**（不记基线、不设上限）⇒ 数字涨了也没人知道 ⇒ 真问题会**淹没在常亮黄灯里**。
  ⭐ 本轮就吃过：我一度以为"疑似 40"里有我的锅，只能逐条去查。

### F5：**"有断言" ≠ "断言有区分力"** —— 变异测试覆盖面**无人知道**

- 仓库里有 `tools/_mut_*.py` 约 12 个（theme / time / trash / auth / fix3 / jc / …），但 **527 条判据里有多少条被变异测试覆盖过 ⇒ 没有台账**。
- **后果**：新增判据时"跑一遍绿"就收工（本轮的 `_mut_theme.py` 首跑就抓出一条**假绿**）⇒ 说明这层检查真有用，但**它是靠我每轮手动想起来做**。

### F6：一次性脚本（约 **80 个** `_mut_*` / `_apply_*` / `_doc_*` / `_acc_add_*`）与常跑尺子**混在 `tools/`**

- **后果**：看不出"哪些是活的、哪些是一次性的"；换工具接手时**只能逐个开文件看**。

### F7：规则的"机器实现"散落在各脚本 docstring 里（子代理扫描的结论）

- 集中锚点（`MEMORY.md §八`）只起**目录**作用，真正的**判定逻辑与出处**在一堆 `tools/*.py` 注释里
  ⇒ "这条规则谁定的、能不能改"**要靠考古**。

### ⭐⭐ F8（扫描过程中**当场撞上**的事故实例）：交付面里"我造的文件"会被 **WPS 同步改回来**

- **经过**：`_doc_handbook_sync.py` 在交付面留了一份备份 `_backup-handbook-20260921-1450.md`。
  `doc_audit` 把它**当文档扫**（疑似 +1）⇒ 我改名成 `.md.bak`（**当场验证改名成功**）。
  **几分钟后再看：名字自己变回 `.md` 了。**
- **原因**：交付面是 **WPS 云同步树** —— `MEMORY.md §一` 早就记着这个坑（"生成 `<原名>-副本<时间戳>` ＋ **回退旧版**"）。
  ⇒ **我在交付面里造的任何一个新文件，都不受我控制**。
- **处置**：备份挪出交付面 ⇒ `<repo>/artifacts/delivery-backups/…md.bak`（**交付面里现在 0 个我造的文件**）。
- **对规则的启示**：① 交付面的**写操作**只该是"改既有文档的既有内容"，⛔ **不该建新文件**；
  ② 任何"备份/中间产物"一律落**仓库侧**（`ops/` 或 `artifacts/`）。
