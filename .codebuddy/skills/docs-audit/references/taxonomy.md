# 本仓文档七类（按**用途**分 · ⛔ 不按主题分）

> ⚠️ **本件是审计用的分类与判读表，⛔ 不是口径** —— 分层 / 命名 / 落点的主人 = 根 `README.md`（§二 四层 · §四 命名 · §七 决策树）。
> 用法：第 2 步（分类）逐份归位；第 3 步（找病）按类查它那一列的"典型病"。

## 二、七种病 × 本仓真例（找到病时，**回这里对一行**）

| 病 | 一眼判法 | 本仓真例 / 后果 |
|---|---|---|
| **一事多处** | 同一句话 / 同一条规矩在两个文件都能搜到 | `TAIL-130` 与 `TAIL-117` 批次 0 **登记两处**：活做完了、工单还挂墙上 ⇒ 下一个人把做完的活**重查一遍** |
| **职责混杂** | 一份文件里既有"规矩"又有"进度/流水" | 口径文件里塞"当前进度表"⇒ 规矩改一次要动两处，进度一漂就没人敢信那份文件 |
| **过期讲错** | 文档说 A，代码/后端做 B | 界面写"集采抓取**定时自动**"，而后端口径是"**只做人工点击、无定时**"；代码里"教人怎么做"的注释一改就是**假说明书**（本仓口径：订正过期注释与删代码**同权**） |
| **超预算** | `T10`（读预算）/ `T5`（行数）报黄 | 超预算的**失败方式很特别**：我不读、改去 `grep` ⇒ **没被搜到的东西就永久丢了**（实测：三条待办只活在对话里，grep 0 命中） |
| **孤儿 / 死链** | 没人引用；反引号里的路径解析不到 | `T3` 幽灵路径；`T18` 抓过 4 例"**检查在跑、其实扫空集**"（常量指向搬迁前的旧地址） |
| **该有没有** | 有登记的能力却没有对应的文档/判据兜住 | `cover_gap` 的登记册（`T7` 是**登记档、不判红**） |
| **备份/留痕当文档算** | 它在 `backups/` 或 `artifacts/` 里 | 备份快照占全仓文档行数的一大截（2026-09-28 实测 **39%**）⇒ 审计时要**单列占比**，⛔ 别按内容审它 |

## 三、两条最贵的本仓课（审计报告里值得复述）

1. **文档超预算的失败方式不是"读得慢"，是"我改去 grep"** ⇒ 没被搜到的东西**永久丢掉**。所以①②层（注入档 / 按需档）必须瘦，过程叙事一律下沉到留痕档或 `work/`。
2. **"已完成" ≠ "可归档"**：问的永远是「这条是**过程**还是**口径**」，⛔ 不是"它还有用吗"。
