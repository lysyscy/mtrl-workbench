# 文档审计（本仓）

## 这个技能做什么 / 不做什么

- **做**：盘点（分布）→ 分类（结构）→ 找病（内容）→ 排队（给用户拍）→ 收口（改完过闸门）。
- **⛔ 不做**：写新文档（走 `doc-coauthoring`）；改业务代码；替用户决定"这份文档该不该存在"（那是**裁定**，要用户拍）。
- **⛔ 本技能不新增口径** —— 三个主人各有其主，一律**只给指针、⛔ 不复制条文**：
  | 要知道 | 唯一主人 |
  |---|---|
  | 文档**分层 / 命名 / 落点 / 怎么加一份新文档** | 根 `README.md`（＝文档地图，它的 §二/§四/§七） |
  | 每把尺子**管什么 / 权威 T 表** | `tools/audit/doc_audit.py` 头部 |
  | **硬数字**（预算 / 行数上限 / 阈值） | `ops/阈值表.md` ＋ `tools/audit/audit_meta.py` 的常量 |

## 五步工作流（每步都有产物；⛔ 别跳到"改文件"）

### 第 0 步 · 先跑既有尺子（**别先读文档**）

```powershell
backend\.venv\Scripts\python.exe tools\audit\doc_audit.py --ui
backend\.venv\Scripts\python.exe tools\audit\audit_meta.py
backend\.venv\Scripts\python.exe tools\audit\audit_drift.py
backend\.venv\Scripts\python.exe tools\audit\cover_gap.py
```

**读法**：**「必须修 0」是硬门槛**（非 0 就先修，⛔ 别往下审计）；**黄档要读汇总行** ——
「疑似 N」**不是噪音，是待判清单**（已知三类必须逐条解释：`T5` 行数 · `T10` 读预算 · `T12` 布局）。
逐把尺子的命令 / 读哪一行 / 期望值 / 黄档怎么处置 ⇒ `references/rulers.md`。

### 第 1 步 · 盘点（**分布**）

```powershell
backend\.venv\Scripts\python.exe .codebuddy\skills\docs-audit\scripts\doc_inventory.py
```

产出：按目录的**件数 / 真值行数**、**最大的 10 件**、**超预算件**、**同一内容多份（重复/快照）**、**过短件**。
⭐ 行数**真值** = `len(text.splitlines())` —— ⛔ **别用 PowerShell `Get-Content` 量**（实测同一文件 69 vs 198，见 `README.md` §八；脚本已按真值口径写）。
**判读顺序**：① 先看**占比**（哪一层在膨胀：留痕？备份？设计产物？）② 再看**超预算件** ③ 最后看重复。

### 第 2 步 · 分类（**结构**）

逐份按**用途**归位（⭐ **不按主题分** —— 这是本仓的分层口径），七类的信号 / 真源 / 典型病 ⇒ `references/taxonomy.md`。
**判据一句话**：**这份文件"谁读、什么时候读"答得上来吗？** 答不上 ⇒ 它多半是**过程叙事混进了口径层**（本仓最贵的一课：文档超预算的失败方式是"我不读、改去 grep ⇒ 没被搜到的就永久丢了"）。

### 第 3 步 · 找病（**内容**）

按类查这七种病（每种都有本仓真例 ⇒ `references/taxonomy.md`）：

1. **一事多处**（同一件事在两个文件各写一遍 ⇒ 改一处漏一处）
2. **职责混杂**（一份文件既当口径又当进度 / 流水）
3. **过期讲错**（写完没再改、内容已漂 —— 最贵的是"**假说明书**"）
4. **超预算**（`T10` 读预算 · `T5` 行数）
5. **孤儿 / 死链**（没人引用；引用的路径不存在 ⇒ `T3`）
6. **该有没有**（缺口 ⇒ `cover_gap` 的登记册）
7. **备份 / 留痕被当文档算**（快照只查"留几份 / 何时清"，⛔ **别审它的内容**）

### 第 4 步 · 排队（产出**给用户拍的清单**）

每条写四格：**动作 / 代价 / 风险 / 落点**；按"低成本高收益"排。
⛔ 涉及**口径变更**、**删 / 归档文件**、**新增层级或目录** ⇒ 一律写成**选项**让用户拍（`README.md` §七-8）。
产物落点：`.codebuddy/work/10-designs/设计-文档审计-<YYYYMMDD>.md`（命名见 `README.md` §四）；
⭐ 若清单里含"建议" ⇒ 每条**必须带待办登记回执**（"已登记 `TAIL-xx`"或"不登记的理由"）—— `T11` 守。

### 第 5 步 · 收口（改完必须过闸门）

```
doc_audit --ui 必须修 0 ＋ audit_meta 必须修 0 ＋ audit_drift 必须修 0 ＋ claim_audit 必须修 0
```

＋ 按改动的层各自补规矩：改**契约面**（《说明书》/ `验收基线.json` / `MOD-*` / 用例索引）⇒ **同批**改，⛔ 别分两轮（否则 `T4`/`T7a`/`T7b` 必红）；改**前端口径** ⇒ 在守则 §10 记一笔。

## 三条铁律（本仓血泪）

1. **⛔ 一处定义**：口径只有一个家，别处只给指针（复制一份 = 长出第二套口径，改一处漏一处）。
2. **⛔ 别顺手清"有意保留的留痕"**；删任何东西之前先问一句 **"它是给谁看的"**（真例：侧栏模块编号被当成黑话、差点清掉）。
3. **⛔ 动文档 = 动产物**：改完跑尺子 —— 本仓"完成"的定义是**机器核过**，不是"我读着通顺"。

## 停手问用户的四件事

要**删 / 归档**任何文件 · 要新增**层级 / 目录** · 要把某条纪律写进**注入档** · 要**扩大收工闸门**（例如把这个盘点脚本升级成第 14 把尺子 ⇒ 那要改 `doc_audit` T 表 ＋ `ops/阈值表.md` ＋ 闸门清单）。

## 附带资源

- `references/taxonomy.md` —— 本仓文档七类：每类的**信号 / 真源 / 机器扫什么 / 典型病 / 该问什么**。
- `references/rulers.md` —— 与文档相关的尺子：**怎么跑 / 读哪行 / 期望值 / 黄档处置**（⚠️ 权威表仍在 `tools/audit/doc_audit.py` 头部）。
- `scripts/doc_inventory.py` —— 只读盘点器（分布 / 超预算 / 重复 / 过短）。
- `scripts/orphan_scan.py` —— 只读孤儿扫描（⭐ 按四层**分开报**：只有 ①② 层的孤儿才是病，留痕档没人引用是正常的）。
