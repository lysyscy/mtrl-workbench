# 文档审查与整理

流程与核验的唯一主人 = ops/agents/issue-tracker.md §四；分层、命名与落点 = README.md §二/四/七；治理关系 = ops/docs-governance.md。用户当前授权优先。

## 执行

1. 从当前任务及现行入口限定范围；列出要解决的用途冲突与完成标准，已有规格不重新访谈。只有判断需要完整分布时才运行 scripts/doc_inventory.py。
2. 按用途分类，参考 references/taxonomy.md。区分现行要求、机器输入、索引、过程和恢复证据；日期、体量及零引用都不能单独证明无用。
3. 核对主人与实际使用者：一事多写、职责混杂、过期指针、历史默认读入、必要含义缺失。历史仅在复发、约束不明或明确追溯时读取，说明原因。
4. 在用户已授权范围直接整理；更新主人及活引用，保留未解决风险。业务含义变化、删除仍有现行用途的内容、范围扩大须另获授权。提交与推送按 ops/agents/issue-tracker.md §四执行。Git已有过程不要求再复制全文或新增长索引；有独立恢复用途的归档才按主人登记。
5. 按实际影响选择文档检查及机器使用者，读法参考 references/rulers.md。相关失败不报通过；无关治理提示不阻挡当前交付。仅改资料不默认验全部业务、变异或仓外原型。
6. 在当前票或改动说明记录结果、依据、耗时和未验项；稳定含义回主人，不新增永久阅读日志、双份状态或每轮强制报告。

## 完成标准

受影响现行含义有一个主人，入口说明何时读，活引用可达；历史退出默认路径，未决冲突明确保留。相关检查与必要反例通过，跳过项能说明真实不相关后果。

## 按需资源

- scripts/doc_inventory.py：分布、预算与重复的只读盘点；需要完整分布才跑，不是日常闸门。
- scripts/orphan_scan.py：引用线索；孤儿不是删除结论。
- references/taxonomy.md：用途分类与病因提示。
- references/rulers.md：检查结果读法，核验选择仍回流程主人。
