# tools/ · 工具用途与触发入口

> 读者：选择工具或维护检查的人。回答：工具职责与何时运行。流程回 docs/agents/workflow.md；命令回 docs/guides/development-and-verification.md §十一。

| 目录 | 用途与读取条件 |
|---|---|
| audit/ | 语法、字节、接线、资源及文档检查；按实际风险显式选择，命令由各工具持有。 |
| mut/ | 少量必要反向场景按需运行；先核隔离及当前靶，不维护全局选集、覆盖登记或自动运行义务。旧直接写正式靶的脚本保持不可执行边界。 |
| probe/ | 真机与端到端实测；改到对应运行行为时使用，需要时说明服务和现场前提。 |
| oneoff/ | 开销票及操作/历史脚本；自动选测、通过回执与变异调度入口已退役，恢复用途未知者保留。 |

## 纪律（⛔ 别破坏）

1. **新增尺子 ⇒ 放 `audit/`**，并在 `doc_audit` 的 T 表、`docs/reference/thresholds.md` 登记；⭐ **新增一条判据（`T*`）⇒ 同批核它接进了 `doc_audit`**（`T23` 半边④ 是范例：**拆掉接线就报红** ⇒ 忘了接线的判据自己会喊）；
2. 必要反例写明保护行为、隔离和正常/拒绝场景；优先复用已有pytest，不要求每条测试配变异或维护台账；
3. **⛔ 全站只许一处 `wb.save(`**（`report_export/save.py`，`tests/test_export_save.py` 静态扫描守着）；
4. 搬动任何件 ⇒ **同批改锚点路径**（`_mut_*.py` 按路径定位，搬了不改 = **静默失效**，`TAIL-57` 台账的"⚠️找不到"列会亮）。
5. **正常提交保留适用检查**：钩子仅执行暂存语法、字节及.env文件名拦截，输出必须能看见pre-commit结果。文档/台账/全局变异登记退出每次提交；业务与文档按影响入口各验一次，不用跳过钩子来减负。
6. ⭐ **模块 / 函数的 docstring 第一句就得是它**（`Q4` 只查得前者）：⛔ **别把注释放 docstring 前面** ——
   那段字符串就不再是 docstring（`__doc__` 变 `None`），而**没有任何尺子看得见**；⛔ docstring 里写
   Windows 路径**用正斜杠或 raw 字符串**（`D:\dev\...` 的 `\d` 是非法转义 ⇒ `syntax_audit` 判红）。
   ⚠️ 2026-10-06 两条都当场踩过：前者在 `audit_work.py`、后者在 `syntax_audit.py` 自己身上。

## 付款计划核对规则分发

`tools/oneoff/_build_plan_audit_runtime.py` 从工作台真源生成 `skills/payment-plan-audit/resources/audit-runtime.zip`，携带纯金额/审查规则与必要枚举，不包含数据库、配置或凭据。同一命令同时生成唯一对外交付包 `dist/payment-plan-audit.skill`，仅含入口、回写参考和运行脚本/规则，排除开发测试、缓存、会话和业务文件。维护相关规则后重新生成，运行skill测试核manifest和解包独立运行，再通过Skills Manager更新；不手改zip内的规则副本。

## 隔离行为反例

通知书搜索选择由 `tools/mut/_mut_notice_selection.py` 在隔离浏览器假回包上验证：搜索含词裁剪、绕开隐藏核对、付款行序失配和失效ID未清理四靶；正常与复原13项包括550行虚拟表和最大字号。仅改副本壳，不访问真实付款或服务；主仓3.13组合和门禁边界见TAIL-309。

长期登录反例由 `tools/mut/_mut_long_login.py` 在隔离副本验证服务器期限、400天cookie、退出清理、验签、版本/旧三段/时间整数/账号校验与写闸；假密钥和内存HTTP禁止数据库调用。主仓整合与组合回归证据见TAIL-308；提交关系从原票及Git定位。

过程报表来源组装由 `tools/mut/_mut_proc_report_data.py` 在隔离后端副本验证：机械独有资格、各仓库截止、原始/调整金额、逐单与月度差异、批量单次读取、回滚后有效历史、已存机械不受截止遮挡及尾块空列清公式。正常和复原输入必须通过，只有行为断言失败算造红；不改正式源码、公共workbook机制或生产数据。证据与边界见TAIL-307。

会话身份反例由 `tools/mut/_mut_session_identity.py` 在隔离后端副本执行，使用假账号和进程内假密钥；覆盖登录写姓名、新票误作内部标签、重新接纳旧三段票、中间件丢账号类型、写闸只看Cookie存在、留痕写账号及i8身份类型丢失。生产服务和真实凭据不参与；旧 `_mut_auth.py` 仅同步本轮已改锚点，不能在正式工作文件上执行。

`tools/mut/_isolated.py::isolated_backend`供`tools/mut/_mut_proc_split.py`与`tools/mut/_mut_tail270.py`共用：复制后端到scratch，子进程传测试库与独立四态出口，结束清临时副本；不复制凭据。新增同类反例优先复用，测试库写入仍由用例事务回滚。
一次性编辑脚本与可重复核验脚本分开；改过的锚不会作为下一次核验的前置动作。开工差异与真机证据边界回 docs/guides/development-and-verification.md §十一。

## `oneoff/` 的保留与处置口径（`TAIL-194` · 2026-09-29 立 · ⭐ **本处是唯一主人**）

**三类件，处置不同**（⚠️ 判"属于哪一类"的唯一办法 = **查引用**）：

| 类 | 怎么判 | 处置 |
|---|---|---|
| ① **常驻小工具** | 收工闸门 / 口径 / 别的件会**反复**引用它（`_ps_*.ps1` · `_list_tails.py` · `_page_measure.py` · `_prepush_sensitive.py` · `_oneoff_measure.py` · ⭐ **`_tail_open.py` / `_tail_close.py`**（立/销台账 · 2026-10-02 补）· ⭐ **`_doc_downgrade.py`**（降档动作 · 2026-10-06）） | ⛔ **长期保留** —— 名字带 `oneoff` **不代表**它是"一次性" |
| ② **被引用的留痕件** | 台账 / 设计件 / 判据 / 记忆里**提到了它的文件名** | ⛔ **长期保留** —— 它们是"当初怎么做的"的唯一书面凭证；删了就**断链**（`T3` 幽灵路径 / 交付面 `_links` 会报）。活引用须同批更新；历史引用不能单凭零命中判断无用。 |
| ③ **零引用的** | **没有任何**仓内文书提到它 | ⭐ **候选清理**：**移进** `tools/oneoff/_归档-YYYYMMDD/`（可逆、⛔ 不删）；或写明留档理由 |

**两条纪律**：
1. ⛔ **不盲删** —— 先跑**只读**量测件 `tools/oneoff/_oneoff_measure.py`（报：件数 / 容量 / 被引用 / **零引用清单**）；
2. 删移先查现行用途和引用，按用户已授权范围执行；未授权或仍有现行用途才需确认。

**机器眼**：`T20`（保留期与容量 · `tools/audit/audit_work.py`）—— 件数 / 容量超线 ⇒ **黄一行**；
阈值登记 = `docs/reference/thresholds.md`（**改数先改表**）；自证 = `tools/mut/_mut_t20.py`。
