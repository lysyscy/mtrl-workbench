## 关键纪律（详文回计划）

- **旁路与手改保护**：手改/调整单/手动行**永不被抓取或导入覆盖**（计划 §6.3）。
- **金额**：`core.money` 唯一出口；快照保留原始精度（§6.1）。
- **幂等**：同源重跑 = 更新不重复；减行不留残影（§6.4）。
- **统一导入**：`backend/app/import_kit/`（读表/解析/校验/暂存通用层；域判定留各域 —— `TAIL-69`）。

## 跨域必须统一的口径清单（原 §8.4 的「一致性清单」· 2026-09-22 `D22` 裁定落点）

> ⭐ **为什么不做成界面卡片**（`D22` · `TAIL-71` 销号理由）：四项口径**都已有机器守卫**，
> 卡片是静态文本 ⇒ **写死即旧**（`T13` 刚立的教训）⇒ 清单放**工程侧本页**（随变更同批改），
> 界面不再新增只读展示卡。要改口径 ⇒ 改下表「守护」那一列的实现，⛔ 不是改这张表。

| 项 | 口径（一句话） | 唯一守护（改它才是改口径） |
|---|---|---|
| **金额** | 金额唯一出口 = `core.money`；**禁 float 直传**（先转字符串再归一）；快照留原始精度 | `backend/app/core/money.py` · `import_kit/parse.py` · 判据 `ACC-PAY-AMT-001` |
| **时间** | 业务时钟（`bjMonth` / 服务端 today）**唯一**；报表按核算年月；抓取只允许单月 | 计划 `§9.2` · 壳 `bjMonth` · 判据 `ACC-*` 中「核算年月」各点 |
| **手改保护** | 手改列 / 手动行 / 调整单 / 手动导入行 **永不被覆盖或清理** | 各域 `repository`（如 `merge_month` 只写非手改列）· 判据 `ACC-PLAN-MANUAL-001` · `ACC-INV-ADJ-*` |
| **删除策略** | 配置类 = **硬删不留痕**；业务类 = 留痕/软删（可在回收站恢复） | `mod14_config` · `mod15_user`（软删）· 判据 `ACC-CFG-RULE-001` · `ACC-X-DEL-001` |
| **幂等** | 同源重跑 = 更新不重复；换月/减行**不留残影**；失败整批回滚不留半成品 | 各域 `merge_month` / `upsert_details` / `preview_store` 批次 · 各导入判据 |
| **包间调用** | 业务包之间**只许经对方的 `service`**（包间出口），⛔ 不得 `import` 对方 `repository`（翻账本）；⭐ 全仓现存 **1 处「按设计的例外」**（`mod14_config → mod11_jc.repository`，理由写在那个文件头） | `backend/tests/test_layering.py` **规则 C（一般式）**（待清名单**已清空** · 出口须经打桩判据）· 反向灵敏度 `tools/mut/_mut_layering.py` · 口径 = 计划 `§2.3` |
