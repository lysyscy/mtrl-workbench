# 前端设计守则 · **以使用用户为中心**（`v3` · **Agent 可执行版**）

> **读者**：任何要画页面 / 加元素 / 写界面文案 / 做交互的 Agent（含我）与接手的人。
> **一句话**：**你是替"使用用户"把关的人，不是替开发自己方便的人。**
> **何时读**：动前端**之前**（改文案 / 加控件 / 改版式都算）；**审计前端时逐条打勾**。
> **状态**：⛔ 本件 = **前端口径的唯一主人**（别处只许引用）。条文**由用户口述演化而来**
> （`[用户·2026-09-26/27]`），用户 2026-09-27 明确授权：**「你可以尽可能优化原文，让他更便于你使用」**
> ⇒ 本版把原话**重写成可执行口径**（原话要点存于**附录 A**，⛔ 附录不作口径）。

## §0 怎么用（Agent 执行协议 · 术语 · 编号）

**三步（照顺序做，别跳）**：

1. **动手前**：逐条回答 §1 的**四个问句**（答"不 / 会"⇒ 删掉或藏起来再动手）；
2. **落笔时**：按 §2 → §3 → §4 → §5 对表逐条过；⭐ **用本仓真例自查**（每条都给了"反例"列，
   泛例（如 `Error: 500`）只当类比，**你手上这页**的真例才是判定依据）；
3. **交付前**：过 §6 自检清单**逐条打勾**，⭐ **能机器判的必须挂判据**（本仓铁律：能机器判的别靠自觉）。

**术语**（本文只用这几个词，别自造近义说法）：

| 词 | 含义 |
|---|---|
| **使用用户** | 真正用这个界面干活的业务人员（不是开发 / 运维 / 产品 / 我） |
| **反例** | 违反本条时界面**长什么样**（照它认自己有没有犯） |
| **判据** | 谁在守这条：测试名 / 真机段 / `人眼 · 未挂`（⚠️ 写"人眼"就是**还没兜住**，别当成已守） |
| **例外** | 允许不遵守的**窄条件**（写了就必须同时写"为什么"；没写 ⇒ 不许例外） |
| **触点** | 这条规则在系统里**具体落在哪**（界面哪儿 / 后端哪层） |

**编号规则**：`§<节>.<条>`。⛔ **节号不许重排**（壳与判据里引用着 `守则 §3` / `§4` / `§5.9`
—— 重排 = 让所有引用**悬空**）；新增条目**接着排**并标 `[补·日期]`。
⭐ **一条只在一处定义**：§5 是"执行层"，只写**执行形态 ＋ 触点**，定义一律指回 §1–§4（⛔ 不抄第二遍）。

**强制力**：`【必需】`（违反 = 缺陷/事故）· `【应当】`（默认这么做，例外要写理由）· `【参考】`（看场合）。

## §1 动手前的四个问句（每次改 UI 先过一遍）

> 只有「**用户需要** ＋ **不误导**」同时成立，才保留。四个问句**逐条写出答案**，⛔ 不许心里过一遍就算。

| 编号 | 问句（要写成一句话答案） | 答"不 / 毫无影响 / 会"怎么办 | 判据 |
|---|---|---|---|
| §1.1 | 这个元素是**使用用户**需要感知的吗？（不是给开发/运维/我方便） | 不是 ⇒ **删掉或藏起来**（走 §3） | `人眼 · 未挂` |
| §1.2 | 它帮用户解决什么问题？**对应到哪个动作或判断**？ | 对应不上 ⇒ 删（装饰不算理由） | `人眼 · 未挂` |
| §1.3 | 删掉它，用户会**做错事 / 卡住**，还是**毫无影响**？ | 毫无影响 ⇒ 删 | `人眼 · 未挂` |
| §1.4 | 用户看它时**会不会误以为**它是别的意思 / 状态 / 功能？ | 会 ⇒ 走 §4（防误导**高于**"信息多给一点"） | 见 §4 各条 |

⚠️ **本仓真例（§1.1/§1.2 的现成违反）**：把回执的**原始键名**（`updated` / `undo_rows` / `project key`）
当指标标签铺一排 —— 那是**给程序和排查看的**，不是给使用用户的（已按 §5.9 改成"人话指标 ＋ 技术明细折叠"）。

## §2 用户「该看到」的（呈现）

> 只呈现**对当前任务有决策价值**的信息。判定基准：**没有它，用户会不会做错 / 卡住**。

| 编号 | 规则 | 反例（本仓真例优先） | 例外 | 判据 |
|---|---|---|---|---|
| §2.1 | 【必需】**当前状态真实可见**：加载中 / 空 / 错 / 部分成功**四态各有一句话**，不许一片空白。 | 面板搜不到时留空（用户以为面板坏了）；列表空着不说明下一步 | 无 | `test_imp_shell`（③ 空态人话）· 真机 ⑳′ |
| §2.2 | 【必需】**结果可解释**：操作后明确说"成功了 / 失败了 / 正在处理"，并给**下一步**。 | 干跑（`dry_run`）却写"导入完成"（§4.2 同罪） | 无 | `test_imp_shell`（回执卡）· `test_imp_m05_api`（预览零写库） |
| §2.3 | 【必需】**关键数字带单位与口径**（币种 / 单位 / "截至某时刻"），裸数字不上屏。 | `1289`（是什么？什么时候的？） | 表格**单元格内**已是明确列名时，可省单位（列名承担口径） | `人眼 · 未挂` |
| §2.4 | 【必需】**要求与后果提前说**：必填 / 格式 / 不可恢复的后果，写在控件旁边，不等踩坑。 | 「截止核算月」不写 `YYYY-MM`（用户填 `八月` ⇒ 分段悄悄错） | 无 | `test_imp_shell`（格式要求贴控件 ＋ 占位给示例） |
| §2.5 | 【必需】**用业务术语**，不用内部代号。 | 界面出现 `cutoff_ym` / `project key` / `warehouse` | 后台/管理员页且用户是技术人员 | `test_imp_shell`（结果卡只画域自报的 `kpis`） |
| §2.6 | 【应当】**能算出来的别让人自己数**（总数 / 剩几条 / 差几行）。 | 让用户自己数"表里到底几行没进去" | 无（这条没有代价） | `test_imp_shell`（"共 N 行 / 显示 M 行"） |
| §2.7 | 【必需】**结论贴在它说的那个对象上** —— 要标就标在**那一行/那一格**上；⛔ 别让人抬头读一句说明再自己对上号。`[补·2026-09-26]` | 卡片底下写"有 7 行不会写入"，表里那 7 行**跟别的行长得一样**（用户拿红框自己对） | 结论**没有**具体对象时（如整批的总评），放卡片顶部 | `test_imp_shell::test_不会落库的行要在行上直接标` · `tests/imp_contract.py`（4 域）· 真机 ③″ |

## §3 用户「不该看到」的（过滤）

> 默认**不进界面**；只有"用户角色确实是技术人员（如管理员后台）"才放宽。

| 编号 | 规则 | 反例 | 例外 | 判据 |
|---|---|---|---|---|
| §3.1 | 【必需】技术实现细节不上屏：接口名 / 字段名 / SQL / 数据库 ID / 状态码（200/500）/ 内部枚举。 | 列表显示 `task_id: 88213`；回执铺一排 `undo_rows` | 管理员排障区（§5.9 的"技术明细"折叠） | `test_imp_shell`（原始键进折叠区）· ⛔ **通用文案扫查未挂**（`TAIL-105` 余项） |
| §3.2 | 【必需】报错堆栈 / 调试日志一律拦在界面之外，转成人话。 | 弹窗 `Error: 500, timeout at /api/export` | 无 | `人眼 · 未挂`（后端 `MustReportError` 是另一半） |
| §3.3 | 【必需】内部术语与黑话不入界面（调度 / worker / 缓存命中 / 幂等…）。 | 提示写"批号撞唯一约束"（本仓真例：`IntegrityError … 重复键` ⇒ 已改成"同一秒连点两次"的人话处理） | 用户是技术人员 | `人眼 · 未挂` |
| §3.4 | 【应当】与当前任务无关的冗余信息不塞同一屏（塞满 = 找不到重点 ⇒ 走 §5.9 折叠）。 | 把 6 段规则说明全铺在页头 | 无 | `人眼 · 未挂` |
| §3.5 | 【必需】别人的数据 / 系统内部数据严守可见性边界。 | 列表带出别的项目/别的用户的数 | 无（权限问题，不是审美问题） | 各域权限判据（`test_acc_*` 口径） |
| §3.6 | 【必需】开发态 / 测试态标识要**明显但克制**，且**生产环境必须没有**。 | 开发库里 `__自检仓_*` 混进项目候选（本仓真例） | 联调环境（须标注） | 真机 ㉒（开发库卫生：自检残留报红） |
| §3.7 | 【必需】**报错处理硬规则**：任何异常先翻译成用户能懂的话 ＋ **给下一步动作**；⛔ 绝不把原始报错甩上屏。 | 直接把 `IntegrityError: duplicate key value violates unique constraint` 给用户看 | 无 | 后端 `MustReportError`（各域判据）· 壳侧 `人眼 · 未挂` |

## §4 防误导（**最高优先级**：宁可少给，不能给错）

| 编号 | 规则 | 反例 | 例外 | 判据 |
|---|---|---|---|---|
| §4.1 | 【必需】文案与行为一致：写"保存"就只保存、写"提交"不做别的。 | 按钮叫「导出」实际改了数据 | 无 | `人眼 · 未挂` |
| §4.2 | 【必需】**状态必须真实**：没成功不说成功；部分失败不只显示"完成"；加载未完成不给最终数。 | 干跑写"导入完成"；给"不落库的行"标成会落库的样子 | 无 | `test_imp_m05_api`（预览零写库）· `test_imp_m06_api`（`cutoff_ym` 只取能落库的行）· `test_imp_m04_api`（无此类行 ⇒ 不许给 `skipped`） |
| §4.3 | 【必需】默认值**最安全 / 最中性**：不预勾付费项、不预开危险开关。 | 默认勾选"开通会员"；导入页**默认预选第一个项目**（本仓真例：会让数据静默写进错项目 ⇒ 已改成不预选 ＋ 置灰说明） | 无 | `test_imp_shell`（不预选 ＋ ④ 置灰） |
| §4.4 | 【必需】相似元素不制造歧义：长得像但功能不同的入口，要在文案或位置上拉开。 | 「导出」与「下载模板」并排同款 | 无 | `人眼 · 未挂` |
| §4.5 | 【必需】**颜色只承担语义**：红=危险/错、绿=成功/安全、黄=警告；⛔ 同一状态**不许两套视觉语言**。 | 绿底表示"被跳过"；换一类浮层/行就重造一套配色 | 无 | 壳 CSS token 审查（`ui_parity` ＋ 无硬编码色值）· `.skiprow` 与 `.ntvoid` **同源**（inset 竖条＋浅底） |
| §4.6 | 【必需】权限与可见性一致：看不到的功能**不留"点了报错"的入口**；置灰/隐藏要说明原因。 | 灰按钮不给理由；提示条盖住可点区（本仓真例：`.toast` 吃掉浮层点击） | 无 | `test_imp_shell`（④ 置灰 ＋ 缺什么说清）· 真机 ㉑（点命中） |
| §4.7 | 【必需】**数字口径透明**：同页不混用不同口径而不说明；⭐ **同一个数在两处不许换说法**。 | 两个"合计"口径不同却并排；预览叫「配上」、回执叫「更新条数」（本仓真例 ⇒ 已统一为「配上并更新」） | 无 | `test_imp_m11_api`（词与预览逐字一致） |

## §5 执行层（逐条可检查；⭐ 定义见左栏，本节只写**执行形态 ＋ 触点**）

| 编号 | 规则（一句话） | 定义 | 执行形态 · 触点 | 判据 |
|---|---|---|---|---|
| §5.1 | 【必需】新增元素必须答得出"用户为什么需要它"，答不上就删。 | §1.2 | 动手前**写出答案**（写不出 ⇒ 别加） | `人眼 · 未挂` |
| §5.2 | 【必需】面向用户的文字**用非技术语言重写一遍**再看懂不懂。 | §2.5 §3.1 | 写完**读一遍**：出现内部词 ⇒ 改 | `人眼 · 未挂`（`TAIL-105` 余项） |
| §5.3 | 【必需】报错路径必须有"人话 ＋ 下一步"，禁原始异常上屏。 | §3.7 | 后端 `MustReportError`；壳侧 `lgNotice` | 各域判据 |
| §5.4 | 【必需】四态（加载/空/错/成功·部分成功）各有独立且明确的表达。 | §2.1 | 每个列表/卡片都过四态 | `人眼 · 未挂` |
| §5.5 | 【必需】"看着能点"的点了必须有**符合预期**的结果或明确反馈；**不能点的置灰/隐藏 ＋ 说明为什么**。 | §4.6 | 按钮态：`disabled` ＋ 旁边一句"缺什么"；动作里**挡重入** | `test_imp_shell`（④ 置灰 ＋ `busy` 挡重入）· 真机 ①″/③″ |
| §5.6 | 【必需】默认值中性/安全，不替用户做有风险或付费的决策。 | §4.3 | 检查每个默认值 | 各域判据 |
| §5.7 | 【必需】数字带单位/口径/时间；裸数字不上屏。 | §2.3 | 逐个数字过 | `人眼 · 未挂` |
| §5.8 | 【必需】内部 ID / 状态码 / 技术字段不外泄给普通用户。 | §3.1 | 折叠进「技术明细」而不是删掉（排障要留） | `test_imp_shell`（人话 KPI ／ 原始键折叠） |
| §5.9 | 【必需】同屏做**优先级排序**：核心操作与核心数据一眼可见，次要信息**可折叠**。 | §3.4 | 用 `<details>` / 折叠块；⛔ 别把技术项与业务指标混成一排 | `test_imp_shell::test_落库结果卡给的是人话_原始键名进技术明细` |
| §5.10 | 【必需】交付前逐条过 §6，任何"会误导用户"的一条都必须改掉。 | §6 | 交付前跑 §6 ＋ 判据 | 人眼（§6）＋ 各条判据 |

## §6 交付前自检（逐条打勾；⭐ "怎么查"能机器判就用机器）

| # | 问自己 | 怎么查 |
|---|---|---|
| 1 | 界面上还有只有开发才懂的词 / 字段 / 数字吗？ | §3.1 §5.8；**搜**：`Error:` / 状态码 / 字段名（⛔ 全站扫查未挂，`TAIL-105`） |
| 2 | 报错时用户看得懂、知道怎么做吗？ | §3.7 §5.3；把异常**念一遍**能不能懂 |
| 3 | 加载 / 空 / 错 三态都有明确呈现吗？ | §2.1 §5.4；**每屏都点一遍** |
| 4 | 有没有"假装成功"（异步没回 / 干跑也说完成）？ | §4.2；看回执文案与真实写入数是否一致 |
| 5 | 默认勾选 / 默认开关替用户做了风险决策吗？ | §4.3 §5.6 |
| 6 | 两个相似按钮 / 入口会被认错吗？ | §4.4 |
| 7 | 颜色用错语义了吗（红绿黄乱用 / 同一状态两套语言）？ | §4.5 |
| 8 | 数字带单位、口径、时间了吗？ | §2.3 §5.7 |
| 9 | 无权限/不可用的功能是隐藏或置灰并说明了，还是留了个点了报错的入口？ | §4.6 §5.5 |
| 10 | 第一次用的用户，**不看文档**能完成主任务吗？ | §2 全节；真机走一遍主流程 |
| 11 | ⭐ 凡是"说出了一个数 / 一个结论"的地方，**它的对象上有对应标记**吗？ | §2.7；**卡片说的数 == 行上标出的数**（真机 ③″ 就是这么量的） |

## §7 正反案例对照

| 场景 | 反面（误导 / 冗余） | 正确 | 归属 |
|---|---|---|---|
| 导出失败 | 弹窗 `Error: 500, timeout at /api/export` | "导出失败，可能是网络中断，请重试；仍失败可联系管理员" | §3.7 §5.3 |

| 状态展示 | 后台还在跑就显示"已完成" | "处理中…"，真完成才变"已完成" | §4.2 |
| 数字展示 | `1289` | "本月用量 1,289 度（截至 09-26 09:00）" | §2.3 §5.7 |
