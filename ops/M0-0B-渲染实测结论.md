## 二、结论（5 条，均有实测证据）

| # | 结论 | 证据 |
|---|---|---|
| **1** | ✅ **「会话 0（非交互）内本地渲染 PDF」可行** —— 全片最大不确定性**排除**，切片 1 可按 Plan A 推进（不启用 WeasyPrint / 桌面代理退路） | 场景 C |
| **2** | ⚠️ **服务 / SYSTEM 身份下必须显式设 `PLAYWRIGHT_BROWSERS_PATH`** —— 否则它会去 `C:\Windows\System32\config\systemprofile\AppData\Local\ms-playwright` 找浏览器，**那里没有** | 场景 D 的报错原文 |
| **3** | ⚠️ **服务启动参数 / 脚本参数里不要放中文路径** —— 含中文参数时 python 虽已启动，但 **argparse 报错、退出码 2**；而 `-Execute`（程序路径）与 `-WorkingDirectory` 含中文**没有问题** | A/B 的 `LastTaskResult=2` + C/D 的正常启动 |
| **4** | ⚠️ **`p.chromium.executable_path` 不可作为"浏览器是否可用"的判据** —— 只装 headless shell 时，它返回一个**并不存在**的 `chromium-1234\chrome-win64\chrome.exe`；实际使用的是 `chromium_headless_shell-1234\chrome-headless-shell.exe` | C 的 `（存在？ False）` |
| **5** | ℹ️ **`headless=True` 在本机可用**（本机只有 headless shell，无完整 chromium ⇒ `headless=False` 必然失败，与 §2.4 一致）；**冷启动 ~7.5s、热启动 ~0.15s、单件渲染 ~0.5–1.6s** ⇒ 批量打印建议**复用同一浏览器实例**，不要每单起一次 | 基准场景 7.46s vs C 场景 0.15s |

**收尾策略已验证**：全程**不调 `browser.close()` / `playwright.stop()`**（§2.4 记其会挂死），改用 `os._exit(0)` 快退 —— 四个场景**均未出现挂起**。

## 三、给 M7（上线服务化）的行动项

1. **NSSM 服务必须注入环境变量** `PLAYWRIGHT_BROWSERS_PATH=<中性路径>`（如 `C:\ProgramData\ms-playwright` 或 `D:\ms-playwright`）。
   ⚠️ **不要把服务指向某个用户的 `AppData`** —— 换账户/清理 profile 就会失效。
2. **服务与脚本的命令行参数避免中文路径**；推荐路径通过 **`.env` / 环境变量**传入（`.env` 是 UTF-8 读取，无此问题）。
3. **M7 上线后必须用真实 NSSM 服务复做一次本实测**（本次是"近似会话 0"，不是真服务）。
4. ✅ **出纸（IPP 直投）已于 2026-09-16 真机验证通过**（一次连投 4 张：付款通知书 ×2 ＋ 其他支出 ×2）——
   ⚠️ 首次投递 4 张**全回 `0x0400 client-error-bad-request`**，真因 = **`document-format` 的「值标签」用错**：
   `mimeMediaType` 必须用 **`0x49`**，而实现写的是 `0x44`（那是 `keyword`）⇒ 报文非法；**把标签改对即可**（详见 `ops/i8-接口契约-旁证摘要.md` §四 补记）。
