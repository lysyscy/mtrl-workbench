# 票仓：本地 markdown

> **读者**：要开工 / 收尾一张票的 agent｜**回答**：票住哪、一张票长什么样、状态怎么记、收尾怎么过闸
> **何时读**：开始一项改动、决定用哪些 skills 或核验范围、领票与收尾时。
> 票是"**尾巴**"的载体；活跃票索引主人 = `.codebuddy/plans/开发计划-主文档.md` **§15**，已销号短索引主人 = `.codebuddy/plans/票索引-已销号.md` §一。本页 §四是日常开发流程的主人（用户 2026-10-07 本会话「按推荐」）。

## 一、票住哪

- **一张票一个文件**：`.codebuddy/work/50-tickets/TAIL-<编号>-<短名>.md` ⛔ **绝不是一个合并的大文件**。
- **索引** = 主计划 **§15**（一行一票：编号 / 一句话 / 阶段 / 状态 / 指针）。⭐ 索引**只放一行**，历史与本事的细节**一律写在票文件里**。
- ⚠️ 编号**沿用 `TAIL-` 且顺延、不重用**（销号不释放编号）—— 这是本仓"销号不跳号"的口径，机器守着呢。

## 二、一张票长什么样（**照第二个项目的票面** —— 2026-10-04 用户指出后对齐）

```markdown
# TAIL-<编号>: <一句话标题>

**What to build:** <从用户视角说清"要做成什么" —— ⛔ 不写逐层实现清单>

**Blocked by:** None (can start immediately) ／ 或挡住它的那些票号

**Status:** ready-for-agent

- [ ] 验收项 1（怎么算做完 · 要能证伪）
- [ ] 验收项 2

---

## Comments

**<日期> · 建票（agent）。** 来源 / 不做会怎样 / 落点 / 阶段-时机 / 排期四问
**<日期> · 落账（agent）。** 办完了什么 ＋ **逐条证据**（跑了哪条命令、出什么数）
**<日期> · 两轴 `/code-review`（基点 `<sha>`）。** Standards 轴 / Spec 轴
**<日期> · 提交与推送。** `<sha>` ＋ 实际推送结果（执行口径见 §四）
```

- ⭐ **三个字段用英文**（`What to build` / `Blocked by` / `Status`）—— 它们是 `/to-tickets` 的字段名，机器与人都认这三个词（`T6` 就按它们核）。
- ⭐ **验收 = `- [ ]` 复选框列表，就是票面主体**（不是附在末尾的一栏）。
- ⭐ **过程一律进 `## Comments`**（只追加）：开工声明 / 落账 / 评审 / 逐条证据 / 提交。⛔ 票面正文别写过程叙事。
- ⚠️ **票不带"读者 / 何时读"那类文档文头** —— 票是**工单**，不是文档（本仓 `T15` 只对 `10-designs`／`30-troubleshooting`／`40-decisions` **三区**查文档文头，区名唯一出处 = `tools/audit/audit_work.py` 的 `HEADER_ZONES`；⛔ 票仓不在里面）。

⭐ **为什么这样分**：一张尾巴以前**挤在索引表的一格里**，那一格普遍 1000–2400 字 ⇒ 谁读都得在一行里穿过上万字。**"一句话"留索引、"要做成什么 ＋ 验收"留票面、"过程"留 Comments**，字墙就长不出来了。

## 三、状态（`状态` 行）

| 状态 | 什么意思 |
|---|---|
| `ready-for-agent` | **待做**、已说清、agent 可以直接领（＝原来那个"待做"） |
| `claimed` | **在办**：领了就把这行先改成它（⛔ 别同时两个人领） |
| `ready-for-human` | **要人做**（我做不到的：真机 / 拍板 / 现场） |
| `needs-info` | 卡在**缺信息**（等你说一句 / 等真数据） |
| `needs-triage` | **还没定要不要做**（推测性候选放这儿） |
| `wontfix` | **决定不做** —— ⚠️ 必须写一句"为什么不做"（⛔ 不许静默删） |
| `done` | **已销号**：票文件顶部标它 ＋ 活跃索引行由 `_tail_close.py` 移除；已销号短索引由人追加到姊妹件 |

五个角色的字符串见 `triage-labels.md`。

## 四、开工 / 收尾

**开工（领一张票）**：按 **Blocked by** 判断 —— 挡住它的票**全都 `done`** 才能领（这叫"**前沿**"）；领了先写 `状态: claimed`。
**收尾（销号）**：① 在票Comments追加"**办完了什么 ＋ 证据**"；② 人在 `.codebuddy/plans/票索引-已销号.md` 表尾追加一行；③ ⭐ `_tail_close.py` 从主计划 §15 移除活动行、重算计数、将 §14.3 活动排期原行迁入同份计划的「已办排期（历史）」区，并把票标 `done`。先干跑看清，再真跑；脚本负责的改动不要手改。
> ⚠️ **已销号索引落点**：`.codebuddy/plans/票索引-已销号.md`；四列的逐行原文与末尾追加写法以该件为准。主计划 §15 只保留活跃票和指针。

### 执行步骤与结束条件

1. **确定目标与授权**：由用户请求和当前票验收确定看得见的结果；已有授权继续有效。结束条件是目标、相关状态、实质未定取舍及权限边界已明确；用户提出的某种改法只是手段，仍按目标验收。
2. **调查新增影响**：金额或日期出口变化时，先用业务样例核对字段设计目的、实际事实与统计调整的区别，再定实现；按AGENTS触发读主人章节，保存开工差异，找到运行/机器输入的实际使用者。结束条件是受影响项、可复用证据和待查输入均有依据；待查项继续调查，不默认为全量或免验。
3. **修改与核验**：按下节分支执行，对变化或无证的相关输入补验。共享出口先验证已查明的页面、导出等实际使用者；涉及壳行为时，相关失败先修复并局部复验，再完成本轮最终完整壳自检。结束条件是当前票全部验收项成立、相关失败已修复并复验、未变有效结果可追认；隔离自证失败不能算通过。收益取舍用于选择实现手段，仍按用户要求完成票面目标；用户只授权一轮review时，在全部验收成立后审查最终差异。
4. **交付与接续**：有票就在该票Comments写结果、实际检查与未验边界，按票协议销号；无票的小改在交付结果说明即可。只有需要跨会话接续且无合适票时追加当日日志。结束条件是下一步可定位、风险仍真实、必要状态已同步；无需把同一结果再写一份长日报。提交与推送按下节执行。

### 提交与推送

`[用户·2026-10-12]` 运行 agent 自行决定是否及何时提交、推送本仓改动，无需另征用户同意；当前任务明确要求不提交或不推送时遵守该要求。

决定提交前完成本节要求的相关核验，明确列举本次范围内的文件暂存，保留无关已有修改，遵守 MEMORY.md 的凭据与 Git 操作纪律，运行真实提交钩子。推送后读取远端分支 SHA 与本地提交核对；交付时报告提交 SHA、推送结果，或本轮未提交／推送的理由。

### 取舍：什么才值得建一道闸（2026-10-09 用户定 · **够用即止**）

威胁模型 = **一人开发 · 局域网 2 人 · 不会有第二个人改数据或改代码**。
所以防误改 / 防误用 / 防外部攻击的闸门**不建**；真有这类担心，用一行注释写清为什么不建。

建任何检查、守卫、扫描之前，先过两问：
**① 它在本项目会不会真的发生？② 真发生了，是不是真难受（比维护它的成本大？）**
两问都否 ⇒ 不做，理由记进票或一行注释即可。

两条手法：
- 能靠"改对"解决的，不要靠"加闸"兜着 —— 兜着只是让缺陷看不见，缺陷还在。
- 建闸时顺手写一句"**什么情况下可以删掉它**" ⇒ 防再次出现"永远脏、永远要记得绕过"的东西。

不为不存在的风险写代码，也**不承诺**不存在的守卫：钩子或文档里写过"以后会做 X"的，X 不发生就**删掉那句承诺**，不补。

### 日常开发流程（唯一口径）

工具自测登记在 tools/oneoff/_run_rulers.py 的SELFTESTS，工具及相关依赖变化时选中；普通修改与显式完整检查都不固定附带三个自测，未变化的有效逐项结果可复用。固定登记检查仍归CMDS；依赖触发回 tools/oneoff/_impactscope.py，相关关键业务回归与真机验证保持。

`[用户·2026-10-08]` 来源：本轮已确认的阅读与核验减负整改。用户最新要求优先；提交与推送回本节「提交与推送」。

**开始**：读AGENTS.md、README.md §〇、主计划§13.6最新行及§15相关票；然后只读当前动作的主人章节。业务规则未决先查事实并请用户选择；已确认规格不重新访谈。历史仅在复发排障、约束含义不明或明确追溯时读取，并说明触发原因。

**按实际影响核验**：说明/索引、agent操作规则、业务规格、机器消费输入分开判断；扩展名、新删件、提交动作和既有dirty均不直接触发全量。查清运行代码、测试与检查的使用者；金额、权限、批量写入、迁移及共享机制验证真实触达后果，需要时扩大。未知输入先调查并列出不确定点，不能静默跳过或直接等同全量。选择器变更只验证相关分支、正常放行和漏验反例，不附带全部业务与元测试。壳测试的读取面迁移随相关测试修改顺带做，保留断言与未知依赖兜底；目前未证明整体提速，不专门批量迁移或扩大解析规则。

**输入与证据**：开工快照界定本轮新增差异，不能证明既有输入已验。已通过且代码/输入/环境未变的逐项结果可复用；无证或变化的相关使用者重验。失败不能留绿，只重跑失败或修补触达项。局部pytest结果隔离，只有完整运行刷新权威四态。自动入口遇待查影响返回非零并说明，不以完整测试掩盖依赖调查。

**自证**：不要求每次代码修改都新增判据或变异；金额、覆盖、批量写入等高后果缺陷保留能复现错误的回归用例。新改判据、核验机制或怀疑断言失效时，只运行相关隔离自证。调用真实实现处理隔离输入；正式代码与 `delivery/` 产品资料不作临时变异靶。新/改判据同批给对应反向灵敏度。**改机制或改名同批回扫本轮碰过的注释与行内文档**（点名的标识符必须存在、写的列号或偏移必须与代码一致）；共用隔离靶串行；隔离失败不能冒充通过，不靠重跑无关业务补救。

**动作与记录**：明确目标可直接实现；需要独立交付或跨会话才拆票。当前票留目标、验收、结果和未验风险；稳定要求回主人。小改不要求长日报、全文备份或销号流水。review按当前用户授权和成本判断是否使用双轴code-review；已明确范围的文档小改可对新增差异定点自查，验收与相关检查仍须有证据。改后端运行Python重启服务；改壳验证相关回归、真机自检，成功后盖壳章。无关治理提示不阻挡当前业务交付，相关失败不得报通过。

**成本控制**：按指针定点取章节、限制命令输出；长任务用较长等待，只报告有变化的状态。先跑便宜的相关回归，再执行较长检查；修补后复验实际触达项，复用输入未变的逐项有效结果。证据只留命令、退出码、关键数与边界，优先修正业务和实现，不为假设性分支新增检测；**回写类改动**（README、计划、票索引、票 Comments）**一次写完再跑终轮**（边跑边改数字＝同一轮多跑一遍）。

**执行与汇报**：命令回 .codebuddy/memory/IDE-细节.md §十一。默认及提交前均按影响入口；显式完整检查仅在已查明广泛影响、刷新完整权威结果或用户要求时使用。汇报实际依据、主要读取章节及理由、运行/跳过检查、各长检查和总耗时、未验风险；不另造永久阅读日志和状态源。

## 五、别开票的情况（免得长出第二份清单）

- 属**计划内的活**（"某个切片还没做完"）⇒ 由四态报表看管，⛔ 不进票仓。
- 属**当场就能办完**的一行订正 ⇒ 在现有票或交付结果说明改动与依据即可；仅有跨会话接续需求且无合适票时，追加当日日志，不另开票。
- ⭐ **`wontfix` 也要留一张票**（写清为什么不做）—— 否则下一个人会把同一件事再想一遍。
