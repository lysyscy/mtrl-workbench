# 票仓：本地 markdown

> **读者**：要开工 / 收尾一张票的 agent｜**回答**：票住哪、一张票长什么样、状态怎么记、收尾怎么过闸
> **何时读**：开始一项改动、决定用哪些 skills 或核验范围、领票与收尾时。
> 票是"**尾巴**"的载体；尾巴的编号、台账与销号纪律主人 = `.codebuddy/plans/开发计划-主文档.md` **§15**。本页 §四是日常开发流程的主人（用户 2026-10-07 本会话「按推荐」）。

## 一、票住哪

- **一张票一个文件**：`.codebuddy/work/50-tickets/TAIL-<编号>-<短名>.md` ⛔ **绝不是一个合并的大文件**。
- **索引** = 主计划 **§15**（一行一票：编号 / 一句话 / 阶段 / 状态 / 指针）。⭐ 索引**只放一行**，历史与本事的细节**一律写在票文件里**。
- ⚠️ 编号**沿用 `TAIL-` 且顺延、不重用**（销号不释放编号）—— 这是本仓"销号不跳号"的口径，机器守着呢。

## 二、一张票长什么样（**照第二个项目的票面** —— 2026-10-04 用户指出后对齐）

```markdown
# TAIL-<编号>: <一句话标题>

**What to build:** <从用户视角说清"要做成什么" —— ⛔ 不写逐层实现清单>

**Blocked by:** None (can start immediately) ／ 或挡住它的那些票号

**Status:** ready-for-agent

- [ ] 验收项 1（怎么算做完 · 要能证伪）
- [ ] 验收项 2

---

## Comments

**<日期> · 建票（agent）。** 来源 / 不做会怎样 / 落点 / 阶段-时机 / 排期四问
**<日期> · 落账（agent）。** 办完了什么 ＋ **逐条证据**（跑了哪条命令、出什么数）
**<日期> · 两轴 `/code-review`（基点 `<sha>`）。** Standards 轴 / Spec 轴
**<日期> · 提交。** `<sha>`（⛔ 提交要用户点头）
```

- ⭐ **三个字段用英文**（`What to build` / `Blocked by` / `Status`）—— 它们是 `/to-tickets` 的字段名，机器与人都认这三个词（`T6` 就按它们核）。
- ⭐ **验收 = `- [ ]` 复选框列表，就是票面主体**（不是附在末尾的一栏）。
- ⭐ **过程一律进 `## Comments`**（只追加）：开工声明 / 落账 / 评审 / 逐条证据 / 提交。⛔ 票面正文别写过程叙事。
- ⚠️ **票不带"读者 / 何时读"那类文档文头** —— 票是**工单**，不是文档（本仓 `T15` 只管四区文档，⛔ 不管票仓）。

⭐ **为什么这样分**：一张尾巴以前**挤在索引表的一格里**，那一格普遍 1000–2400 字 ⇒ 谁读都得在一行里穿过上万字。**"一句话"留索引、"要做成什么 ＋ 验收"留票面、"过程"留 Comments**，字墙就长不出来了。

## 三、状态（`状态` 行）

| 状态 | 什么意思 |
|---|---|
| `ready-for-agent` | **待做**、已说清、agent 可以直接领（＝原来那个"待做"） |
| `claimed` | **在办**：领了就把这行先改成它（⛔ 别同时两个人领） |
| `ready-for-human` | **要人做**（我做不到的：真机 / 拍板 / 现场） |
| `needs-info` | 卡在**缺信息**（等你说一句 / 等真数据） |
| `needs-triage` | **还没定要不要做**（推测性候选放这儿） |
| `wontfix` | **决定不做** —— ⚠️ 必须写一句"为什么不做"（⛔ 不许静默删） |
| `done` | **已销号**：票文件顶部标它 ＋ 索引行移进 §15 的"已销号"段 |

五个角色的字符串见 `triage-labels.md`。

## 四、开工 / 收尾

**开工（领一张票）**：按 **Blocked by** 判断 —— 挡住它的票**全都 `done`** 才能领（这叫"**前沿**"）；领了先写 `状态: claimed`。
**收尾（销号）**：① 票文件正文追加"**办完了什么 ＋ 证据**"＋ 顶部标 `done`；② 主计划 §15 索引那行移进"已销号"段 —— ⭐ **三处同改**走 `tools/oneoff/_tail_close.py`（⛔ 别手改台账）；③ 过闸门（见下）。
> ⚠️ **「已销号」那张表在哪儿（2026-10-07 补 · 本仓为它花掉 4 次检索）**：
> 它是**主计划 §15 里的小节「四、已销号」**（表头 = `| # | 事项 | 销号依据 | 日期 |`）——
> ⛔ **不是主计划 §4**（§4 = 「开发流程」，与销号无关）——⛔ 也不是根 `README.md` §四。
> 销号那一行**由人写**（`_tail_close.py` 只代改三处，⛔ 不代笔判断），
> 写法与字数上限见主计划 §15 §四 开头那三行规矩。

### 日常开发流程（唯一口径）

`[用户·2026-10-07]` 来源：本会话对日常流程三项取舍答「按推荐」；原话留在 .codebuddy/memory/journal/2026-10-07.md。

| 情况 | 怎么开始 | 留什么记录 |
|---|---|---|
| 目标与完成标准明确，一次会话能完成 | 读有关口径 → 实现 → 核验 → 两轴 `code-review` | 使用已有票记目标、完成标准与结果；没有适用票时按本页建票，§五的例外照常适用 |
| 业务规则或预期效果有未决问题 | `grill-with-docs` 问清取舍后实现；已有故障先复现、诊断 | 长期口径变化更新主人文件，过程进当前票 |
| 需要跨会话、分开完成且有依赖 | `grill-with-docs` → `to-spec` → `to-tickets` → 逐票实现 | 先查已有方案和票，保留明确的完成标准与依赖边 |

**过程把控**：agent 自行查事实、选择实现细节、完成相关核验与 review，再交结果。业务选择、重要取舍或范围扩大时回来确认；提交仍须用户点头。当前改动中发现的问题同批修、同批核验，留在当前票；无关建议只记候选，待决定后开工。

**核验按后果分**：金额计算、批量数据写入或删除、权限、数据库结构、多个页面共用的功能，以及检查流程本身，属于关键改动，跑完整核验；只改相关页面的文案或局部展示，通常属于普通改动，跑相关检查。agent 要查明实际触达面，报告跑了什么、跳过什么及依据；无法确定影响范围时使用完整核验。提交前另见 AGENTS.md「提交前（唯一入口）」；日常核验不替代提交前要求。

**记录按用途分**：当前票承载目标、完成标准与结果；长期口径更新它的主人文件。跨会话且需独立完成的工作才拆票。同批 review/retro 修补继续记当前票，避免反复开票。skills 按上表触发，不要求每次改动都走全链。

**执行入口与当前能力**：命令只在 .codebuddy/memory/IDE-细节.md §十一维护。普通入口按实际差异判断：信息记录与已证明的单页静态文字采用相关检查；表达式、标签/属性、多个页面、业务/权限/金额/批量写入、检查机制、新删件或未知影响使用完整路径。无关格式、预算、票计数与工具治理不阻挡普通交付；相关工具失效则该风险未验，不能报通过。新登记检查缺少守护后果分类、漏掉必要检查或选择越界均不能静默跳过。

已有dirty只能从同环境完整核验通过的内容基点排除；没有这种证明时与HEAD比较，关键/未知差异完整重验。单页文字的pytest选集来自完整运行的真实壳读入（含共享模块、子进程和远程请求）；测试名字空间、读取证据或摘要不可信时pytest全跑。通过回执丢失、坏档、失败或环境变化不能沿用基点；执行开始即清除磁盘旧绿，全部成功才重新保存。局部pytest使用隔离结果档；失败清空可复用证明。关键改动使用完整入口（pytest全套与KEY变异串行）；提交前仍按AGENTS入口，不以日常相关核验替代。普通入口打印实际运行/跳过理由与总墙钟，约一分钟目标未达必须如实保留，不自动销号。

**附加核验**：动过判据，同批给 tools/mut/ 下的反向灵敏度；改过后端 Python，重启服务核对运行效果；改过壳，真机自检后盖壳基线章。这些动作只在对应改动发生时执行。

## 五、别开票的情况（免得长出第二份清单）

- 属**计划内的活**（"某个切片还没做完"）⇒ 由四态报表看管，⛔ 不进票仓。
- 属**当场就能办完**的一行订正 ⇒ 办完在日志留痕即可，⛔ 不必开票。
- ⭐ **`wontfix` 也要留一张票**（写清为什么不做）—— 否则下一个人会把同一件事再想一遍。
