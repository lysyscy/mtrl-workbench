> **读者**：要开工 / 收尾一张票的 agent｜**回答**：票住哪、一张票长什么样、状态怎么记、收尾怎么过闸
> **何时读**：开始一项改动、决定用哪些 skills 或核验范围、领票与收尾时。
> 票是"**尾巴**"的载体；活跃票索引主人 = `.codebuddy/plans/开发计划-主文档.md` **§15**，已销号短索引主人 = `.codebuddy/plans/票索引-已销号.md` §一。本页 §四维护个人工作流的本仓绑定与授权；通用方法通过AGENTS.md指向个人技能（用户2026-10-13要求接入并适配）。

## 一、票住哪

- **一张票一个文件**：`.codebuddy/work/50-tickets/TAIL-<编号>-<短名>.md` ⛔ **绝不是一个合并的大文件**。
- **索引** = 主计划 **§15**（一行一票：编号 / 一句话 / 阶段 / 状态 / 指针）。⭐ 索引**只放一行**，历史与本事的细节**一律写在票文件里**。
- ⚠️ 编号**沿用 `TAIL-` 且顺延、不重用**（销号不释放编号）—— 这是本仓"销号不跳号"的口径，机器守着呢。

## 二、一张票长什么样（**照第二个项目的票面** —— 2026-10-04 用户指出后对齐）

```markdown
# TAIL-<编号>: <一句话标题>

**What to build:** <从用户视角说清"要做成什么" —— ⛔ 不写逐层实现清单>

**Blocked by:** None (can start immediately) ／ 或挡住它的那些票号

**Status:** ready-for-agent

- [ ] 验收项 1（怎么算做完 · 要能证伪）
- [ ] 验收项 2

---

## Comments

**<日期> · 建票（agent）。** 来源 / 不做会怎样 / 落点 / 阶段-时机 / 排期四问
**<日期> · 落账（agent）。** 办完了什么 ＋ **逐条证据**（跑了哪条命令、出什么数）
**<日期> · 评审（实际执行时填写）。** 范围、基点与结论
**<日期> · 提交与推送。** `<sha>` ＋ 实际推送结果（执行口径见 §四）
```

- ⭐ **三个字段用英文**（`What to build` / `Blocked by` / `Status`）—— 它们是 `/to-tickets` 的字段名，机器与人都认这三个词（`T6` 就按它们核）。
- ⭐ **验收 = `- [ ]` 复选框列表，就是票面主体**（不是附在末尾的一栏）。
- ⭐ **过程一律进 `## Comments`**（只追加）：开工声明 / 落账 / 评审 / 逐条证据 / 提交。⛔ 票面正文别写过程叙事。
- ⚠️ **票不带"读者 / 何时读"那类文档文头** —— 票是**工单**，不是文档（本仓 `T15` 只对 `10-designs`／`30-troubleshooting`／`40-decisions` **三区**查文档文头，区名唯一出处 = `tools/audit/audit_work.py` 的 `HEADER_ZONES`；⛔ 票仓不在里面）。

⭐ **为什么这样分**：一张尾巴以前**挤在索引表的一格里**，那一格普遍 1000–2400 字 ⇒ 谁读都得在一行里穿过上万字。**"一句话"留索引、"要做成什么 ＋ 验收"留票面、"过程"留 Comments**，字墙就长不出来了。

## 三、状态（`状态` 行）

| 状态 | 什么意思 |
|---|---|
| `ready-for-agent` | **待做**、已说清、agent 可以直接领（＝原来那个"待做"） |
| `claimed` | **在办**：领了就把这行先改成它（⛔ 别同时两个人领） |
| `ready-for-human` | **要人做**（我做不到的：真机 / 拍板 / 现场） |
| `needs-info` | 卡在**缺信息**（等你说一句 / 等真数据） |
| `needs-triage` | **还没定要不要做**（推测性候选放这儿） |
| `wontfix` | **决定不做** —— ⚠️ 必须写一句"为什么不做"（⛔ 不许静默删） |
| `done` | **已销号**：票文件顶部标它 ＋ 活跃索引行由 `_tail_close.py` 移除；已销号短索引由人追加到姊妹件 |

五个角色的字符串见 `triage-labels.md`。

## 四、开工 / 收尾

**开工（领一张票）**：按 **Blocked by** 判断 —— 挡住它的票**全都 `done`** 才能领（这叫"**前沿**"）；领了先把票面 `Status` 改为 `claimed`。
**收尾（销号）**：① 在票Comments追加"**办完了什么 ＋ 证据**"；② 人在 `.codebuddy/plans/票索引-已销号.md` 表尾追加一行；③ ⭐ `_tail_close.py` 从主计划 §15 移除活动行、重算计数、将 §14.3 活动排期原行迁入同份计划的「已办排期（历史）」区，并把票标 `done`。先干跑看清，再真跑；脚本负责的改动不要手改。
> ⚠️ **已销号索引落点**：`.codebuddy/plans/票索引-已销号.md`；四列的逐行原文与末尾追加写法以该件为准。主计划 §15 只保留活跃票和指针。

### 按影响核验：项目能力与边界

- 范围按运行代码、测试及机器输入的实际使用者选择；说明和索引通常核引用、语义、字节与结构。新删件、提交及已有dirty不自动扩大范围；显式完整检查使用 `--full`。
- 金额、身份权限、写入、回滚、迁移、共享出口及已修复缺陷保留相关覆盖。局部pytest写独立结果，完整pytest才刷新权威四态；隔离自证失败不能算通过，未知影响由入口报非零并说明。
- 回执复用读取实际签名：当前pytest回执按整组选集及广泛输入集合判断，票或规则文档变化也可能失效；没有跨票逐用例自动证明账。已有逐项证据是否仍有效按个人验证方法核实，不能因旧整体通过或基点存在而免验。
- 真实服务39段与壳快照仅在现场问题、部署验收或用户明确需要时执行；未验仍记未验。归档工具的现有限制回 tools/README.md“按需自证与归档”，本次接入不改变该工具及检查机制。
- 失败归因与处理读个人“验证与失败处理”；本仓原票Comments承载判断依据和后续入口，自动入口非零结果按实际记录。

## 五、别开票的情况（免得长出第二份清单）

- 属**计划内的活**（"某个切片还没做完"）⇒ 由四态报表看管，⛔ 不进票仓。
- 属**当场就能办完**的一行订正 ⇒ 在现有票或交付结果说明改动与依据即可；仅有跨会话接续需求且无合适票时，追加当日日志，不另开票。
- ⭐ **`wontfix` 也要留一张票**（写清为什么不做）—— 否则下一个人会把同一件事再想一遍。
