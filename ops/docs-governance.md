**本件是总图，不是新口径。** 它只回答「**哪条口径住在哪 · 谁改它 · 变了要同批改哪几处**」；条文一律不在这里重写一遍 —— 重写一份就有第二套口径，而"改一处漏一处"是本仓最贵的病。凡本件写「见某处」，那个「某处」就是主人。

### ⭐ 归档 / 降档前必答的三问（**2026-10-05 新立 · 当天差点出事**）

1. **它的结论落到哪里去了？** —— 说出**文件名**（哪条口径 / 哪个常量 / 哪条判据）。“应该落了吧”不算答案。
2. **还有谁引用它？** —— 三路都要报：**机器引用**（**六路活机器**；⛔ 清单的**唯一真源** = `tools/audit/audit_common.py` 的 `LIVE_MACHINE_GLOBS` ＝ 后端业务代码 · 后端测试 · 尺子／反向灵敏度／真机探针 · **运维脚本** · **规则档** · **前端壳的脚本与页面**）＋ **活文档口径引用** ＋ **未销号的票**。⛔ 只查机器引用就下结论 = 当天翻车的原因；⛔ **别在别处另抄一份清单**（抄了必漂）。⭐ 不想靠回忆就敲 `tools/audit/refs_query.py <件名>`（只读）：三路计数 ＋ 逐路分布 ＋ 它自报「不动的 N 件 ＋ 各自引用数」。
3. **仓外归档索引登记了吗？** —— 没有索引 ⇒ 仓内指针当场变幽灵（`T3` 判红）。

⚠️ **今天的教训（值一票）**：那份《文档重构方案》**机器引用 0**，却被四张票当唯一依据 ⇒ **「零机器引用」只能算一个信号，不能当结论**。凡"删/搬一份设计件"，必须**自报「不搬的那 N 件 ＋ 各自引用数」**，别靠回忆（当天第一版量测就漏了 `ops/*.ps1` 与 `rules/*.mdc` 两路）。

## 五 · 引用写法（**今天新立 · 治幽灵指针**）

1. **跨文档引用写全路径** —— `README.md` §四 格式 ②；反引号里的仓内路径会被 `T3` 校验（写错就红）。⚠️ 交付面文档**不得出现** `.codebuddy/…` 路径。
2. ⛔ **不得只写「方案 §六-1 丙案」这类不带路径的节号引用** —— `T3` 读不懂散文 ⇒ **人删了文件它不会红**（今天已发生五处：`ops/阈值表.md` 第 32 行 · `TAIL-225/226/227/228` 票面）。正路：写全路径，或改成指回本件的节号。
3. **引用一份会被归档的件** ⇒ 指针必须能落到「仓外归档 ＋ 仓内索引」两跳。
4. **改一件就同批复核指向它的指针** —— 本件 §二 每行已写明"它变了要同批改哪几处"；那是本仓最贵的一课（"一个数两处用"同批改两处）。

## 七 · Agent 每轮工作流（**动文档时照这条走**）

1. **接手**：根 `AGENTS.md`（入口表）→ 计划 `§0.2` → `§13.6` 最新行 → **本件（仅当要动文档）**。
2. **动手前**：先搜有没有既有文档能承载（`README.md` §七 决策树 ①）⇒ **能 ⇒ 别新建**。
3. **动手**：按 §二 找到主人文件 ⇒ 只改主人，别处改指针。归档/删除类另过 **§三 三问**。
4. **收工**：`tools\oneoff\_run_rulers.py --all` ＋ 全套 pytest ＋ `doc_audit.py --ui` ⇒ **整行读汇总行**（`rc=0` ≠ 全绿）。
5. **报告里写一句**：本次动了哪些文档、**指针是否同批**、删/搬类动作自报「**不搬的 N 件 ＋ 各自引用数**」。
6. **记忆**：结论回 `MEMORY.md`（若属长期纪律）＋ 当天 `journal/`；⛔ 别在 `memory/` 根另开一份。
