## 二、专项实现约束

这些已完成事项的约束仍有效；仅搬迁正文，业务取值与完成状态不由本节重新定义。

### 剔除规则的持久化

#### 设计（5 条 · 长期有效）

1. **规则来源 = 「库 → 出厂默认」**：库里有 ⇒ **以库为准**；**库空 ⇒ 回落 `DEFAULT_RULES`（＝ §4.2.2 那张表）**
   ⇒ 首装行为即符合 §4.2.2，不必人工录一遍（与 `core/app_settings` 的「库 → `.env`」同款思想）。
   ⛔ **备选（库空 = 不剔任何东西）不采用** —— 那会让首装行为**悄悄偏离口径**。
2. **一条规则 = 一行**：`kind` ＋ `values`（`｜` 分隔的**原文**）＋ `meaning`（业务含义，**纯展示、不参与判定**）＋ `ord`
   —— 与 §4.2.2 表形态、原型行形态同构；**同一 `kind` 允许多行**，判定按 `kind` **合并命中值**。
   ⚠️ 写入一律规整成**全角 `｜`**；**解析时半角 `|` 也认**（手输常见）—— 认不出分隔符会让整条规则**静默不命中**。
3. **判定出口一个字不改**：仍是 `classify.match_exclude_rule`（规则由 loader 注入，默认真实实现读库）；
   ⛔ **不得在编排层另写一份剔除判定**（本仓老纪律：同一件事不许实现两遍）。
4. **改规则 ≠ 重算历史**：已产生的剔除标记（`exclude_source=rule`）**不受影响、也不重算**
   ⇒ 写侧**不触发任何重算**；页面与回执**必须讲清这一句**。
5. **模块归属**：**表与仓储放付款域**（`mod03_notice`）—— §4.2.2 原文即「剔除规则本身属付款域」，
   而抓取管线（付款域）要用它、配置**页**在 `MOD-14` ⇒ 依赖**单向** `mod14_config → mod03_notice`，**不成环**。
   ⚠️ **这条实施时改判过**：原设计写「放 `mod14_config`」，但那样 `mod03` 要读它、`mod14` 又要读 `mod03` 的规则值对象
   ⇒ **循环 import**。落地形态 = `backend/app/mod03_notice/rules_repository.py` ＋ `backend/app/mod14_config/rules_api.py`。

#### 落点（全部已落地）

| # | 落点 | 做什么 |
|---|---|---|
| 1 | Alembic 迁移 | 新建 `exclude_rule` 表（NOT NULL 列带 `server_default`；外键命名） |
| 2 | `backend/app/mod03_notice/rules_repository.py` | 读（`all_rows` / `effective_rules` / `effective_payload`）＋ 写（`add_row` / `update_row` / `delete_row`，**硬删不留痕**）＋ `ensure_seeded`（**幂等初始化**）＋ 复用 `classify.validate_rules` |

### 全名回查与人工指认

#### 四个概念（别混）

- **陌生仓库** = 材料报表里出现、而项目档案里查不到对应档案行的仓库名。
- **占位行** = 建档时没能拿到真实仓库名、先占位的行（`未建仓-N`）。
- **全名** = 项目全名（**不在材料报表里** ⇒ 必须经「仓库名 → 所属项目全名」这一跳换出来）。
- **「全名回查」** = 用换出来的全名去**本地项目档案**里查有没有对得上的行。

#### 查询范围与匹配规则（**已确认：就这样定**）

- **只查本地档案表**（⛔ 不查 i8、⛔ 不做模糊匹配、⛔ 不加兜底猜测）；**含归档行**、**不筛状态**。
- 比较一律走**归一化全名的唯一出口** `norm_full_name`（剥尾码 ＋ 压缩空白），**精确相等**。
- 命中里**先判壳**：命中里有壳 ⇒ 这条仓库是**具体小微**（走「新建具体小微」，不进 `≥2` 分支）。
- 判定口径的**唯一出口** = `recovery.classify_hits`（⛔ 不靠中文 `reason` 串认类别 —— 文案一改就会静默失效）。

#### 四种处置

| 命中情况 | 处置 |
|---|---|
| 无命中 | **没建档** ⇒ 走链路 A（安全绳：**不许臆造**） |
| 命中里有壳 | **新建具体小微**（系统自己做，不打扰人） |
| **≥2 条非壳行** | ⭐ **报出来、要人指认挂哪一行**（本节的入口服务的就是它） |
| 1 条占位行 | **系统扶正**（占位名 → 真实仓库名） |
| 1 条已有真实仓库名 | 与本次不符 ⇒ 列出来要人核对（普通项目 ↔ 仓库 = **1 : 1**） |

#### 入口与三裁定（用户 2026-09-18 逐条确认）

1. **范围** = **只查本地档案表**（含归档行）· 归一化全名**精确相等** · 命中里**先判壳** · 不查 i8、不模糊。
2. **入口落 `m01` 档案页**（材料侧抓取回执补一句「待人工 N 条，去 `m01` 处理」）。
3. **本轮只做「指定到哪一行」** —— 该行的**类型纠正另立** `TAIL-42`（已销号，历史见主计划§15）（⛔ 不在这一步偷偷改类型）。

### 模板填充与导出

#### 权威依据（读哪；⛔ 别自创口径）

- **形态主人** = `demo/模板/模板清单.md`（模板本体**当交付物随系统走**）；**行为口径** =《说明书》§7.1。
- **模板资产闸门**：一律走 `report_export/resources.require_template()`（带 SHA256 登记 ＋ 资产断言）。

#### 引擎契约（`backend/app/report_export/tpl_fill.py`）—— **三条硬性，⛔ 不许简化**

1. **按「标记文字 `DATA_START`」定位数据区起点** —— ⛔ **不抄坐标**（实测：只改列位置就会错）。
2. **尾部行块随行数派生**：样板数据区删到只剩**首行**（当行样式母版）→ 按 `n` 行写入 → 下方 `insert_rows(m)`
   → 按 offset **整块下移**合计 / 小计 / 脚注 / 合并块 → **改写公式区间**（过程资料是**两段** `=SUM`，两段都要重写）。
   ⚠️ 模板里的公式**不参与求值** ⇒ 口径数字由系统算好、**以数值覆盖**（实测：产物里残留公式 **0**）。
3. ⭐⭐ **「新数据区之外不留残留」守卫**（与 `TAIL-43` 同族）：模板带着示例数据，只写前 n 行、不清尾部
   ⇒ 用户会读到**示例 / 上月**的数（`TAIL-43` 就是这一族的**显示区**形态）。守卫 = 产物里**数据区之外不得有非空单元格**。

#### 出口与壳侧（每片一套）

- 后端：`report_export/service.py::export_*` ＋ `GET /api/<模块>/<报表>/export?period=…`；
  **成功给 xlsx ＋ `X-Export-Filename`**（⛔ **前端不拼文件名**，按 `content-type` 分流）。
- 壳侧：按钮**真下载**（原「诚实占位」已换掉）；⛔ 判定（对平 / 提取口径 / 手填校验 / 选题校验）**一律留后端**。
- 几个约定（都是踩出来的）：
  · **空串 `""` = 显式留空**（模板那格是公式而口径要求"不可得的总额留空 ⇒ 留空 ≠ 0"）；
  · 「没传」与「传了空」必须用 **`is None`** 区分；
  · `insert_rows` / `delete_rows` **不搬合并区**；`delete_rows` 会留下空 `<row>`（`UsedRange` 虚增）；
  · `verify_filled` **必须读两遍**（`data_only=True` 看不见公式）。
